# OTサイバーセキュリティとISA/IEC 62443：製造業向け実践ガイド

> **要点:** OTセキュリティ（Operational Technology Security、制御系セキュリティ）は、PLC、SCADA、HMI、ロボット、ドライブ、安全系システムなど、物理的な生産を担うシステムを保護し、工場が安全に稼働し、可用性を保ち、良品を生産し続けられるようにするものです。その国際的な基準はISA/IEC 62443シリーズです。このシリーズは、資産所有者、インテグレーター、製品サプライヤーに役割を割り当て、資産をゾーンにまとめ、ゾーン同士をコンduitで接続し、ゾーンごとに目標セキュリティレベル（SL 1〜4）を定め、7つの基本要件に照らして各ゾーンを確認します [1][2]。米国では通常、NIST Cybersecurity Framework 2.0およびNIST SP 800-82と組み合わせて使用します [9][11]。

> **重要なポイント**
> - OTでは、可用性と安全性が最優先です。本来防ぐはずの攻撃よりも、ラインを止めてしまうファイアウォールのルールやパッチの方が大きな損害をもたらすことがあります。
> - ISA/IEC 62443は単一の文書ではなく、一連の規格群です。工場で主に使われるのは、パート2-1（セキュリティプログラム）、3-2（リスクアセスメントとゾーン）、3-3（システム要件）、4-1と4-2（サプライヤー要件）です [1]。
> - 中核となる手法は、言葉にすれば単純です。資産を洗い出し、ゾーンにまとめ、ゾーン間のコンduitを定義し、ゾーンごとに目標セキュリティレベルを設定し、目標と達成レベルのギャップを埋めます [2]。
> - 文書化された事例の多くで、生産停止は制御機器ではなく事務系ITから始まりました。Colonial Pipeline、Norsk Hydro、Cloroxは、いずれもITenvironmentへの攻撃の後に操業の停止や減速を余儀なくされました [17][20][35]。
> - 中規模工場における最初の1年の実践的な取り組みは、資産インベントリ、ゾーンとコンduitのモデル化、セグメント化された産業用DMZ、制御されたリモートアクセス、オフラインバックアップ、そしてリハーサル済みのOTインシデント対応手順です。検知とサプライヤー要件は2年目に続けます。
> - NIST SP 800-82 Rev. 3（2023年）は現行の米国OTセキュリティガイドです。NISTは2026年9月21日にRev. 4の初期公開ドラフトを公表しました。CSF 2.0を基に再構成されており、意見募集は2026年11月30日まで行われています [9][10]。
> - 製品向けの認証（ISASecure CSA、SSA、SDLA）があり、2025年6月からは運用サイト向けの認証（ISASecure ACSSA、62443-2-1、2-4、3-2、3-3に基づく）も存在します [7][8]。
> - このプログラムの予算は、一度きりのプロジェクトではなく保守費用と同様に扱い、明確なKPIを伴う安定した年次予算項目として計上してください。

## OTサイバーセキュリティとは何か

オペレーショナルテクノロジー（OT）とは、物理的なプロセスを監視・制御するハードウェアとソフトウェアのことです。NISTはOTを「物理環境と相互作用するプログラム可能なシステムとデバイスの広範な集合」と定義し、産業用制御システム、ビルディングオートメーション、交通システム、物理的アクセス制御、環境監視をその例として挙げています[9]。工場においては、これはプレスラインのプログラマブルロジックコントローラ（PLC）、塗装工場の分散制御システム（DCS）、公益事業向けの監視制御・データ収集（SCADA）サーバー、各ステーションのヒューマンマシンインターフェース（HMI）、ロボットコントローラ、ドライブ、画像処理システム、そのすべてをプログラミングするエンジニアリングワークステーション、そしてプロセスを安全な状態へ移行させる安全計装システム（SIS）を指します。

OTサイバーセキュリティとは、これらのシステムが妨害されたり、改ざんされたり、社内の他の領域への侵入経路として悪用されたりすることを防ぐための方針、技術的対策、日常的な運用手順の総体です。その目的は従来のITセキュリティとは異なります。オフィスでは通常「データは機密が守られているか」が最初の問いになります。製造現場では、最初の問いは「誰かが怪我をしないか」そして「ラインは止まらず、良品を生産し続けられるか」です。

### OT、ICS、IACS、SCADA：用語の整理

この分野ではいくつかの重なり合う用語が使われています。規格がこれらを厳密に使い分けているため、違いを押さえておくことが重要です。

| 用語 | 意味 | 登場する場面 |
|---|---|---|
| OT（オペレーショナルテクノロジー） | 物理世界と相互作用するシステムを総称する用語 | NIST SP 800-82 Rev. 3 はそのタイトルに使用[9] |
| ICS（産業用制御システム） | 産業における制御システム：PLC、DCS、SCADAおよびそのネットワーク | 旧版のNIST・CISA文書、MITRE ATT&CK for ICS[15] |
| IACS（産業オートメーション・制御システム） | ISA/IEC 62443が用いる用語で、産業プロセスの運用に関わる人、ハードウェア、ソフトウェア、方針を指す | 62443の全パート[1][2] |
| SCADA | 分散した拠点（パイプライン、公益事業、水道）の監視制御 | 公益事業、工場全体のエネルギーシステム |
| DCS | 分散制御システム。連続プロセス工場で一般的 | 化学、食品、医薬、塗装工場 |
| PLC | プログラマブルロジックコントローラ。個別組立製造の主力 | 機械、コンベア、組立ライン |
| SIS | 安全計装システム。安全計装機能を実行する | プロセス安全、プレス機、バーナー |
| IIoT | 産業用IoT。エッジまたはクラウドのプラットフォームへデータを送るセンサーやデバイス | 予知保全、エネルギー監視。IEC PAS 62443-1-6[5] |

実務では「OTセキュリティ」「OTサイバーセキュリティ」「ICSセキュリティ」「産業サイバーセキュリティ」が同義語として使われています。本ガイドでは、分野全体を指す場合は「OTセキュリティ」、62443が要求する対象を指す場合は「IACS」を用います。

### そもそも製造業が対象となる理由

多くの工場長は、サイバー攻撃はIT部門の問題であり、自社の機械は「エアギャップ（物理的に分離）」されていると考えています。しかし大半の工場では、もう何年も前からそうではありません。MES、ヒストリアン、ERPインターフェース、機械メーカーによるリモートサポート、クラウドダッシュボード、IIoTセンサーが、工場の現場と企業システム、そしてインターネットを結んでいるのです。CISAは重要製造業（一次金属、機械、電気機器、輸送機器）を米国の重要インフラ分野の一つに挙げ、その分野のリスク管理機関として国土安全保障省を指定しています[32]。一般に16の分野の一つとして数えられています[unverified: 引用されたCISAのページには分野数が記載されていない]。

稼働を止めた工場のコストは、工場を運営したことのある人なら容易に理解できるはずです。停止1時間ごとに、限界利益の損失、遅れを取り戻すための残業、中断されたバッチによるスクラップ、緊急対応の費用、そして最悪の場合は顧客へのペナルティが発生します。第3章の事例は、攻撃者がこの事情を理解していることを示しています。ランサムウェア集団は、PLCを理解しなくても生産を止められます。工場が稼働に欠かせないシステムを暗号化すれば十分なのです。

工場のデータ面についてさらに詳しくは、[MESとISA-95](https://www.m365.fm/en/learn/mes-isa-95/)および[製造業向けAzure](https://www.m365.fm/en/learn/manufacturing-it-azure/)のガイドをご覧ください。これらは工場データが企業システムやクラウドへどのように届くかを解説しています。そうした接続のいずれもが、62443の意味での「コンduit（通信経路）」にあたります。

## ITセキュリティとOTセキュリティの違い:オフィスの手順が工場現場で通用しない理由

ITとOTのセキュリティでは、ファイアウォール、アカウント、ログ取得、バックアップといった多くの同じツールを使います。しかし、対象とするシステム、優先順位、そして障害がもたらす影響は大きく異なるため、オフィスの手順をそのまま工場現場に持ち込むと稼働停止を招きます。ISAGCAのクイックスタートガイドは、工場における優先事項を一つの概念にまとめています。それが**必須機能**で、"Equipment Under Control の健全性、安全、環境、可用性を維持するために"維持しなければならないものです。ガイドには、安全計装機能、制御機能、そして機器を監視・操作するオペレーターの能力が挙げられており、これらを失うことは、保護の喪失、制御の喪失、または監視の喪失を意味します[2]。

| 観点 | 一般的なオフィスIT | 一般的な工場OT |
|---|---|---|
| 最優先事項 | データの機密性と完全性 | 安全性、可用性、プロセスの完全性。機密性も重要だが、通常は後順位になる |
| 障害の影響 | データ損失、罰金、評判の失墜 | 負傷、環境への放出、設備の損傷、スクラップ、生産量の損失 |
| システムの寿命 | ノートPCやサーバーで3～5年 | 実務上、コントローラーや機械では15～25年が一般的です[実務上の目安、業界統計としては未検証] |
| 変更の時間帯 | 毎晩または毎週 | 計画停止、年に1～2回のこともある |
| パッチ適用 | 自動化、毎月 | ベンダーの承認と検証を経てから。一部の機器はパッチを適用できない |
| 再起動 | 許容される | 再起動によりラインが停止したり、バッチが台無しになったりすることがある |
| プロトコル | 認証・暗号化あり(HTTPS、Kerberos) | 多くのレガシー産業用プロトコルは、認証や暗号化を前提に設計されていない |
| ウイルス対策とエージェント | すべてのエンドポイントに標準導入 | HMIやコントローラーのベンダーが対応していないことが多い。許可リスト方式の方が安全 |
| 性能 | 数秒の遅延は不便 | ミリ秒単位の遅延でもプロセスが停止することがある |
| 責任の所在 | IT部門 | 保全、制御技術者、製造部門、多くの場合は装置メーカー |
| 変更を行う人 | 管理者 | 技術者、インテグレーター、ベンダー、場合によってはオペレーター |

### 実務上の意味

この表から、次の三つのルールが導かれます。

1. **テストなしでのコントローラーへのアクティブスキャンは行わない。** ファイルサーバーでは無害な脆弱性スキャナーでも、古いPLCやHMIをクラッシュさせることがあります。OTの資産検出は、受動的(ネットワークトラフィックの傍受)に始めるか、ベンダーのエンジニアリングツールを使います。
2. **セキュリティ変更には生産部門の承認が必要。** 必須機能のあるゾーンでのファイアウォールルール、アカウント変更、パッチはすべて、レシピや安全インターロックの変更と同様に変更管理(MOC)に従います。
3. **代替管理策が通常のケースである。** Windows 7のHMIを次回のライン再構築まで交換できない場合は、小さなゾーンに隔離し、コンduitを制限し、USBアクセスを除去し、通信を監視して保護します。このような状況で代替管理策を受け入れることこそ、62443の手法が意図するところです。

### ITとOTが連携すべき場面

逆の誤りは、OTセキュリティは工場の問題であり、ITは関与すべきでないと宣言することです。次のセクションのインシデントが示すように、攻撃者は多くの場合、ITが運用するIDシステム、電子メール、ヘルプデスクを経由して侵入します。効果的なプログラムでは、サイトレベルのリスク責任者を一人置き、ITセキュリティと制御技術者による合同チームを編成し、各ゾーンの責任を明確に割り当てます。役割分担の一例は、セクション18の役割表に示しています。

### 事例の背景にあるパターン

5つの事例を並べて読むと、本ガイド全体の方向性を決める4つのパターンが見えてきます。

- **IT からの侵入、OT への影響。** 引用した情報源のいずれも、5件のうちどれについてもコントローラへの直接攻撃は記述していません。操業が止まったのは、共有ネットワーク、共有の ID、あるいはそれらに依存する業務システムが機能しなくなったためです。だからこそ、工場とエンタープライズの間のゾーン境界（産業用 DMZ）と ID の衛生管理が、ロードマップの最上位に置かれています。
- **オペレーターによる自主的な停止。** Clorox は侵入を検知すると、システムをオフラインにして製造を停止し、その後は受注を手作業で処理しました [20]。Colonial のパイプラインはランサムウェア攻撃の後に停止されました [35]。どの業務システムに依存しているかを把握し、縮退運転ができる工場は、より多くの選択肢を持ちます。
- **復旧には数週間を要する。** 十分な準備をしていた企業であっても、通常の生産量を回復するまでに数週間を要しました。バックアップ、再構築されたエンジニアリング用ワークステーション、検証済みのコントローラのロジックによって、その空白期間の長さが決まります。
- **サードパーティも攻撃対象領域の一部である。** ソフトウェア更新（NotPetya）、外部委託のヘルプデスク（Clorox）、インテグレータ（第12節の CISA/FBI ファクトシートを参照）はいずれも記録に現れています [14][18][20]。

### 制御機器を狙った攻撃

産業プロセスそのものを操作する攻撃は比較的まれですが、実在します。62443がセキュリティレベル3と4を設けている理由もここにあります。MITREは産業用制御システムに対する攻撃者の振る舞いを集めた公開ナレッジベース、ATT&CK for ICSを維持しています。そのマトリクス（コンテンツバージョン20.1）は、技術を12のタクティクスに分類しており、Initial Accessから、Inhibit Response FunctionとImpair Process Controlを経て、Impactに至ります[15]。このうち2つはOT特有のタクティクスです。**Inhibit Response Function**（安全機能および保護機能が反応しないようにすること）と**Impair Process Control**（プロセスの制御を操作すること）です[15]。

防御側にとって、ATT&CK for ICSは次の3つの点で有用です。

1. 検知のためのチェックリストとして：監視で何を捉えられるか。
2. ITセキュリティアナリストと制御エンジニアの間で共有できる語彙として。
3. 62443-3-2のリスクアセスメント（第8章）における脅威シナリオへの入力として。

本ガイドは防御の側にとどまります。いかなる技術の実行方法も説明しません。

### 各要素の組み合わせ方

米国の製造業者にとって実用的な組み合わせは、次のようになります。

- **governance と取締役会向けの CSF 2.0。** 経営陣、監査人、保険会社、顧客が共通の言葉で議論できるようになります。新設された Govern 機能は、役割、リスク選好、サプライヤーリスクを対象としています [11]。
- **プラント設計とサプライチェーン向けの 62443。** 表の中で、アセット所有者、インテグレーター、製品サプライヤーに具体的な責任を割り当て、ゾーン、コンジット、セキュリティレベルを定義している唯一のフレームワークです [1][2]。
- **橋渡し役としての SP 800-82。** OT 固有の事項を NIST の管理策の枠組みに翻訳します。Rev. 4 草案は CSF 2.0 を軸に再構成されており、資産管理、ネットワーク監視、システム管理機能に対するゼロトラストの原則に関するガイダンスが追加されています [10]。
- **健全性チェックとしての CPG。** 短く、測定可能な項目で構成されています。62443 の本格的なプログラムに着手する前に、簡易的な基準値を把握するのに役立ちます [13]。
- **CMMC、SEC、CIRCIA、NIS2、CRA** は、自社に適用される場合にのみ検討します（第 19 節）。

NIST Manufacturing Extension Partnership（MEP）は、中小規模の製造業者を対象に、CSF に基づく自己評価、ギャップ分析、インシデント対応計画の策定を支援しています [30]。従業員数 500 人未満の多くのプラントにとって、これは最も手頃な着手方法です。

## ISA/IEC 62443 の解説：構成、役割、ステータス

### 標準の成り立ち

International Society of Automation（ISA）は 2002 年に ISA99 委員会を設立し、自動化および制御システム向けのサイバーセキュリティ規格の策定を始めました。2010 年ごろ、同委員会は International Electrotechnical Commission（IEC）と密接に協力するようになり、文書は ISA/IEC 62443 として番号が付け直されました [3]。ISA の文書は ANSI/ISA-62443-x-y として発行され、IEC は同じ内容を IEC 62443-x-y として発行しています。ISA によれば、このシリーズは国際連合から承認を受けており、IEC は 2021 年にこれを水平規格（特定の業界ではなく、複数の分野にまたがって適用される規格）に指定しました [1]。

米国の読者にとって実務上重要なのは、ANSI/ISA 版は ISA から、IEC 版は IEC ウェブストアから購入でき、技術的には整合しているという点です。ただし、発行日や版番号は両機関の間で異なる場合があるため、契約書では必ず正確な版を明記してください。

### 4 つの文書グループ

シリーズは次の 4 つのグループで構成されています [1][2]。

1. **一般（1-x）：** 用語、概念、モデル、指標。
2. **ポリシーと手順（2-x）：** 組織としてアセット所有者およびサービスプロバイダーが行うべきこと。
3. **システム（3-x）：** リスクアセスメント、ゾーンとコンジット、自動化ソリューション全体に対する技術要件。
4. **コンポーネント（4-x）：** 個々の製品に対するセキュア開発プロセスと技術要件。

A note of caution on secondary sources: in 2026 some websites announced a new "IEC 62443-4-2:2026" with mandatory AI anomaly detection. We found no such publication in the ISA catalog or the IEC webstore as of November 2026 [1][4]. Check every edition claim against the publisher.

### The roles: who has to do what

62443 assigns responsibilities to roles, not to departments. The ISAGCA quick start guide defines them as follows [2]:

| Role | Definition (ISAGCA) | Typical company | Main 62443 parts |
|---|---|---|---|
| Asset owner | "The organization that is accountable and responsible for the IACS" | The manufacturer that runs the plant | 2-1, 2-2, 2-3, 3-2 |
| Integration service provider | "The organization that provides integration activities for an Automation Solution" | System integrator, machine builder delivering a line, in-house engineering | 2-4, 3-2, 3-3 |
| Maintenance service provider | Provides support activities for an Automation Solution under the asset owner's policies | Service contractor, OEM service, in-house maintenance | 2-4 |
| Product supplier | "The organization that manufactures and supports a hardware and/or software product" | PLC, HMI, network, drive and software vendors | 4-1, 4-2 |

One company can hold several roles. A machine builder is a product supplier for its control cabinet software and an integration service provider when it installs the line. A large manufacturer with its own controls engineering department is asset owner and integrator at the same time. The value of the role model is that the contract and the audit can say exactly which requirements each party owns.

### 2つのライフサイクル

62443は、サプライヤーの**製品開発ライフサイクル**と、工場における**自動化ソリューションのライフサイクル**を区別しており、後者には統合フェーズと運用・保守フェーズがあります [2]。安全に設計されたPLC（4-2）があっても、それだけでラインが安全になるわけではありません。インテグレーターはそれを正しく設定する必要があり（3-3）、設備所有者は20年間それを安全に運用しなければなりません（2-1）。工場で問題が起きる多くは、3番目の段階です。

## 基礎要件、セキュリティレベル、成熟度レベル

### 7つの基礎要件

3-3（システム）と4-2（コンポーネント）のすべての技術要件は、7つの基礎要件（FR）にまとめられています [2]。これらを理解してください。ギャップ分析のすべての土台になります。

| FR | 名称 | 工場の言葉で言うと何を求めるか | 典型的な工場での対策 |
|---|---|---|---|
| FR 1 | 識別と認証の管理（IAC） | 接続してくるのは誰（または何）か分かっているか？ | 共有の「オペレーター」ログインをやめて個人アカウントにする、リモートアクセスに多要素認証（MFA）を使う、OPC UAにデバイス証明書を使う |
| FR 2 | 利用の管理（UC） | 各人が役割で必要な操作だけできるようになっているか？ | HMIやエンジニアリングツールでのロールベースの権限設定、管理者アカウントの分離、ロジック変更者の監査 |
| FR 3 | システムの完全性（SI） | ソフトウェア、ロジック、データへの不正な変更を検知または防止できるか？ | アプリケーションのホワイトリスト化、署名付きファームウェア、コントローラのキースイッチをRUNにしておく、ロジック変更の検知 |
| FR 4 | データの機密性（DC） | 使用中、転送中、保存中の機密情報が保護されているか？ | 暗号化されたリモートセッション、レシピや図面の保護、防衛関連業務におけるCUIの取り扱い |
| FR 5 | データフローの制限（RDF） | ゾーン間の通信が必要なものだけに制限されているか？ | セグメンテーション、コンduitでのファイアウォール、インダストリアルDMZ、正当な理由がある場合の単方向ゲートウェイ |
| FR 6 | イベントへのタイムリーな対応（TRE） | インシデントに気づき、適時に対応できるか？ | ログ収集、OTネットワーク監視、アラーム対応、インシデント対応手順書 |
| FR 7 | リソースの可用性（RA） | ストレスや攻撃を受けても、重要な機能が稼働し続けるか？ | 冗長化、バックアップとテスト済みのリストア、ネットワークフロードへの防御、手動による代替運転 |

### セキュリティレベル（SL 1～4）

セキュリティレベルは、あるゾーンやコンポーネントがどの程度強い攻撃者に耐えられるかを示します。62443-3-3では4段階が定義されています [2]。

| SL | 防御対象 | 工場における想定脅威の例 |
|---|---|---|
| SL 0 | 特別な防御は不要 | ほとんど正当化されず、設計目標にはならない |
| SL 1 | 偶発的または不注意による侵害 | 技術者が誤ったスイッチポートにノートPCを接続してしまう |
| SL 2 | 低い資源、一般的な技能、低い動機による、単純な手段を用いた意図的な侵害 | 汎用のランサムウェア、標準的なツールを使う日和見的な攻撃者 |
| SL 3 | 中程度の資源、IACS固有の技能、中程度の動機による、高度な手段を用いた意図的な侵害 | 行動の前に制御システムを調べる犯罪組織 |
| SL 4 | 豊富な資源、IACS固有の技能、高い動機による、高度な手段を用いた意図的な侵害 | 特定のプロセスを狙う、資金力のある国家支援型のチーム |

セキュリティレベルは工場全体に対する1つの数値ではなく、7つのFRにまたがるベクトルです。あるゾーンでは、FR 3（完全性）については、ロジックを操作されると人が傷つくおそれがあるためSL 3が必要かもしれませんが、FR 4（機密性）については、データが機密性の高いものではないためSL 1で足りるかもしれません。補足の概要では、SLは製品全体の評価としてではなく、技術要件ごとに評価されると述べられています [3]。

セキュリティレベルには3つの種類もあります [2]。

- **SL-T（目標）:** リスクアセスメントによって定められた、ゾーンまたはコンduitに求められるレベル。
- **SL-C（能力）:** 適切に統合・設定された場合に、システム（3-3）またはコンポーネント（4-2）が提供できるレベル。
- **SL-A（達成）:** 導入された実際のソリューションのレベル。

プログラム全体は、次の1文で説明できます。SL-Cが少なくともSL-Tと同等以上のコンポーネントを選定し、SL-AがSL-Tに達するように設定し、そうならない場合には補償的対策を講じる。

**多くの中堅製造業者が目標を設定する方法。** 生産ゾーンの目標としては、個別製造業ではSL 2が一般的であり、その侵害が負傷、大規模な環境への放出、長時間の停止を引き起こしうるゾーン（安全システムや重要なプロセス制御など）ではSL 3が用いられます。これは実務者の経験であり、規格の規定ではありません [unverified as a statistic]。この判断はリスクアセスメントの中で文書化し、設備所有者が承認すべきものです。

### 成熟度レベル

セキュリティレベルは技術的な強度を測るものです。成熟度レベルは、プロセスがどれだけうまく運用されているかを測るものです。62443の成熟度モデルはCMMIに基づいており、パート2-1、2-2、2-4、4-1で使われています [2]。副次的な概要では、ML 1（初期、場当たり的）、ML 2（管理された、文書化され再現可能）、ML 3（定義され、組織全体で実践され、証跡がある）、ML 4（改善中、測定され、継続的に改善される）が説明されています [3]。

実務上の見方として、2-4のプロセスがML 1にとどまっているインテグレーターは、適切な技術者が現場にいるときには良い仕事をしますが、そうでなければ質の低い仕事になります。契約ではML 2以上を求めてください。これは、文書化された手順、訓練された要員、証跡があることを意味します。

### 要件の背後にある設計原則

クイックスタートガイドは、シリーズ全体に通じる4つの設計原則を挙げています。設計段階からのセキュリティ（secure by design）、攻撃対象領域の縮小（アクセス制御、セグメンテーション、最小機能、最小権限）、多層防御（defense in depth）、そして重要機能の保護です [2]。多層防御は「特に階層化された複数のセキュリティ防護を、攻撃を遅延または阻止する意図で設けること」と定義されています [2]。単一のファイアウォールがすべての負荷を担うことは想定されていません。

## ゾーンとコンduit、そしてパーデュー・モデル

### 定義

- **ゾーン:** 「リスクやその他の基準に基づいて、論理的または物理的な資産をまとめたもの」 [2]。
- **コンduit:** 「共通のセキュリティ要件を共有する通信チャネルの論理的なまとまり」 [2]。

1つのゾーン内の資産は同じセキュリティ要件を共有します。ゾーン間の通信は定義されたコンduitを通ってのみ流れ、各コンduitには独自の制御（ファイアウォールルール、プロトコル制限、認証、監視）が適用されます。ゾーンは、ロボットとそのPLCからなる単一のセル、ライン全体、ユーティリティ系統、あるいは産業用DMZのいずれにもなり得ます。

### ゾーンの描き方

資産を次の基準でおおよそこの順序でグループ化します。

1. **機能と影響度:** 安全系システムは、基本的なプロセス制御とは分けて独自のゾーンに置きます。
2. **物理的または論理的な位置:** ライン、建屋、サイト。
3. **所有とライフサイクル:** 1つの機械メーカーが納入したターンキーのラインは、自然なゾーンを形成することが多いです。
4. **技術的な対応力:** 強化できないレガシーシステムは、厳しいコンduitを備えた小さな専用ゾーンが必要になる場合があります。
5. **接続要件:** 企業系やクラウドと通信する必要のあるシステムは、プラントの奥深くではなく境界付近に置きます。

両極端は避けてください。プラント全体を1つのゾーンにすると封じ込めができません。100ものゾーンを作るとルールの管理が困難になり、誰も触れようとしないファイアウォールが生まれます。中規模のプラントでは、実務上8〜20ゾーンが一般的です [実務上の目安、未検証]。

### パーデュー・モデルとその限界

多くのプラントは今でもパーデュー・エンタープライズ参照アーキテクチャでアーキテクチャを説明しています。これはISA-95規格が機能階層として採用したものです。そのレベルは、ゾーンを検討する最初の地図として役立ちます。

| レベル | 内容 | 例となるシステム | 一般的なゾーン |
|---|---|---|---|
| 4-5 | エンタープライズ: 事業計画と物流、企業IT、インターネット | ERP、メール、Microsoft 365、企業ID | エンタープライズゾーン |
| 3.5 | 産業用DMZ（元のモデルにはなく、実務では一般的） | ヒストリアンのレプリカ、パッチサーバー、リモートアクセスゲートウェイ、ファイル転送 | IDMZ |
| 3 | サイト運用: 製造運用管理 | MES、サイトヒストリアン、OTドメインコントローラー、バックアップサーバー | サイト運用ゾーン |
| 2 | エリア監視制御 | SCADA、HMI、エンジニアリングワークステーション | ラインまたはエリアゾーン |
| 1 | 基本制御 | PLC、DCSコントローラー、ロボットコントローラー、ドライブ | セルまたはラインゾーン |
| 0 | 物理プロセス | センサー、アクチュエーター、モーター、バルブ | セルゾーンの内側 |
| 安全 | 安全計装システム | 安全PLC、バーナー管理、プレス安全 | 独立した安全ゾーン |

パーデュー・モデルは出発点の地図であり、ゾーンモデルそのものではありません。その限界は3つの点に現れます。

- **IIoTとクラウド。** データをクラウドプラットフォームに直接送信する無線センサーは、階層を飛び越えます。IEC PAS 62443-1-6（2025年12月）は、このシリーズをIIoTシステムに適用するためのガイダンスを提供しています [5]。また、NIST SP 800-82 Rev. 4のドラフトもIIoTとクラウド統合の範囲を追加しています [10]。
- **フラットなライン。** 多くの機械は、1つのキャビネット内にレベル1とレベル2を同居させています。ゾーンは図面ではなくリスクに従います。
- **共有サービス。** オフィスとプラントの両方にサービスを提供するActive Directoryは、図面には示されていない形でレベル4とレベル3を接続します。意図された依存関係ではなく、実際の依存関係をマッピングしてください。

データアーキテクチャ側(ISA-95のレベル、ユニフィケーテッド・ネームスペース、産業用DMZ内のエッジクラスター)については、[MES and ISA-95](https://www.m365.fm/en/learn/mes-isa-95/)および[Azure for manufacturing](https://www.m365.fm/en/learn/manufacturing-it-azure/)のガイドを参照してください。

## 62443-3-2のリスクアセスメント、ステップごとの手順

62443-3-2は、「システムがある」という状態から「ゾーン、コンduit、目標セキュリティレベルがわかっている」という状態に至るまでの方法を説明しています。クイックスタートガイドは、このワークフローを7つのゾーンおよびコンduit要件(ZCR)にまとめています[2]。

| ステップ | ZCR | 活動 | 成果物 |
|---|---|---|---|
| 1 | ZCR 1 | 対象システム(SUC)の特定 | 境界、資産一覧、侵入経路 |
| 2 | ZCR 2 | 初期のサイバーセキュリティリスクアセスメントの実施 | システムが侵害された場合の最悪の結果 |
| 3 | ZCR 3 | SUCのゾーンおよびコンduitへの分割 | ゾーンおよびコンduitの図 |
| 4 | ZCR 4 | 判断:初期リスクは許容リスクを超えているか? | 詳細アセスメントが必要なゾーンの一覧 |
| 5 | ZCR 5 | 詳細なサイバーセキュリティリスクアセスメントの実施 | 脅威、脆弱性、発生可能性、結果、ゾーンおよびコンduitごとのSL-T |
| 6 | ZCR 6 | サイバーセキュリティ要件、前提条件、制約の文書化 | サイバーセキュリティ要件仕様書(CRS) |
| 7 | ZCR 7 | 資産所有者による承認 | 署名済みのCRS |

(クイックスタートガイドでは、文書化のステップを一箇所で「ZCR 4」と記載していますが、手順の順序では6番目のステップです。)

### 実際の進め方

**ステップ1:システムを定義する。** 1つのチームが数週間で対応できる範囲を選びます。たとえば、1つの生産棟、または1つのラインとそれを支えるシステムなどです。リモートアクセスの経路とクラウド接続も含めてください。サーバーが別の場所にあっても、それらはシステムの一部です。

**ステップ2:「侵害を前提とする」観点での初期アセスメント。** 候補となる各ゾーンについて、攻撃者が完全な制御を得た場合に考えられる最悪の結果は何かを問います。入力としてプロセスハザード分析(PHA)またはHAZOPを使用してください。安全チームは、どの逸脱が人に危害を与えうるかをすでに把握しています。初期アセスメントは軽減前のリスク、つまり既存のセキュリティ対策を考慮しないリスクを用います。

**ステップ3:ゾーンとコンduit。** 前節の基準に従って描きます。ゾーン境界をまたぐすべての接続がコンduitの一部になります。

**ステップ4:許容リスク。** 企業には、発生可能性と結果のどの組み合わせが許容できるかを示すリスクマトリクスが必要です。多くの工場にはすでにプロセス安全または全社リスクマネジメント用のものがあるはずです。新たに作るのではなく、それを再利用してください。

**ステップ5:詳細アセスメント。** 許容ラインを超えるゾーンについては、脅威シナリオ(ATT&CK for ICSが役立ちます[15])、既存の対策と脆弱性を列挙し、発生可能性と結果を見積もります。FRごとにSL-Tを導出します。

**ステップ6:サイバーセキュリティ要件仕様書。** ゾーンおよびコンduitごとに、SL-T、必要な対策、前提条件(例:「キャビネットは施錠され、ホールには入退室カードによるアクセス制御がある」)、制約(例:「HMIベンダーはウイルス対策ソフトをサポートしていない」)を書き出します。CRSは、インテグレーターや機械メーカーに渡す文書です。

**ステップ7:承認。** 工場長または指名された資産所有者が署名します。このステップは重要です。これにより、残留リスクはエンジニアリング上の好みではなく、経営上の判断になります。

### 簡単なスコアリング方式

全社のリスクマネジメントで使用している尺度があれば、それをそのまま使ってください。ない場合は、以下の5x5方式で初回の評価を行えます。

| スコア | 発生可能性(現行の対策を前提) | 結果(ゾーンごとの最悪の現実的ケース) |
|---|---|---|
| 1 | システムの寿命中に起こりえない | 安全への影響なし、停止時間4時間未満、5万ドル未満 |
| 2 | 起こりうるが可能性は低い | 応急処置が必要な負傷、停止時間1交代勤務未満、25万ドル未満 |
| 3 | 10年以内に起こりうる | 記録対象の負傷、停止時間1~3日、100万ドル未満 |
| 4 | 3年以内に起こりうる | 重傷または環境への放出、停止時間1~2週間、500万ドル未満 |
| 5 | 1年以内に発生すると予想される | 死亡事故または大規模な放出、停止時間2週間超、500万ドル超 |

上記の金額および時間の基準は例示であり、各社がそれぞれのリスク許容度に合わせて設定する必要があります。

リスク = 発生可能性 x 影響度。一般的な対応付けの例: 1〜6 は許容可能、8〜12 は対策と承認が必要、15〜25 は許容不可。SL-T については、実務上の簡便な目安として、最悪の影響度が 4 または 5 のゾーンには FR 1 から FR 3 および FR 7 について SL-T 3 を割り当て、影響度 2 または 3 のゾーンには SL-T 2、影響度 1 のゾーンには SL-T 1 を割り当てます。この目安は初期検討のための当社の簡略化であり、規格が求めているのは式そのものではなく、文書化された根拠です。

## 作業例: 中規模工場のゾーンとコンduit

抽象的な定義だけでは理解しにくいため、本節では架空ですが典型的な工場に 62443-3-2 を適用します。名称や数値はすべて説明用です。

### 工場の概要

「Midwest Components」は、農業機械および建設機械向けの金属製ハウジングとアセンブリを製造しています。拠点は1か所、従業員は420名、3交代制で、年間売上高は約1億5,000万ドルです。生産ラインは次のとおりです。

- **プレス工場:** サーボプレス4台とトランスファー自動化装置。1つのプレスラインには、ライトカーテンと両手操作制御を備えた安全 PLC があります。
- **溶接セルエリア:** 2社の機械メーカーによる溶接ロボットセル12基。各セルには、独自の PLC、ロボットコントローラ、HMI があります。
- **塗装工場:** 粉体塗装ラインと硬化オーブン（都市ガスバーナーとバーナー管理システム付き）。小規模な DCS で運用しています。
- **組立:** トルク工具、ラベルプリンタ、コンベア用ライン PLC を備えた手作業組立ライン2本。
- **ユーティリティ:** 圧縮空気、冷却水、HVAC、エネルギー計量を SCADA システムで監視しています。
- **拠点システム:** サーバと40台のクライアントを備えた MES、ヒストリアン、三次元測定機（CMM）を備えた品質試験室、OT 用 Active Directory、バックアップサーバ。
- **全社システム:** 本社 IT がホストする ERP、Microsoft 365、全社の ID 基盤。
- **リモートアクセス:** 溶接機の2社と、プレスメーカーは、それぞれ現在、セルラーモデムを備えた独自のリモートアクセス装置を使用しています。塗装ラインのインテグレーターは、ベンダー用 VPN 経由で接続しています。
- **クラウド:** エネルギー監視サービスは、ユーティリティネットワーク内のゲートウェイから、インターネット経由で計量データを受信しています。

### ステップ1と2: 初期評価

チーム（工場エンジニアリング部門長、制御担当リーダー、IT セキュリティ担当リーダー、EHS 責任者、保全監督者）は、各エリアについて「攻撃者にこの設備を掌握された場合、考えられる最悪の結果は何か」という問いを立てて確認しました。

| エリア | 考えられる最悪の結果（侵害を前提） | 影響度スコア |
|---|---|---|
| プレスライン安全 PLC | 運転中に安全機能が無効化され、重傷災害のリスクが生じる | 5 |
| プレス制御 | 金型およびプレスの破損、数週間の停止 | 4 |
| 塗装オーブンのバーナー管理 | 安全でないバーナー状態となり、火災または爆発のリスク | 5 |
| 塗装 DCS | バッチの廃棄、数日間の停止 | 3 |
| 溶接セル | 治具の破損、品質流出、セルあたり1〜3日の停止 | 3 |
| 組立ライン | 誤ったトルクまたは誤ったラベルによる、顧客への品質流出 | 3 |
| ユーティリティ SCADA | 圧縮空気および冷却水の喪失により、工場全体が停止 | 4 |
| MES およびヒストリアン | 数日間は手作業による縮退運転が可能 | 3 |
| 品質試験室 | 誤った計測データによる品質流出 | 2 |
| 全社 IT | 業務の中断。受注および出荷データが利用できない場合は工場が停止 | 4 |

| C6 | Z7 塗装DCS <-> Z8 バーナー管理 | ステータスおよび許可信号 | 有線I/O。技術者によるアクセスは、変更管理（MOC）に基づく現地でのみ |
| C7 | Z12 IIoTゲートウェイ <-> インターネット（クラウドサービス） | 暗号化された送信テレメトリーのみ（外向き） | 専用VLANに配置したゲートウェイ。外向きのみ、内向きの接続は無し |
| C8 | Z10 ユーティリティ -> Z12 | 計量値 | 一方向のデータフロー（データダイオードまたは一方向のファイアウォールルール）。Z12からZ10への経路は無し。まず計量器のプロトコルが一方向で動作するか確認すること。要求応答型のプロトコルの場合は、Z10側でポーリングを行うゲートウェイが必要 |

### ステップ4から7：ギャップから要件仕様書へ

Z4プレス安全の詳細評価では、初期リスクは5（影響度）×3（発生可能性：安全PLCはプレスHMIのネットワークおよび機械メーカーのセルラーモデムから到達可能）＝15で、許容できないことが分かりました。計画している対策（独立したゾーン、ルーティング可能な接続の撤廃、セルラーモデムの撤去、RUN位置でのキースイッチの保護、ロジックのチェックサムの毎週確認）により、チームは発生可能性を1、残留リスクを5と見積もり、許容可能と判断しています。資産所有者が承認しています。

Z5 と Z6 でのギャップは、主に FR 1 と FR 2 にあります。12 台すべての HMI とロボットのティーチペンダントで、アカウントが共有されています。次の セル購入時の CRS では、名前付きアカウントと SL-C 2 認証の HMI が求められます。既存のセルについては、補償策として、その前段に個人アカウントを持つジャンプホストを設け、ノートパソコンからの直接接続を禁止します。

### 1 年後の結果

| 指標 | 導入前 | 12 か月後 |
|---|---|---|

| ゾーン | 1 つのフラットな工場ネットワーク。事務 VLAN がそこにルーティングされている | 工場ゾーン 12 と、その間に IDMZ を置いたエンタープライズ |

## OT 資産目録

保護できるのは、存在を把握しているものだけです。資産目録は、62443-3-2 (対象システムの特定) およびすべての NIST プロファイルにおける最初の段階です。NIST SP 800-82 Rev. 4 草案は、資産管理に関する指針を拡充しています [10]。

### 記録すべき項目

有用な目録は IP アドレスの一覧にとどまりません。この表はひな形です。太字の項目から始め、残りは時間をかけて追加してください。

### 何も壊さずに目録を作る方法

1. **既存の情報から始める。** 電気図面、PLC のプロジェクトファイル、ネットワークスイッチの設定、保全管理 (CMMS) の記録、発注書、機械メーカーの文書には、データの大部分がすでに含まれています。
2. **受動的なネットワーク探索。** 市販の OT 監視ツールは、ネットワークトラフィックのコピー (SPAN ポートまたはネットワーク TAP 経由) を傍受し、コントローラにパケットを送ることなく、機器、ファームウェアのバージョン、通信パターンを特定します。
3. **ベンダーツールと管理された照会。** エンジニアリングソフトウェアは、コントローラから機器情報を安全に読み取れます。ベンダーが対応していて、生産部門が時間帯に同意している場合は、能動的な照会も許容されます。
4. **現場を歩いて確認する。** 目録作成では、どの図面にも載っていない機器が必ず見つかります。忘れられた携帯回線ルーター、キャビネット内のノートパソコン、業者が設置した無線アクセスポイントなどです。
5. **継続的に維持する。** 更新を変更管理に結び付けてください。目録に登録されていない機器は稼働させない。毎月、監視で見えているものと照合します。

### ツールについて

専門の OT セキュリティプラットフォームは、受動的な探索と脆弱性の照合を自動化します。Microsoft は、Defender for IoT の OT セキュリティ構成要素を 2029 年 10 月に廃止すると発表し、顧客にパートナーソリューションを案内しています [31]。その移行については [製造業向け Azure ガイド](https://www.m365.fm/en/learn/manufacturing-it-azure/) で扱っています。どのツールを選ぶにしても、目録は資産所有者のものであり、エクスポートできる必要があります。特定のベンダーのコンソールに閉じ込めないでください。

## ネットワークのセグメンテーションと産業用DMZ

セグメンテーションはFR 5(制限されたデータフロー)を実装するものです。第3章で取り上げた事例の大半において被害の拡散を抑えられたはずの唯一の対策であり、多くの工場で最も大きなギャップが見つかる箇所でもあります。

### 目標アーキテクチャ

- **企業と工場の間の2層境界。** 企業側と現場の運用側の間に産業用DMZ(IDMZ)を置き、両側にファイアウォールを設けます。企業から工場へ直接通過するトラフィックはなく、すべてのやり取りはIDMZで終端します(データブローカー、ヒストリアンのレプリカ、ファイル転送、ジャンプホスト、パッチサーバー)。
- **ゾーン単位の内部セグメンテーション。** 工場内では、各ゾーンをそれぞれ独立したVLANまたは物理ネットワークに配置し、コンジットにファイアウォールまたはアクセス制御リストを設けます。
- **安全系システムの分離。** 安全ゾーンは、他のネットワークとルーティング可能な接続を持たないか、プロセス安全の承認を得た厳しく制限されたコンジットを通じてのみ接続します。
- **デュアルホーム接続のPCを置かない。** オフィス側と工場側にそれぞれネットワークカードを持つPCは、すべてのファイアウォールを迂回してしまいます。
- **インターネットは定義された経路のみ。** クラウド接続はIDMZまたは専用のIIoTゾーンを経由し、外向き通信のみとします。

### 7つのステップによるセグメンテーションプロジェクト

1. **まず実際のトラフィックを把握する。** 2〜4週間パッシブ監視を実施し、誰が誰と通信しているかを確認します。工場では毎回驚きの結果が出ます。
2. **目標とするゾーンモデルを描き**(第9章)、生産部門と合意します。
3. **IDMZを構築し、境界をまたぐサービスを移行します。** ヒストリアンのレプリカ、リモートアクセスゲートウェイ、パッチサーバー、ファイル転送などが対象です。
4. **ファイアウォールはまず「許可してログ取得」に設定します。** コンジットにファイアウォールを設置し、現在のトラフィックを許可しつつすべてをログに記録するルールを設定します。
5. **段階的にルールを絞り込みます。** 広範なルールを、送信元、宛先、プロトコル、ポートを指定した具体的なルールに置き換えます。ゾーンごとに、制御技術者が現場に立ち会う計画された作業時間帯に実施します。
6. **ログに想定どおりのトラフィックしか現れなくなったら、「デフォルト拒否」に切り替えます。**
7. **ルールを変更管理の対象にします。** 新しいルールには、依頼者、業務上の理由、有効期限、承認者を必ず付けます。

### ファイアウォールルールのテンプレート

| 項目 | 記入例 |
|---|---|
| ルールID | C4-017 |
| コンジット | C4 (Z2 現場運用 -> Z3 プレス制御) |
| 送信元 | MESサーバー 10.20.1.15 |
| 宛先 | PR3-PLC01 10.30.3.11 |
| プロトコル/ポート | EtherNet/IP, TCP 44818 |
| 方向 | Z2 -> Z3 のみ |
| 業務上の理由 | MESが部品カウンタを読み取り、製造指示番号を書き込む |
| 依頼者/承認者 | MES管理者 / プレス制御責任者 |
| 有効期限 | 見直し日 2027-11 |
| ログ取得 | あり |

### 無線およびセルラー接続

ハンディスキャナー用のWi-Fi、無線センサー、機械盤内のセルラーモデムは、いずれも有線ネットワークの図面には現れない経路を作ります。各無線ネットワークは独立したゾーンとして扱うか、コンジットの一部として扱ってください。具体的には、工場機器用とゲスト用でSSIDを分けること、工場機器には証明書による認証を用いること、無線と制御ネットワークの間でブリッジしないこと、そして不正なアクセスポイントやモデムを見つけるために定期的な電波調査を行うことです。クラウドサービスへ直接データを送信する無線IIoTセンサーは、worked exampleのZ12のようなIIoTゾーンに配置します。

### よくあるセグメンテーションの問題

- **エンジニアリング用ノートPC**がゾーンとオフィスの間で持ち運ばれる。対策: ゾーンごとに固定のエンジニアリング用ワークステーションを置くか、ジャンプホストを使用し、ノートPCは工場ネットワークの外に出さない。
- **フラットな機械ネットワーク**が機械メーカーから納入される。HMI、PLC、リモートアクセス用ルーターが同じ非管理スイッチに接続されている。対策: 機械1台を1つのゾーンとして扱い、そのエッジでコンジットを制御する。
- **共有のActive Directory。** 企業のドメインを工場にまで延長していると、ドメインを掌握した攻撃者は工場も掌握できてしまう。対策: 別個のOTドメインを設けるか、定義された信頼モデルのもとでローカルアカウントを使用する。
- **ブロードキャストの多いプロトコル**は適切にルーティングできない。対策: 制御機器ベンダーと協議してVLAN境界を計画する。プロトコルによっては、レイヤー2で隣接している必要がある。

## 委託先およびエンジニアのためのセキュアなリモートアクセス

多くの工場では、リモートアクセスが最大の未管理経路になっています。機械メーカーはサポートのためにこれを必要とし、生産現場は機械が停止した際に迅速な支援を求めます。禁止しても機能することは稀であり、現実的な解決策は、回避策よりも使いやすい管理された経路を一つ用意することです。

2026年9月、CISAとFBIは、サードパーティのICSインテグレーターと協働する重要インフラ事業者向けのファクトシートを公表しました。これは、米国の自動化企業で2025年に発生した侵入事案に関するFBIの分析を引用しており、インテグレーターのアクセスを必要最小限に制限すること、リモートアクセスやパッチ管理を含むサイバーセキュリティ要件を契約に明記すること、機器のインターネットへの露出を減らすこと、リモートアクセスを監視・記録し、可能な場合はオンデマンドのアクセスを用いることを勧告しています [14]。

### リモートアクセスの要件（テンプレート）

| 要件 | 詳細 | 62443 FR |
|---|---|---|
| 単一の経路 | すべてのリモートセッションはIDMZ内のゲートウェイを経由する。携帯電話回線モデムは使用しない。生産ゾーンで終端するベンダー用VPNは使用しない | FR 5 |
| 個人アカウント | 一人につき一アカウント。ベンダーの共有アカウントは使用しない | FR 1 |
| 多要素認証 | すべてのリモートセッションに適用 | FR 1 |
| セッションごとの承認 | 工場側の担当者がセッションごとに承認する。アクセスは初期状態でオフ | FR 2 |
| 最小権限 | ベンダーが保守する資産にのみ、必要な期間だけアクセスを許可 | FR 2 |
| セッションの記録とログ | 記録し、定められた期間保管する | FR 6 |
| 変更時の立会い | ロジックの変更は、工場のエンジニアが立ち会い、作業指示書がある場合にのみ行う | FR 3 |
| ファイル転送 | スキャン済みの転送ゾーンを経由するファイルのみ許可 | FR 3 |
| 契約 | リモートアクセスのルール、通知義務、責任範囲をサービス契約に明記する | 2-4 |

### 実務上のヒント

- **安全な経路を、安全でない経路より使いやすくする。** 夜間の承認に二時間かかるなら、誰かが携帯電話回線のルーターを接続してしまいます。シフトごとに承認者の当番を定めてください。
- **不要な機器を取り除く。** リモートアクセス機器はすべて台帳に登録し、ゲートウェイを経由しないものは撤去または無効化します。多くの機械メーカーは独自のルーター付きでラインを納入するため、その点を購入仕様書（第17節）に盛り込んでください。
- **アカウントを四半期ごとに見直す。** 退職したベンダー担当者のアカウントは削除してください。

## OTにおけるパッチおよび脆弱性管理

オフィスITでは「迅速にパッチを当てる」が原則です。OTでは「慎重に判断する」が原則です。パッチの適用には、ベンダーの承認、コントローラーの再起動、規制業界における再バリデーション、あるいはライン全体の試験が必要になる場合があります。FDA規制の工場(医薬品、医療機器、食品)や、自動車・航空宇宙分野の顧客要件のもとでは、バリデーション済みシステムへの変更は通常、変更管理およびバリデーション手順の対象となります。パッチ適用の時間枠には、品質部門のレビュー時間を織り込んでください。ISA-TR62443-2-3は、IACS環境におけるパッチ管理を扱っています[1]。

### 脆弱性情報の入手元

- PLC、HMI、ドライブおよびソフトウェアのサプライヤーが公開するベンダーセキュリティアドバイザリおよび製品セキュリティポータル。
- CISAのICSアドバイザリ。産業用製品の脆弱性を公開するもので、多くはベンダーと連携して公表されています[unverified as to current volume; check the CISA advisories page]。
- OT監視ツール。在庫に登録された機器のファームウェアバージョンを、アドバイザリと照合します。

### アドバイザリごとの判断表

| 確認事項 | はいの場合 | いいえの場合 |
|---|---|---|
| 該当製品は当社の在庫にあるか | 継続 | 終了し、記録する |
| 脆弱な機能は当社の構成で使用されているか、または到達可能か | 継続 | 理由を記録し、次回の変更時に再確認する |
| 悪用が確認されているか、または公開されたエクスプロイトが存在するか | 優先度:高 | 影響度スコアで優先度を決める |
| 資産は信頼度の低いゾーンからまたはリモートから到達可能か | 優先度:高 | 優先度:中 |
| ベンダーは当社のバージョンに対するパッチを承認しているか | 次回の適用時間枠でパッチを計画する | 代替措置を適用する |
| 停止なしでパッチを適用できるか | 通常のメンテナンスで計画する | 計画停止で計画する |

### パッチを適用できない場合の代替措置

パッチが入手できない、承認されていない、または次回停止までに適用できない場合は、次の措置を取ります。

- 接続経路を制限する。資産を必要とするホストとプロトコルのみを許可する。
- 未使用のサービスとポートを無効にする。
- コントローラーがサポートしている場合は、リモートからのプログラム変更を防ぐため、キースイッチをRUNにする。
- 資産の監視を強化する(新規接続やプログラムダウンロードの警報)。
- 残留リスクを文書化し、資産オーナーの承認を得る。

### 判断の例

あるアドバイザリで、Z3プレス制御に使用しているPLC機種のWebサーバーに、リモートから悪用可能なサービス拒否の脆弱性があることが示されました。在庫を確認したところ、影響を受けるPLCは4台でした。Webサーバーは有効化されていますが、使用はされていません。ファームウェアの修正版は提供されていますが、コントローラーの再起動が必要で、ベンダーは機能試験の実施を推奨しています。判断は次のとおりです。次の週末の時間枠(プレス1台あたり30分)に4台すべてのPLCでWebサーバーを無効にし、接続経路C4でPLCへのHTTPおよびHTTPSを遮断します。ファームウェアは8週間後の計画停止時に適用します。暫定的なリスクは文書化し、工場エンジニアリング部門長の承認を得ます。

### レガシーおよびサポート終了システム

どの工場にも、今後パッチが提供されないシステムがあります。サポートが終了したWindowsバージョン上のHMIや、ベンダーが製造を中止したコントローラーなどです。これらは、無期限に更新され続ける例外としてではなく、予算を伴うライフサイクルの課題として扱ってください。在庫項目の「ベンダーサポート状況」は、ライン再構築と設備投資計画に沿った更新計画へ反映させます。

## アカウント、ハードニング、リムーバブルメディア

FR 1からFR 3は、工場で最も目に見える不備があり、かつ最も安価に是正できる領域です。

### アカウントとID

- **対応しているシステムでは共有ログインを廃止する。** シフト全体で共有される「Operator」「maint」「admin」アカウントは、すべての変更を追跡不能にします。現在の多くのHMIおよびSCADAシステムは個人別アカウントやバッジログインに対応していますが、古いシステムでは対応していない場合があります。
- **管理者アカウントを分離する。** エンジニアは、メールには通常のアカウントを使い、OT管理には別のアカウントを使い、両者を混同しないようにします。
- **すべての機器で初期パスワードを変更する。** 対象はスイッチ、ルーター、HMI、ロボットコントローラー、カメラなどです。立ち上げ時のチェックリスト項目にしてください。
- **人が遠隔からログインする場合や、IDMZへ接続する場合にはMFAを使用する。** 工場現場のHMIではMFAの導入が難しいことが多いため、物理的なアクセス制御とプロセスが許す範囲での短い画面ロックで補います。
- **ヘルプデスクを保護する。** Cloroxの事例は、ITヘルプデスクへのソーシャルエンジニアリングの電話が特権アクセスにつながりうることを示しています [20]。パスワードおよびMFAのリセットには本人確認を必須とし、特権アカウントについてはより厳格な確認を行ってください。

### Windowsベースの OTシステムのハードニング

HMI、SCADAサーバー、ヒストリアン、エンジニアリングワークステーションの多くはWindowsコンピューターです。ハードニングはベンダーのガイダンスに従って実施します。

1. システムに不要なソフトウェアおよびサービスを削除する（最小機能の原則）。
2. ベンダーが対応している場合は、アンチウイルスの代わりに、またはそれに加えてアプリケーションの許可リストを使用する。
3. USBポートを無効化するか、制限する。
4. ローカルの管理者権限を制限する。
5. 既知の正常な状態のイメージとインストールメディアを保管し、迅速な再構築に備える。

### コントローラー

- コントローラーがサポートしている場合は、キースイッチまたはソフトウェア保護をRUNに維持し、PROGRAMモードへの変更はすべて記録する。
- 現行のロジックはオフラインで保管し、チェックサムまたはプロジェクトバージョンを定期的に比較して、不正な変更を検出する（FR 3）。
- 使用していないサービス（Webサーバー、FTP、SNMP書き込みアクセス）を無効化する。

### リムーバブルメディア

USBドライブやノートパソコンは、あらゆるネットワーク境界をまたいでマルウェアを持ち込みます。簡単なルールセットは次のとおりです。

| ルール | 実施方法 |
|---|---|
| 私有メディアの使用禁止 | 文書化された方針、教育、ステーションへの掲示 |
| 使用前のスキャン | 工場入口またはIDMZ内のスキャンキオスク |
| 会社支給のメディアのみ使用 | エンジニアリング用に暗号化され、管理台帳に登録されたUSBドライブ |
| ネットワーク経由を優先 | USBの代わりにIDMZサーバーを経由したファイル転送 |
| 技術的な強制 | ポリシーによりHMIおよびサーバーのUSBポートを無効化または制限 |

## 監視と検知

FR 6(イベントへのタイムリーな対応)では、インシデントに気づけることが求められます。OT における検知には、ログとネットワークトラフィックという 2 つの情報源があります。

### ログに記録すべき対象

| 情報源 | イベント | 用途 |
|---|---|---|
| コンデュイットのファイアウォール | 許可された接続と拒否された接続 | ゾーン間で想定外のトラフィックを検出 |
| リモートアクセスゲートウェイ | ログイン、承認、セッション記録 | ベンダーの作業状況のレビュー |
| OT 用 Active Directory と踏み台ホスト | ログイン、権限変更、新規アカウント | アカウントの不正利用 |
| エンジニアリングワークステーション | ソフトウェアの起動、プロジェクトのダウンロード | 無許可のロジック変更 |
| コントローラー(対応している場合) | モード変更、プログラムのダウンロード、ファームウェア更新 | 完全性 |
| バックアップシステム | ジョブの成功と失敗 | リカバリーの準備状況 |

### パッシブな OT ネットワーク監視

専用の OT 監視ツールは、産業用プロトコルをデコードし、工場の通常の通信パターンを学習します。そのうえで、逸脱を検知してアラートを出します。例えば、新しいデバイス、ゾーン間の新しい接続、メンテナンス時間帯外のプログラムダウンロード、通常とは異なるホストからのコマンド送信などです。コピーされたトラフィックを受動的に監視するだけなので、プロセスには影響しません。NIST SP 800-82 Rev. 4 のドラフトでは、ネットワーク監視と検知に関するガイダンスが拡充されています [10]。

### アラートを誰が監視するか

誰も読まないアラートは、コストがかかるだけで効果がありません。中規模の工場における選択肢は次のとおりです。

- **企業のセキュリティオペレーションセンター(SOC)**。OT 用のプレイブックを持ち、工場側に担当の制御エンジニアが指名されて待機している体制。
- **OT の経験を持つプロバイダーによるマネージド検知サービス**。
- **工場側での少数の重要アラートのレビュー**(新規デバイス、プログラムダウンロード、承認のないリモートセッション)。残りは SOC に転送します。

どの方式を選ぶにしても、誰がどの対応を行えるかを明確に定めてください。SOC のアナリストが単独でラインを停止できてはなりません。その判断を誰が下すかは、プレイブックに明記します。

## バックアップ、復旧、および OT インシデント対応

FR 7(リソースの可用性)と、CSF 2.0 の「対応(Respond)」および「復旧(Recover)」の機能が、ここで結びつきます [11]。ノルスク・ハイドロの事例は典型例です。同社は手作業の手順により生産の大部分を維持し、後に総費用を約 8 億ノルウェークローネと見積もりました [17]。

### バックアップの対象

| 対象 | 頻度 | 保管先 | 復元テスト |
|---|---|---|---|
| PLC、セーフティ PLC、ロボットのプログラム | 変更のたびに、かつ毎月 | オフラインおよびオフサイトのコピー | 重要なコントローラーごとに年 1 回、予備機またはシミュレーターで実施 |
| HMI と SCADA のプロジェクト | 変更のたびに | オフラインおよびオフサイト | 年 1 回 |
| サーバーのイメージ(MES、ヒストリアン、SCADA、OT ドメインコントローラー) | 週次で完全バックアップ、日次で増分 | 変更不可またはオフラインのコピー | 年 2 回、1 台のサーバーを完全に再構築 |
| ネットワーク機器の構成 | 変更のたびに | オフライン | 年 1 回 |
| ファームウェアとインストールメディア | 更新時 | オフラインのライブラリ | 年 1 回、完全性を確認 |
| 文書類(図面、ゾーンモデル、資産台帳、パスワード保管庫のエクスポート) | 毎月 | オフライン、重要な項目は印刷物も保管 | 机上訓練(タバletop 演習)で確認 |

### OT インシデント対応プレイブック

OT のプレイブックは、IT のものと比べて、誰が判断するか、そして何を最初に行うかが異なります。

| フェーズ | OT 固有の内容 |
|---|---|
| 準備 | 機械メーカーや制御ベンダーを含む連絡先リスト、意思決定権限、クリーンなイメージを入れた予備のエンジニアリングノートPC、エリアごとの手動運転手順 |
| 検知と分析 | 定められた時間内に、IT セキュリティ、制御の責任者、生産管理者による合同の電話会議を行う。最初の問い: 安全性に影響があるか |
| 封じ込め | 事前に合意された選択肢: エンタープライズ側と IDMZ の切断、IDMZ と工場側の切断、個別ゾーンの隔離。どの接続を、どの生産リスクを負って切断できるかを誰が決めるか |
| 安全な状態 | プロセス安全の担当者が、運転を続けるか、手動運転にするか、安全に停止するかを判断する。復旧を「助ける」ために安全システムを無効にすることは決してしない |
| 根絶と復旧 | 既知の正常なイメージから再構築する。再起動前に、オフラインのバックアップとコントローラーのロジックを照合する。ゾーンごとに段階的に再起動する |
| 報告 | 法務と広報の対応。上場企業については SEC の重要性評価、顧客への通知、保険会社、法執行機関への連絡、EU の義務に基づく NIS2 または CRA の報告(第 19 節) |
| 教訓の反映 | 根本原因、更新されたゾーンモデル、プレイブックへの反映 |

### 実践する

生産、保全、IT、EHS、広報、経営層を交えた机上演習を、少なくとも年1回実施してください。最初のシナリオとして適しているのは次の想定です:「ランサムウェアによりMESとERPが暗号化された。ラインは稼働中である。このまま稼働を続けるか、そして製造と出荷の実績をどう追跡するか。」この問いへの答えから、手作業による代替手順が存在するかどうかが明らかになります。

CISAのCPGは、インシデント対応計画を含むガバナンスと、測定可能な基礎的実践を重視しています。CPG 2.0は2025年12月にガバナンスの構成要素を追加しました [13]。

## サプライヤーと調達の要件

工場のセキュリティレベルの大部分は、自社で構築するのではなく購入によって決まります。新たな機械、ライン、制御システムの導入はすべて、そのレベルを引き上げる機会になります。62443は、購入仕様書に使える用語を提供します。製品には4-1と4-2、インテグレーターとサービスプロバイダーには2-4、納入されたシステムには3-3を用います。

### 求めることができる認証

ISAの完全子会社であるISASecureは、2007年に設立され、62443に基づく認証プログラムを運営しています [7]。

| プログラム | 認証対象 | 基づく規格 |
|---|---|---|
| ISASecure CSA | コンポーネント(コントローラー、HMI、ネットワーク機器、ソフトウェア) | IEC 62443-4-2 [7] |
| ISASecure SSA | システム | IEC 62443-3-3 [7] |
| ISASecure SDLA | サプライヤーのセキュア開発ライフサイクル | IEC 62443-4-1 [7] |
| ISASecure ACSSA | 稼働中の現場のIACS: ポリシー、手順、サービスプロバイダーおよび技術的管理策。資産所有者によるリスクアセスメントから開始する | IEC 62443-2-1、2-4、3-2および3-3。2025年6月18日発表 [8] |

他の適合性評価制度による認証も存在します(ISAが公表したISASecureのホワイトペーパーが説明するとおり、IECのIECEEサイバーセキュリティプログラムがISASecureの主な代替となります [37])。認証は証拠であって保証ではありません。購入しようとする製品について、認証された製品バージョンとセキュリティレベルを必ず確認してください。

### 購入仕様書に盛り込む条項(テンプレート)

| 項目 | 要求事項の例 |
|---|---|
| 規格 | サプライヤーは発注日時点の最新版のIEC 62443-4-1(製品)およびIEC 62443-2-4(統合)に準拠すること。証拠: 認証書、または列挙された要件に対する自己評価 |
| セキュリティレベル | コンポーネントおよび納入システムは、IEC 62443-4-2 / 3-3に従い、SL-C 2を満たすこと(ゾーンZ4、Z8についてはSL-C 3) |
| ゾーンへの適合 | 機械は定義されたコンデュイット接続点を持つ1つのゾーンとして納入されること。すべてのポート、プロトコル、サービスを文書化したリストを提出すること |
| リモートアクセス | 内蔵のモデムやルーターを備えないこと。リモート保守は資産所有者のゲートウェイを通してのみ行うこと |
| アカウント | 役割に基づく権限を持つ個別のユーザーアカウントとすること。ハードコードされた、または文書化されていないアカウントを認めないこと。初期パスワードは試運転時に変更すること |
| ハードening | 使用しないサービスを無効化すること。ハードニングガイドを納入すること |
| パッチ適用 | サプライヤーはセキュリティアドバイザリを公表し、OSおよびファームウェアのパッチを明記された期間内に検証し、製品を明記された期間サポートすること |
| SBOM | 納入されたソフトウェアおよびファームウェアのソフトウェア部品表を提出すること |
| バックアップ | 納入されたプログラムおよびプロジェクトを編集可能な形式で、復旧手順とともに提供すること |
| 文書 | ネットワーク図、資産所有者のテンプレートによる資産一覧、ファイアウォールのルール要件 |
| 試験 | 工場受入試験および現地受入試験の一部として、セキュリティ受入試験(テスト環境でのポートスキャン、アカウントの確認)を実施すること |
| インシデント対応義務 | サプライヤーは、納入システムに影響する脆弱性およびインシデントを、明記された期間内に資産所有者へ通知すること |

CRA(第19条)は、EU市場に投入される製品について、セキュリティアップデートやSBOMを含むこれらの要件のいくつかを法的義務としています [22][23]。米国の購入者も、米国内のみの工場であっても、同じ製品が世界中で販売されているためその恩恵を受けます。

### インテグレーターとサービスプロバイダー

2026年9月付のCISA/FBIインテグレーター向けファクトシートは、運用者の視点を加えています。サイバーセキュリティとサプライチェーンの要件を契約およびサービス契約に盛り込み、データと機器の設置場所を定め、インテグレーターのアクセスを制限して監視することを求めています [14]。サービスプロバイダーには62443-2-4に関する証拠の提出を求め、そのリモートアクセスおよびデータの取り扱いを、外注業者の安全管理と同じように審査してください。

## 人、安全、そして現場

OTセキュリティは、IT部門の事務所で設計されて現場に押し付けられると失敗します。機械を運転している人こそが最初の防御線であり、同時に設計の悪い管理策による影響を最初に受ける人でもあります。

### 役割と責任（中規模工場の例）

| 役割 | OTセキュリティ上の責任 |
|---|---|
| 工場長 | 資産所有者。リスク評価と残留リスクを承認し、予算に責任を持つ |
| OTセキュリティリーダー（当初は多くの場合、制御エンジニアが兼任） | ゾーンモデル、資産台帳、ルール、インシデント調整 |
| 本社IT セキュリティ / CISO | エンタープライズゾーン、ID、SOC、ポリシー、CSF 2.0との整合 |
| 制御エンジニアリング | セキュアな構成、バックアップ、ロジック変更管理 |
| 保全 | 物理アクセス、リムーバブルメディアのルール、予備品 |
| EHS / プロセス安全 | PHA/HAZOPとセキュリティ上の影響を結び付け、安全ゾーンを承認する |
| 購買 | 仕様書と契約におけるセキュリティ条項 |
| 生産監督者とオペレーター | 異常の報告、アクセスとメディアのルールの遵守、手動による代替運転の実施 |

### 安全とセキュリティの両立

安全エンジニアとセキュリティエンジニアは、似た事柄に対して異なる用語を使うことがよくあります。例えばハザードと脅威、SILとSL、PHAとリスクアセスメントなどです。両者を同じ場に集めてください。以下の2つのルールは譲れません。

- セキュリティ対策が安全機能を無効化したり、低下させたりしてはならない。
- セキュリティインシデントへの対応が、安全状態に関する安全チームの判断を迂回してはならない。

### オペレーターが受け入れる教育

- 報告しやすい環境を作る。携帯電話の充電器を差し込んだことを認めたオペレーターには、懲戒ではなく感謝を伝えること。そうしなければ次のインシデントは報告されなくなります。
- 役割別の短いモジュールにする。オペレーターが報告すべきこと（不明なUSBドライブ、HMIの予期しない動作、アクセスを求める見知らぬ人）を扱い、一般的なフィッシング講座にはしないこと。
- 理由を説明する。オペレーターはロックアウト/タグアウトが何を防ぐのかを理解しているから、それを守ります。セキュリティのルールにも同じ説明が必要です。
- 自分たちに影響する管理策の設計に現場を関与させる。例えばHMIへのバッジログインや画面ロックなどです。労働組合のある工場では、作業ルールや監視の変更を組合と協議する必要がある場合があります。人事・労使関係部門を早い段階で関与させてください［一般的な指針。団体交渉協定を確認すること］。

現場での日々の問題解決という、より広い日常の取り組みについては、[shop floor management](https://www.m365.fm/en/learn/shop-floor-management/)のガイドを参照してください。セキュリティ上の異常も、日次のティア会議で扱うべき一つの項目です。

## 米国およびEUの義務：CMMC、SEC、CIRCIA、NIS2、CRA

62443自体は任意です。以下の義務は任意ではありません。どれが適用されるかは、顧客、所有形態、販売先によって決まります。

### 防衛サプライヤー向けのCMMC 2.0

米国防総省向けに部品を製造している場合、Cybersecurity Maturity Model Certification（CMMC）は、連邦契約情報（FCI）または管理された非機密情報（CUI）を処理、保存または送信するシステムに適用されます。プログラム規則（32 CFR Part 170）は2024年12月16日に施行されました [28]。CMMCを契約に組み込むDFARS規則は2025年11月10日に施行され、3年間の段階的な導入が行われます。フェーズ2は2026年11月10日に開始され、フェーズ3は2027年11月10日に予定されています [29]。レベル2はNIST SP 800-171に基づいています [28][29]。

これが工場の現場にもたらす意味は次のとおりです。

- **対象範囲は機械ではなくデータで決まります。** CUIと表示された図面やプログラムを受け取るCNC機械は対象になる可能性があります。コンベアを動かすだけのコントローラーは通常対象外です。CUIの表示と契約が判断基準です。
- **ゾーンを使って対象範囲を限定します。** 適切に分割されたゾーンモデルは、CMMC評価の境界を小さく保つことができます。防衛サプライチェーンにおいて、セグメンテーションの最も明確な経済的根拠の一つです。
- **特殊なケース。** レベル2では、32 CFR 170.19(c)(1)が、OT、IIoT、IoTデバイス、試験装置、政府支給機器、制限付き情報システムを「特殊資産（Specialized Assets）」として挙げています。これはCUIを処理、保存または送信できるものの、完全には保護できない資産です。これらは資産インベントリとSSPに記載し、リスクベースのセキュリティポリシーで管理し、ネットワーク図に示す必要があります。評価者はSSPを確認しますが、他のCMMC要件に対して評価はしません [38]。

防衛案件の計画面については、[航空宇宙生産計画ガイド](https://www.m365.fm/en/learn/aerospace-production-planning/)が、AS9100サプライチェーンの文脈でCMMC、ITAR、DFARSを扱っています。

### 上場企業向けのSEC規則

2023年7月26日に採択されたSEC規則により、登録企業は、重大なサイバーセキュリティインシデントが重要であると判断してから4営業日以内にForm 8-Kで開示しなければならず、年次報告書でサイバーセキュリティのリスク管理、戦略、ガバナンスを説明しなければなりません [26]。工場を停止させるランサムウェア攻撃は、重要性評価の典型的な対象であるため、OTプレイブックには開示委員会への迅速な経路が必要です。

### CIRCIA

重要インフラ向けサイバーインシデント報告法（CIRCIA）は、CISAの最終規則が施行されると、対象事業者に対し、対象となるサイバーインシデントを72時間以内、身代金の支払いを24時間以内にCISAへ報告することを義務付けます。2026年10月時点で、最終規則はホワイトハウスの審査に回付されていましたが、公布はされていませんでした [27]。2026年11月9日時点でも、2026年10月1日に到着して以降、なお審査中でした [39]。重要製造業は重要インフラ分野の一つです [32]。最終規則がどの製造事業者を対象とするかを追跡してください。

### EU拠点を持つ米国企業向けのNIS2

EUのNIS2指令は、各国法を通じて、多くの製造分野を含むEU域内の重要事業体および重要な事業体に適用されます。米国企業は、EU子会社と工場を通じて影響を受けます。ドイツの施行法は2025年12月6日に施行されました。ドイツ連邦情報セキュリティ局（BSI）は、約4,500事業体ではなく、現在約29,500事業体を監督すると述べています [24]。ドイツでは、列挙された事業体の種類に該当し、従業員数が50名以上、または年間売上高と貸借対照表総額の両方が1,000万ユーロを超える場合に対象となります。製造分野の項目には、医療機器、コンピューターおよび電子機器、電気機器、機械、自動車が含まれます [25][40]。重大インシデントについては、24時間以内の早期警告、72時間以内の通知、1か月以内の最終報告が必要です [25]。他の加盟国にも同様の規則があり、地域ごとの詳細が異なります。工場を持つ国ごとに確認してください。

### 機械メーカーおよび部品メーカー向けサイバーレジリエンス法

EU域内市場でデジタル要素を備えた機械、コントローラー、またはソフトウェアを販売する場合は、米国のメーカーも含めて、サイバーレジリエンス法(規則(EU)2024/2847)が適用されます。2026年9月11日以降、メーカーは実際に悪用された脆弱性と重大なインシデントを、ENISAの単一報告プラットフォームを通じて報告しなければなりません。早期警告は24時間以内、通知は72時間以内、最終報告は是正措置が利用可能になってから14日以内(脆弱性の場合)、または1か月以内(インシデントの場合)です [22]。主要な製品要件は2027年12月11日から適用されます [23]。機械メーカーにとっては、62443-4-1に沿ったセキュア開発が製品コンプライアンスの問題になるということです。

### サイバー保険

保険会社は、OTに関する詳細な質問をますます多くするようになっています。セグメンテーション、リモートアクセス、オフラインバックアップ、MFAなどです。Merckの事例は、保険契約の文言によって補償の範囲が大きく左右されうることを示しています。ニュージャージー州の控訴裁判所は、当事者が和解する前に、Merckの財産保険契約における戦争免責条項はNotPetyaには適用されないと判断しました [18]。サイクロン事業者と協議し、サイバー事象による生産損失が補償対象かどうか、またどのような条件で補償されるかを確認してください [general guidance]。

### 最初の30日間にやること

1. 資産責任者(通常は工場長)とOTセキュリティ担当者を任命する。
2. 把握しているすべてのリモートアクセス経路を洗い出し、各機械メーカーに接続方法を確認する。
3. 最も重要なコントローラーの現行プログラムのオフラインコピーがあるかを確認する。
4. 事務系ネットワークと工場ネットワークがファイアウォールを介さずに相互接続されていないかを確認する。
5. NIST MEPまたは社内のセキュリティ部門に、CSFに基づく自己評価を依頼する [30]。
6. 「MESとERPが暗号化された」というシナリオで、2時間の机上演習を予定する。

これらの手順に新たな技術は必要ありません。フェーズ2の予算を立てる根拠となる事実を得るための作業です。

### ロードマップを工場の実情に合わせる

- **計画停止を活用する。** セグメンテーションやファームウェア変更には作業時間帯が必要です。保守計画の中で1年前から予定を組んでください。
- **設備投資案件に便乗する。** 新ラインの導入は、安全なリモートアクセスと個別アカウントを備えたクリーンなゾーンを構築する最も低コストな機会です。
- **ツールから始めない。** インベントリとゾーンモデルが整う前に監視基盤を購入すると、誰も解釈できないアラートが生まれるだけです。

## 予算とROI：投資判断の進め方

OTセキュリティは直接の収益を生みません。その役割は損失の発生確率と影響度を下げることです。そのため、投資の根拠は三つの部分から成ります。回避できる想定損失、それによって可能になる価値、そして必要となる義務です。

### コストの区分

| 区分 | 典型的な項目 | 資本的支出（Capex）か運用費（Opex）か |
|---|---|---|
| アーキテクチャ | IDMZおよびコンデュイト用のファイアウォール、マネージドスイッチ、IDMZサーバー、リモートアクセスゲートウェイ | 主に資本的支出（ハードウェア）、サブスクリプションは運用費 |
| 可視化 | OT監視プラットフォーム、センサー、ネットワークTAP | 資本的支出またはサブスクリプション |
| 人材 | OTセキュリティ責任者（専任または兼任）、教育・訓練、外部専門家 | 運用費 |
| サービス | リスクアセスメント支援、セグメンテーション設計、SOCまたはマネージド検知 | 運用費 |
| 更新 | 保守期限切れのHMIおよびコントローラーの更新 | 資本的支出。理想的にはライン再構築に合わせて実施 |
| 復旧 | バックアップシステム、予備のエンジニアリングワークステーション、予備のコントローラー | 資本的支出 |

ここでは一般的なドル額は示しません。プラントの規模に応じた信頼できる米国の公的ベンチマークが存在しないためです。価格はゾーン数、機器の経過年数、ベンダーによって大きく変わります。フェーズ1の後に、対象範囲を定めたうえで二〜三社から見積もりを取得してください。

### 想定損失：計算例

年間想定損失（ALE：Annualized Loss Expectancy）は、リスクを財務チームの言語に置き換えるための簡単な方法です。

ALE = 年間発生率（ARO：Annual Rate of Occurrence）× 単一損失想定（SLE：Single Loss Expectancy）

Midwest Components（セクション9）について、財務・オペレーションチームは、プラントを停止させるランサムウェア事案のコストを次のように見積もっています。

| 項目 | 前提 | 金額 |
|---|---|---|
| 失われた限界利益 | 10生産日 × 1日あたり限界利益160,000ドル | 1,600,000ドル |
| バックログ解消のための残業および特急対応 | 見積もり | 350,000ドル |
| 中断されたバッチによる廃棄および手直し | 見積もり | 120,000ドル |
| インシデント対応および復旧サービス | 見積もり | 400,000ドル |
| 顧客ペナルティ | 二社のOEM顧客との契約条件 | 250,000ドル |
| **SLE（単一損失想定）** | | **2,720,000ドル** |

プログラムを実施しない場合、チームはこの種の事案の年間発生確率を10%（ARO 0.10）と見積もっています。フェーズ1〜3が完了すると、セグメンテーションと管理されたリモートアクセスによって最も一般的な侵入経路が塞がれるため発生確率は下がり（ARO 0.04）、さらにバックアップとプレイブックが検証されているため復旧期間も短くなる（10日ではなく5日）と見込んでいます。その結果、SLEは約1,640,000ドルに下がります（5日 × 160,000ドル = 800,000ドル、残業費は半分の175,000ドル、廃棄費は変わらず120,000ドル、対応費は300,000ドル、ペナルティは変わらず250,000ドル、端数処理）。

- 施策前のALE：0.10 × 2,720,000ドル = 年間272,000ドル
- 施策後のALE：0.04 × 1,640,000ドル = 年間65,600ドル
- リスク低減額：272,000ドル − 65,600ドル = 年間206,400ドル

プログラムに二年間で450,000ドル、さらに年間120,000ドルの運用費がかかる場合、リスク低減額のみで見た単純回収期間は次のとおりです：（450,000ドル）÷（206,400ドル − 120,000ドル）= 約5.2年。これは控えめな数字に見えますが、そのまま正直に提示すべきです。前提はあくまで見積もりであり、特にAROは不確実です。たとえばARO 0.05〜0.20のように幅を持たせて示し、結果がどう変わるかを経営層が確認できるようにしてください。施策前のAROを0.20、施策後を0.06とすると、年間の低減額は544,000ドル − 98,400ドル = 445,600ドルとなり、回収期間は約1.4年に短縮されます。

この例のすべての数値は説明用の仮定であり、業界のベンチマークではありません。

### 損失回避以外の価値

- **顧客および契約上の要件：** 防衛産業向けの業務におけるCMMC [28][29]、OEM顧客からのセキュリティ質問票、EU拠点および製品に対するEUの義務 [22][24]。
- **保険：** セグメンテーション、MFA、バックアップに関する適切な回答は、保険の引受可否と条件に影響します [一般的な指針。詳細は保険ブローカーに確認してください]。
- **デジタルプロジェクトの実現：** 明確なIDMZおよびコンデュイトのモデルは、MES、ヒストリアン、クラウドのプロジェクトを、より速く、より安全に承認できるようにします。これらに依存するプロジェクトについては、[予知保全とIIoT](https://www.m365.fm/en/learn/predictive-maintenance-iiot/)および[製造業におけるデジタルツイン](https://www.m365.fm/en/learn/digital-twin-manufacturing/)を参照してください。
- **自ら招く停止の削減：** 資産台帳、変更管理、検証済みのバックアップは、HMIのハードディスク故障のような通常の障害からの復旧も短縮します。

### 資本的支出と営業費用

ファイアウォールやサーバーは通常、資本的支出として計上されます。サブスクリプション型ツール、マネージドサービス、人件費は営業費用です。サブスクリプション型ツールへの移行は支出を資本的支出から営業費用へと移すため、資本予算は厳しいものの運営予算には余裕がある工場にとっては重要な点です。プラントの管理部門とプログラムの分類方法を早い段階で協議してください。分類によって、承認を行う予算責任者が変わるためです。

## OT セキュリティ KPI

行動を左右する指標をいくつか計測します。監視運営グループには毎月、経営層には四半期ごとに報告します。KPI 設計全般については、[製造業 KPI](https://www.m365.fm/en/learn/manufacturing-kpis/) に関するガイドを参照してください。

| KPI | 算式 | 目標例 | 重要な理由 |
|---|---|---|---|
| インベントリ網羅率 | 必須項目がすべて揃っている資産 / 監視で検出された資産 x 100 | > 95% | 他のすべての指標の基礎 |
| 管理されていないリモートアクセス経路 | ゲートウェイを経由しないリモート経路の数 | 0 | 最も一般的な侵入経路 |
| SL-T が承認されたゾーン | 署名済みのリスクアセスメントがあるゾーン / 全ゾーン x 100 | 100% | 手法が適用されていることを示す |
| 通信経路ルールの管理状況 | 所有者、理由、有効な見直し日が記録されたファイアウォールルール / 全ルール x 100 | > 90% | ルールの乱立を防ぐ |
| 重要コントローラーの復旧テスト実施率 | 過去 12 か月以内に復元テストを実施したコントローラー / 重要コントローラー x 100 | 100% | 復旧への備えを示す |
| バックアップの最新性 | オフラインバックアップが稼働中のプログラムと一致するコントローラー / 全コントローラー x 100 | > 98% | 設定のずれや無許可の変更を検出する |
| 勧告への判断までの平均日数 | 勧告公開から文書化された判断までの平均日数 | < 30 日 | パッチ適用のプロセスが機能している |
| 共有アカウントの削減 | 共有ログインを使用しているシステム / 対象システム | 四半期ごとに減少 | FR 1 および FR 2 の進捗 |
| アラートのトリアージ時間 | 優先度の高い OT アラートからトリアージまでの中央値 | < 1 時間 | 検知が有効に機能している |
| 机上演習 | 生産現場が参加する演習の年間実施回数 | 年 1 回以上 | 対応を訓練している |
| セキュリティ条項付きの新規設備 | 62443 条項を含む自動化機器の発注書 / 全自動化機器の発注書 x 100 | 100% | 新たなギャップの発生を防ぐ |

**計算例。** 監視で 640 件の資産が検出され、598 件で必須項目がすべて揃っています。インベントリ網羅率 = 598 / 640 x 100 = 93.4% です。目標に 1.6 ポイント届きませんでした。対応として、不足している 42 件の記録を補完します。大半は溶接エリアのものです。

「遮断された接続数」のような見栄えのための指標は避けてください。数値の増加は防御の向上を意味することもあれば、設定ミスの増加を意味することもあるためです。

## よくある間違い

1. **IT統制をそのまま一対一で移植する。** アクティブスキャン、自動パッチ適用、コントローラー上のエンドポイントエージェントが停止事故を引き起こしたことがあります。すべてベンダーと事前に検証してください。
2. **ツール購入から始める。** インベントリとゾーンモデルがなければ、監視プラットフォームはノイズを生むだけです。
3. **ゾーンが一つだけ。** 事務所と工場の間にファイアウォールを置くことは必要ですが、その背後がフラットな工場ネットワークだと、マルウェアはすべてのラインに到達できてしまいます。
4. **ゾーンが多すぎる。** 誰も理解していないルールが「一時的に」大きく開けられ、そのまま残ります。
5. **リモートアクセス機器を無視する。** 機械キャビネット内のセルラールーターは、アーキテクチャ全体を迂回してしまいます。
6. **一度も復元していないバックアップ。** インシデント発生時に、バックアップが不完全または古いものだったと気づく工場は少なくありません。
7. **意思決定権限が未定義。** インシデントの際に「誰が工場を切り離してよいか」という問いには、事前に答えが用意されていなければなりません。
8. **生産を考慮しないセキュリティ。** オペレーターや保全担当者を交えずに設計された統制は、迂回されてしまいます。
9. **62443を認証取得プロジェクトとして扱う。** 価値は書類ではなく、方法と継続的な運用にあります。
10. **ヘルプデスクと ID 管理を忘れる。** Clorox の事例は、ID リセットの手続きが最も脆弱な環節になりうることを示しています [20]。
11. **新たなギャップを買い込む。** セキュリティ条項なしで発注された機械はすべて、今後20年にわたるレガシー問題を次の世代に残します。
12. **「エアギャップ」を前提にする。** 自社はエアギャップ化されていると考えている工場の多くには、少なくとも一つは把握していない接続があります。

## IEC 62443 および OT セキュリティプログラムの限界

62443 は産業オートメーションのセキュリティにおいて入手可能な最良のフレームワークですが、これを基盤にプログラムを構築する前に知っておくべき限界があります。

- **コストとアクセス。** 文書は有償の出版物であり、Industrial Cyber はシリーズ全体が800ページを超えると述べています [34]。小規模工場が全文を読むことは稀で、クイックスタートガイドやコンサルタントがその穴を埋めますが、品質にはばらつきがあります。
- **経年と改訂。** 3-3 は2013年の発行で、3-2、3-3、4-2 の第2版はなお作業中です [1][6]。クラウド、IIoT、コンテナ化されたエッジといった分野は、1-6 のような新しい PAS 文書 [5] によってのみ扱われています。
- **公式ではなく判断。** 規格は リスクに応じて SL-T を設定するよう求めていますが、プレス機ラインに正確にどの SL が必要かは示していません。資格を持つ二つのチームが異なる結論に至ることもあります。
- **セキュリティレベルは保証ではない。** SL-C 3 の構成要素でも、設定が不適切であれば SL-A 1 になります。認証は特定のバージョンと構成を対象としています。
- **レガシーという現実。** 導入済みの多くのシステムは、FR 1 と FR 2 の SL 2 要件を満たすことができません。代替措置は機能しますが、複雑さが増します。
- **組織への要求。** 2-1 と 2-4 は文書化されたプロセスを求めており、ML 2 以上は小規模工場とそのインテグレーターにとって実質的な負担です。
- **すべてに対する防御ではない。** セグメンテーションと監視はリスクを低減しますが、強い決意と豊富な資源を持つ攻撃者を防ぐものではありません。復旧能力は依然として不可欠です。
- **フレームワークの重複。** 62443 を CSF 2.0、SP 800-82、CMMC、NIS2 に対応付けるには手間がかかります。CSF 2.0 を軸に再構成された SP 800-82 Rev. 4 のドラフトは、確定すれば NIST 側の対応を容易にするはずです [10]。

## FAQ: OT サイバーセキュリティと IEC 62443

### OT サイバーセキュリティとは何ですか?

OT サイバーセキュリティは、PLC、SCADA、HMI、ロボット、安全システムなど、物理プロセスを監視・制御するシステムを、障害や不正操作から守ることです。優先順位は、まず安全性と可用性、次に完全性と機密性です。米国の主要なガイドは NIST SP 800-82 Rev. 3 です [9]。

### IT セキュリティと OT セキュリティの違いは何ですか?

IT セキュリティはデータと業務システムを守るもので、通常は機密性を最優先します。OT セキュリティは物理プロセスを守るもので、制御が失われると人が負傷したり、生産が停止したりする可能性があります。OT システムは稼働期間が長く、パッチ適用が困難で、認証のないプロトコルを使うことが多く、計画された時間帯にのみ変更されます (第 2 章)。

### ISA/IEC 62443 とは何ですか?

産業オートメーション制御システムのセキュリティに関する国際規格群です。ISA99 委員会と IEC が策定しました。一般、ポリシーと手順、システム、コンポーネントの 4 つのグループで構成され、役割、ゾーンとコンduit、セキュリティレベル、基本要求事項を定義しています [1][2]。

### OT セキュリティと ICS セキュリティの違いは何ですか?

日常的な使い方では違いはありません。ICS セキュリティは古くからある用語で、PLC、DCS、SCADA などの産業用制御システムを指します。OT セキュリティはより広い概念で、ビル自動化、交通システム、物理アクセスシステムも含みます。これは NIST SP 800-82 Rev. 3 による OT の定義です [9]。IIoT セキュリティは、エッジやクラウドのプラットフォームにデータを送るコネクテッドセンサーやゲートウェイを扱う分野です。IEC PAS 62443-1-6 は 62443 シリーズを IIoT に適用するものです [5]。

### IEC 62443 における役割は何ですか?

資産所有者 (IACS に対して説明責任を負う)、統合サービスプロバイダー、保守サービスプロバイダー、製品サプライヤーの 4 つです [2]。各役割にはシリーズ内の担当部分があり、明確な契約を作成できるようになっています (第 5 章)。

### 米国では IEC 62443 は義務ですか?

一般的に米国の法律で 62443 が義務付けられているわけではありません。顧客との契約、調達仕様、保険条件、または業界のルールを通じて拘束力を持つようになります。CRA などの EU の法律は、62443 に基づくプロセスが満たすのに役立つ義務を定めています [22]。

### IEC 62443のセキュリティレベルとは何ですか?

SL 1は偶発的または偶然の侵害から保護し、SL 2は簡単な手段による意図的な侵害から保護します。SL 3はIACS固有のスキルと中程度のリソースを持つ高度な攻撃者から、SL 4は拡張されたリソースと高い動機を持つ高度な攻撃者から保護します [2]。各ゾーンには、多くの場合基盤要件ごとに、目標レベルが割り当てられます。

### IEC 62443の7つの基盤要件とは何ですか?

識別と認証の管理、使用の管理、システムの完全性、データの機密性、制限されたデータフロー、イベントへのタイムリーな対応、リソースの可用性です [2]。

### ゾーンとコンduitとは何ですか?

ゾーンは類似したセキュリティ要件を持つ資産をまとめたものであり、コンduitはゾーン間の通信チャネルをまとめ、そのトラフィックに対する管理策を担います [2]。セクション9に、中規模工場の完全な例を示しています。

### IEC 62443のどの部分から資産所有者は始めるべきですか?

セキュリティプログラムについては62443-2-1、リスクアセスメントとゾーンモデルについては62443-3-2から始めます。その後、3-3がセキュリティレベルごとのシステム要件を定義し、2-4と4-1/4-2はインテグレーターやサプライヤーとの契約に関わります [1]。

### IEC 62443はNISTサイバーセキュリティフレームワークとどのような関係にありますか?

両者は互いに補完し合います。CSF 2.0は企業全体に対するガバナンスと共通の言語を提供し [11]、62443は工場のための技術的および組織的な方法を提供します。NIST SP 800-82は両者を結び付けており、そのRev. 4草案はCSF 2.0を中心に再構成されています [10]。

### パーデュー・モデルとは何であり、今でも有効ですか?

フィールド機器(レベル0)から企業(レベル4および5)に至る階層型の参照アーキテクチャであり、多くの場合レベル3.5に産業用DMZがあります。ゾーンを定める出発点の地図としては有用ですが、IIoTやクラウド接続はそのレベルを横断するため、ゾーンは実際のリスクとデータフローに従って定める必要があります(セクション7)。

### ゼロトラストはOTにどのように適用されますか?

ゼロトラストとは、ネットワーク上の位置に基づく暗黙の信頼を置かないことを意味し、すべてのユーザー、機器、接続は必要とする特定のアクセスについて認可されなければなりません。工場においては、これは62443がすでに求めている内容と一致します。すなわち、明示的で許可リスト化されたコンduitを持つゾーン、共有ログインではなく個別のアカウント、そして仲介され承認されたリモートアクセスセッションです(セクション7、11、12、14)。多くのフィールドプロトコルには認証機能が組み込まれていないため(セクション2)、エンジニアリングやベンダーアクセスなどの管理機能とコンduitから着手してください。NIST SP 800-82 Rev. 4草案は、システム管理機能に対するゼロトラストの原則に関するガイダンスを追加しています [10]。

### 生産を止めずにレガシーPLCにパッチを適用できますか?

多くの場合、直ちには難しく、またそうする必要もありません。まず、脆弱な機能が使用されているか、そして到達可能かを確認してください。ファームウェアの修正に再起動や機能試験が必要な場合は、今すぐ代償的対策を講じてください。すなわち、コンduitを制限する、未使用のWebサーバーなど未使用のサービスを無効化する、対応している場合は鍵スイッチをRUNに保つ、そして資産の監視を強化する、といった対策です。残留リスクを文書化して承認し、次の計画停止時に修正を適用してください。セクション13には判断表と実例があります。修正が提供されないコントローラーは、恒久的な例外ではなく、更新計画に含めるべきものです。

### IEC 62443の認証を取得できますか?

はい、取得できます。製品はISASecure CSA(4-2)、システムはSSA(3-3)、開発組織はSDLA(4-1)の下で認証を受けられ [7]、2025年6月以降は稼働中の拠点もISASecure ACSSAの下で認証を受けられます [8]。その他の適合性評価制度でも62443に対する認証が行われており、とりわけIECのIECEEサイバーセキュリティプログラムがあります [37]。

### 62443-4-1と62443-4-2の違いは何ですか?

4-1はサプライヤーのセキュアな開発プロセス(製品がどのように作られるか)を対象とし、4-2はコンポーネントの技術的なセキュリティ機能(製品が何をできるか)を対象とします [1][7]。

### 工場でIEC 62443を実装するにはどのくらいの期間がかかりますか?

中規模の単一拠点であれば、中核部分については12〜24か月が現実的な道筋です。すなわち、資産の棚卸し、ゾーンモデル、IDMZ、リモートアクセス、バックアップ、監視、インシデント対応です(セクション20)。その後、プログラムは年次の定例業務として継続されます。この見積もりは本ガイドのロードマップに基づくものであり、公表されたベンチマークに基づくものではありません。

### OTセキュリティにはどのくらいの費用がかかりますか?

費用はゾーンの数、機器の経過年数、選択するツールによって異なります。信頼できる公開のベンチマークは確認できませんでした。セクション21では、年間化損失期待値を用いて投資根拠を組み立てる方法を示し、前提条件を明示した実例を挙げています。

### CMMCはOTシステムに適用されますか？

CMMCは、FCIまたはCUIを処理、保存、または送信するシステムに適用されます。CUIの表示がある図面やプログラムを受け取る機械は対象範囲に含まれる可能性があります。適切なセグメンテーションにより、評価の境界を小さく保つことができます [28][29]。Level 2では、CUIを扱えるものの完全には保護できないOTは「Specialized Asset」として扱われます。これは在庫、SSP、ネットワーク図に文書化されますが、他の要件に対しては評価されません [38]。

### Colonial Pipeline攻撃から製造業者は何を学んだか？

IT上のインシデントがOT業務を停止させ得るということです。Colonialは、2021年5月7日頃のランサムウェア攻撃を受けてパイプラインの操業を停止し、約75ビットコインを支払い、その後、司法省が63.7ビットコインを押収しました [16]。依存関係を把握し、縮退運転モードを備えておくことは、コントローラーを保護することと同じくらい重要です。

### 欧州に工場を持つ米国企業はNIS2に従う必要がありますか？

その欧州法人が各国の国内法の対象業種および規模基準に該当する場合は、従う必要がある可能性があります。たとえばドイツでは、対象となる法人種別で、従業員数50名以上、または売上高と貸借対照表合計の両方が1,000万ユーロを超えるエンティティにNIS2を適用しています [25][40]。

## 結論

OTサイバーセキュリティとは、攻撃者を想定したプラントエンジニアリングです。ISA/IEC 62443は、製造業者が自社の工場に合った手法を提供します。その手法とは、資産を把握すること、工場を管理されたコンduitで結ばれたゾーンに分割すること、リスクに応じて目標セキュリティレベルを設定すること、技術的および組織的対策で差を埋めること、そしてサプライヤーやインテグレーターにも同じルールを求めることです。NIST CSF 2.0とSP 800-82はこの手法を米国のガバナンスと結び付け、CMMC、SEC規則、NIS2、CRAは適用される場合に追加の義務を課します。

文書化されたインシデントは、同じ最初の一歩を示しています。産業用DMZを通じて工場を企業ネットワークから分離すること、すべてのリモートアクセス経路を管理すること、コントローラーのロジックとサーバーについて検証済みのオフラインバックアップを保持すること、そしてITが停止している間に工場がどのように稼働するかをリハーサルしておくことです。これらのいずれも、完璧なアーキテクチャや次版の規格を待つ必要はありません。第20節の30日間リストから始め、1年以内にゾーンモデルを構築し、少数のKPIで進捗を測定してください。2年以内に、中規模の工場は「エアギャップされていることを願っている」状態から、文書化され、テスト済みで、着実に改善し続けるセキュリティプログラムへと移行できます。
