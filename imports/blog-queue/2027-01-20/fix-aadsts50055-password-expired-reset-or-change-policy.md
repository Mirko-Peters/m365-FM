AADSTS50055 means the user's password has expired, so Microsoft Entra ID ended the sign-in. The user can reset the password, or an admin can reset it. If many users hit this error, the cause is the expiration policy, which you can check with Microsoft Graph PowerShell. This article follows the error code reference and the Learn pages on resetting passwords and on SSPR policies.

## What the error reference says

The Microsoft Entra error code reference lists AADSTS50055 as `InvalidPasswordExpiredPassword`. The password is expired, and therefore the login or session was ended. The user is offered the opportunity to reset it, or can ask an admin to reset it. The page links to the article on resetting a user's password.

## Option 1: The user resets the password

The reference says the user is offered a reset. Whether the user can do it alone depends on your self-service password reset setup. Learn's admin article for resets sends users who are not administrators to the Support page for resetting a work or school password. The pages I read do not list SSPR registration steps for this error, so check your SSPR configuration before you rely on this path.

## Option 2: An admin resets the password

Prerequisite: at least the **Password Administrator** role. Other roles can reset passwords for a limited set of users.

1. Sign in to the Microsoft Entra admin center as at least a Password Administrator.
2. Browse to **Entra ID** > **Users**.
3. Select the user, then **Reset password**.
4. On the **Reset password** page, select **Reset password** again.
5. Copy the password and give it to the user. The user must change it during the next sign-in.

Learn adds details:

- For Microsoft Entra ID, a temporary password is autogenerated. With on-premises Active Directory, you create the password.
- The temporary password never expires. It still works at the next sign-in no matter how much time has passed.
- You cannot reset passwords for users whose home directory is another tenant, a Microsoft account or a Google account.
- For users with Windows Server Active Directory as source of authority, you can only reset the password if password writeback is turned on and the domain is managed. For federated domains, changing the user password is not supported, so change it in on-premises Active Directory.
- For users whose source of authority is External Microsoft Entra ID, you cannot reset the password. Only the user, or an admin in that tenant, can.
- If an admin cannot reset a password and the Application Event Log on the Microsoft Entra Connect server shows error code `hr=80231367`, Learn says to check the user's attributes in Active Directory. If **AdminCount** is 1, an administrator cannot reset the password, and it must be 0.

## Check why passwords expire

The SSPR policy page explains the Microsoft Entra defaults:

| Setting | Documented default |
| --- | --- |
| Password expiry duration (maximum password age) | No expiration. A tenant created before 2021 has a 90 day expiration value by default |
| Let passwords never expire | false, meaning passwords have an expiration date |

Commands from Learn, run after connecting Microsoft Graph PowerShell as at least a User Administrator:

```powershell
Get-MgDomain
Get-MgUser -UserId <user ID> -Property UserPrincipalName, PasswordPolicies | Select-Object @{N="PasswordNeverExpires";E={$_.PasswordPolicies -contains "DisablePasswordExpiration"}}
```

The first checks the domain policy. Learn names `Update-MgDomain` to change the value. The second shows whether a single user's password is set to never expire. To set one user to never expire, use `Update-MgUser -UserId <user ID> -PasswordPolicies DisablePasswordExpiration`. To make it expire again, use `-PasswordPolicies None`.

Warning from Learn: passwords set to DisablePasswordExpiration still age based on the `LastPasswordChangeDateTime` attribute. If you change the setting back to `None`, every password with a `LastPasswordChangeDateTime` older than 90 days must be changed at the next sign-in. That can affect many users at once.

Learn also says by default only passwords of accounts not synchronized through Microsoft Entra Connect can be configured to not expire. Password expiration is the only part of the password policy that can be changed.

Whether to turn expiry off is a policy decision for your organization. I make no recommendation here.

## Expired password versus other password errors

The reference lists neighbors that look similar:

- **AADSTS50144:** the user's Active Directory password has expired. The reference says to generate a new password for the user or have the user use the self-service reset tool.
- **AADSTS50133 and AADSTS50132:** the session is not valid because of password expiration or a recent password change.
- **AADSTS50053:** the account is locked after too many attempts, which is a different cause.

Pick the code from the sign-in log, not from the text the user saw.

## Find the event in the sign-in logs

The reference's pattern for other codes, such as AADSTS50053, is to use **Monitoring & health** > **Sign-in logs** in the Microsoft Entra admin center and look at the **Sign-in error code** and failure reason. The same place helps here, to confirm the code is 50055 and see which application the user used.

## A short checklist (my advice)

This list is my suggestion, not a Microsoft procedure:

1. Confirm the code in the sign-in log. If it says 50144, the on-premises password expired instead.
2. Check whether the user is cloud-only, synced or federated. That decides where the reset happens.
3. If an admin reset is needed, use the portal steps above and tell the user to expect a forced change.
4. If it affects many users, check the domain policy and the per-user `DisablePasswordExpiration` value before changing anything.
