AB-400 is the exam for the Power Platform Developer Associate certification, and it replaced PL-400. The AB-400 exam page says that on October 16, 2026 registration for PL-400 closed and registration opened exclusively for AB-400, and that learners who registered for PL-400 by then could schedule and take it through October 30, 2026. Both dates are now past, and the PL-400 exam page says the exam was retired on October 30, 2026, so PL-400 can no longer be taken. This article covers only the skills measured, from Microsoft's exam page and study guide, and no exam questions.

## Exam status

- Exam page title: AB-400: Power Platform Developer Associate. The study guide title is Exam AB-400: Extending Microsoft Power Platform Solutions with Code and AI.
- The exam is part of the requirements for Microsoft Certified: Power Platform Developer Associate.
- Language listed: English. The page shows a retirement date of none.
- The study guide says a score of 700 or greater is required to pass. It also says associate certifications expire annually and can be renewed by passing a free online assessment on Microsoft Learn.
- Learning paths and modules are listed as not yet available, with no instructor-led courses currently available.

## Who the exam is for

The audience profile says candidates design, develop, test and troubleshoot solution components by using the extension points of Power Platform and generative AI. They implement custom user experiences and business logic, system integrations, data conversions, custom process automation, Power Automate workflow expressions, and agentic AI as part of solution logic. Expected knowledge includes Power Platform services and their boundaries, authentication, security and ALM, developer tools including Power Platform CLI, AI-assisted tools and agents, and IDEs such as Visual Studio and Visual Studio Code. Development experience is listed in JavaScript, JSON, TypeScript and Power Fx, C#, Python, HTML and YAML, RESTful web APIs, Azure, Microsoft Foundry and Copilot Studio.

## Skills at a glance

| Area | Weight |
| --- | --- |
| Build Microsoft Power Platform solutions | 15-20% |
| Extend the user experience | 25-30% |
| Extend Microsoft Power Platform | 35-40% |
| Develop integrations | 10-15% |

The study guide notes that the bullets under each skill illustrate how the skill is assessed and that related topics may be covered. Most questions cover generally available features, and the exam may include preview features if they are commonly used.

## Build Microsoft Power Platform solutions (15-20%)

- **Design the technical architecture:** analyze architecture and components, design authentication and authorization, decide whether out-of-the-box functionality meets requirements, decide where business logic lives (cloud services, client-side processing, business rules, plug-ins, automation), choose standard, virtual or elastic tables or connectors, assess the impact of security features (managed environments, data policies, security roles, teams, business units, row sharing), choose between deterministic and non-deterministic logic, decide when to use code apps, generative pages, PCF, web resources, interactive agents and MCP app widgets, and decide between Microsoft Foundry and Copilot Studio for agents.
- **Design solution components:** reusable Power Apps components, custom connectors and MCP servers, Dataverse plug-ins and custom APIs, automations, inbound and outbound integrations, code apps, custom agents, and monitoring and alerting.
- **Implement ALM:** solution dependencies, environment variables, solution layers, Power Platform Pipelines, and CI/CD with Power Platform Build Tools.

## Extend the user experience (25-30%)

- **Client scripting in model-driven apps:** Client API object model, event handler registration, the Dataverse Web API from client scripts, commands and buttons with Power Fx and JavaScript, and navigation, dialogs and notifications.
- **PCF code components:** lifecycle events, the manifest, component interfaces, packaging, deploying and consuming, and Device, Utility and Web API features.
- **Build Power Apps code apps:** Power Platform connections, Dataverse tables, table and metadata operations, actions and functions, Power Automate cloud flows, Copilot Studio agents and environment variables.
- **Deploy and manage code apps:** Content Security Policy settings, monitoring with Azure Application Insights, packaging, deploying and sharing, troubleshooting with Monitor and browser tools, and performance optimization.

## Extend Microsoft Power Platform (35-40%)

- **Dataverse plug-ins:** event execution pipeline stages, execution context, business logic, images, the Organization service, performance, custom API messages, the Plug-in Registration Tool, plug-ins that implement a custom API, business events and managed identity for plug-ins.
- **Platform APIs:** the Dataverse Web API and Organization service, API limit retry policies, performance, concurrency, transactions and bulk operations, OAuth authentication and troubleshooting, background operations, and the Dataverse SDKs for .NET and Python.
- **Azure Functions workloads:** long-running operations, scheduled and event-driven triggers, and managed identities.
- **Cloud flows and Copilot Studio workflows:** complex expressions, flow control and error handling, trigger filter and retry policies, child flows, and service principals for the Dataverse connector.
- **Microsoft Foundry agents:** integrating custom agents through Power Platform MCP servers, connecting to Copilot Studio agents, using Dataverse data through Work IQ, and the Copilot Studio client library.

## Develop integrations (10-15%)

- **Publish and consume Dataverse events:** the `IServiceEndpointNotificationService`, the Plug-in Registration Tool, service endpoints (webhooks, Azure Service Bus, Azure Event Hub), and options for listening to events.
- **Synchronize Dataverse data:** change tracking, alternate keys and the `UpsertRequest` message.
- **Custom connectors:** authentication, policy templates, importing definitions (OpenAPI, Azure services, GitHub), a connector for an Azure service, an Azure Function for a connector, extending the OpenAPI definition and transforming data in code.

## What changed from PL-400

The old PL-400 exam page listed six assessed areas: create a technical design (10-15%), configure Microsoft Dataverse (15-20%), create and configure Power Apps (10-15%), extend the user experience (10-15%), extend the platform (35-40%) and develop integrations (5-10%). AB-400 has four areas, and its outline adds areas for building Power Apps code apps, deploying and managing code apps, and building Microsoft Foundry agents with code that integrates with Power Platform. The study guide as published now has no change log table, so this article does not compare individual objectives.

## How to use the outline

This section is my advice, not a Microsoft statement.

1. **Weight your time by the percentages.** The extend area is up to 40 percent, so plug-ins and platform APIs repay the most practice.
2. **Treat the new areas as new.** If you prepared for PL-400 before, code apps and Foundry agents are the areas where old material helps least.
3. **Practice with real components.** Build a plug-in, a PCF component and a custom connector in a trial environment, since the outline is made of tasks.
4. **Read the study guide itself** for the exact wording of each bullet and for updates, since this article summarises it.
5. **Check the exam page before booking** for current language, price and learning resources, because those change.
