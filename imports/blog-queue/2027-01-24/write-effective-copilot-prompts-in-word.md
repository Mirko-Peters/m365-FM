Copilot in Word follows the instructions in your prompt, so the quality of the prompt decides much of the result. The Microsoft Support page "Write effective prompts for Copilot in Word" is short. It applies to Word for Microsoft 365 and Word for Microsoft 365 for Mac. This article restates its guidance, groups its examples, and adds a few working habits that are clearly marked as my own.

## The core rule

For the best results, describe the outcome you want clearly. The page lists what to include in a prompt:

The right column below is my plain-language gloss, not the page's wording.

| Element | What it means |
| --- | --- |
| Audience | Who will read the document |
| Purpose | What the document should achieve |
| Source material | Files, notes or outlines Copilot should use |
| Format | Document type and structure |
| Tone | For example warmer, or executive-ready |
| Length | For example half as long |
| Constraints | Anything Copilot must follow or avoid |

## Example prompts by task

The page groups examples into five categories.

### Create content

Give the document type and the structure you want.

- Draft a customer brief with background, benefits, risks, and next steps.

### Edit content

Describe the specific change.

- Make the introduction concise and executive-ready without changing the meaning.

### Reuse an existing document

Reuse a template or a document and update only its contents.

- Fill out an invoice using information from a purchase order PDF.
- Update a regulatory approval package using the latest trial manufacturing data.

### Use work context

Copilot can pull relevant context from files, emails, meetings and notes, based on your prompt.

- Summarize the team's priorities.
- Create a section based on a named file.

### Refine a result

Use short, targeted follow-ups.

- Shorten this by half.
- Use a warmer tone.
- Visualize this table as an infographic.

## Tips from the page

1. Include audience, purpose, tone, format and length.
2. Provide context such as outlines, notes or source files.
3. Ask for one clear outcome or one precise edit.
4. Refine with follow-up prompts instead of starting over.
5. Review the generated content for accuracy, completeness, tone, style and safety before you share it.

## Licensing and availability

Other Microsoft Support pages for Copilot say that Copilot may not be included in your Microsoft 365 subscription, or may be restricted by organization settings. My advice: if the Copilot button is missing in Word, check with your administrator.

## Prompt patterns (my advice)

This is my suggestion, not guidance from the page. A prompt built from the elements above can follow a simple pattern:

1. **Task:** what Copilot should produce or change.
2. **Reader and purpose:** who reads it, and what they should do afterward.
3. **Sources:** which file or notes to use, named as in your library.
4. **Shape:** format, tone, length.
5. **Limits:** what to keep unchanged, or what to leave out.

Example in that pattern, written for illustration:

> Draft a one-page project status update for the steering committee. Use the notes in the file named Project notes. Keep it neutral, with three headings, under 300 words. Do not include budget figures.

Some habits that help in practice:

- Start with a short first prompt and improve in steps. Changing one thing at a time makes it easy to see what helped.
- When editing, state what must stay the same. The page's own edit example does this with without changing the meaning.
- Keep a list of prompts that worked for your team in a shared note, and reuse them. If you repeat the same instructions often, a custom skill may fit better. Other Microsoft pages describe skills for Copilot.
- Check facts, numbers and names in the output against the source. The page reminds you to review for accuracy and completeness.
- For documents with sensitive content, follow your organization's rules on what you may share with Copilot.
