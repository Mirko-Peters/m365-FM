Microsoft Learn describes exports from Dynamics 365 Customer Insights - Data to Azure Synapse Analytics and to Azure Data Lake Storage Gen2. It does not describe a direct export of unified segments into Azure Data Factory. The practical route the documentation supports is to land segment-related tables in a lake or in Dataverse, and then let Data Factory or Synapse pipelines read from there. This article covers what the documentation says about each path and marks where the pages stop.

## The two export types

Learn's exports overview names two main types:

- **Segment exports** export segment tables. Segments are lists of customer profiles built on the unified customer profile table. You choose the data fields for each export. A common use case is sharing customer lists with advertising services. Limits include third-party limits on the number of profiles, and the fact that only fields of the Customer profile table are available. Projected attributes from other tables are not available for export even if you used them to build the segment.
- **Data-out exports** export any table available in Customer Insights - Data, with all fields, metadata, schemas and mapping details. A common use case is sharing data to Azure Data Lake Gen2 for further processing.

For data-out scenarios, Learn recommends Dataverse data sharing features instead: Power BI with Dataverse data, or the Dataverse link to Fabric and OneLake. It also recommends **Azure Synapse Link for Dataverse**, which it describes as a generally available service for continuous replication of Dataverse data to Azure Data Lake, for these tables generated by Customer Insights:

- Unified customer profiles (`msdynci_customerprofile`)
- Unified activities (`msdynci_unifiedactivity`)
- Segment membership (`msdynci_segmentmembership`)
- Customer attribute measures (`msdynci_customermeasure`)
- Enrichment data (`msdynci_enrichment`)
- Prediction model output (`msdynci_prediction`)

For a pipeline that needs segment members, the segment membership table is therefore the documented source to replicate.

## The Azure Synapse export

If you still want the Customer Insights export, Learn documents it as follows.

### Prerequisites

- An Administrator role in Customer Insights - Data.
- An active Azure subscription.
- A user with User Access Administrator (or Owner) in the subscription to grant the service principal access, unless an Azure user with that role sets the permissions.
- For a new Data Lake Storage Gen2 account, the Customer Insights service principal needs Storage Blob Data Contributor, and the account must have hierarchical namespace enabled.
- At least Reader on the resource group with the Synapse workspace for the service principal and the admin user.
- Storage Blob Data Contributor on the Data Lake account linked to the workspace for the admin user and the Synapse workspace managed identity.
- The Synapse Administrator role for the Customer Insights service principal on the workspace.

### Known limitations from the page

- No incremental refresh for data sources if the environment uses a custom Azure Data Lake for storage.
- Power Query data sources as input tables are supported only if the environment stores data in your own Azure Data Lake Storage.
- Private Link is supported only if public access to the storage account is disabled.
- The export works only for CSV formatted files.

### Set up the connection

1. Go to **Settings** > **Connections**.
2. Select **Add connection** and choose **Azure Synapse Analytics**.
3. Enter a **Display name**.
4. Choose who can use the connection. By default only administrators can.
5. Select the subscription, then the **Workspace**, **Storage account** and **Container**.
6. Optionally select **Enable Private Link** if the storage account is behind a firewall.
7. Review the data privacy and compliance text, select **I agree** and **Save**.

### Configure the export

1. Go to **Data** > **Exports** and select **Add export**.
2. In **Connection for export**, choose the Azure Synapse Analytics connection.
3. Enter a **Display name** and a **Database name**. The export creates a new Synapse lake database in the workspace.
4. Select the tables to export. Data sources based on a Common Data Model folder are not supported.
5. Select **Save**.

Saving does not run the export. It runs with every scheduled refresh, and you can run it on demand. To query data in Synapse, you need Storage Blob Data Reader on the destination storage.

When you update an export, removed tables stay in the Synapse database but stop being refreshed, and changing the database name creates a new database while the old one stops receiving updates.

## Where Data Factory fits

The pages read do not describe a Data Factory sink for Customer Insights, a pipeline template or a trigger that fires when a segment refreshes. Based on the documented pieces, one workable design is the author's suggestion rather than a Learn procedure:

1. Replicate `msdynci_segmentmembership` with Azure Synapse Link for Dataverse, or export tables to the lake with the Synapse or Data Lake export.
2. Read the lake files or Dataverse tables from your own pipeline.
3. Schedule the pipeline after the Customer Insights refresh.

Check the Data Factory side in Data Factory documentation, which was not read for this article.

## Segment export limits to remember

Learn's general limitations for export connectors apply to segment exports to external systems: maximum segment size, required fields such as email address, API rate limits, data format requirements such as hashed emails, and regional availability. If an export fails, check the export run details for the error from the connector.

## What the documentation does not say

The pages read do not state how often segment membership is refreshed in Dataverse, how large a segment can be for the Synapse export, or how to filter a single segment during a data-out export. If you need one segment only, filter the segment membership table downstream.
