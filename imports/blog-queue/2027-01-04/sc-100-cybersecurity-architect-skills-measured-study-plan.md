The SC-100 study guide lists four skill areas. Two of them, security operations with identity and compliance, and infrastructure security, carry 25-30% each. Plan your time by those weights and by your own experience. This guide uses only the Microsoft Learn skills outline, valid as of 21 October 2026, and contains no exam questions.

## Audience profile

Learn describes the candidate as someone who translates cybersecurity strategy into capabilities that protect assets, business and operations. They design, guide the implementation of and maintain security solutions that follow Zero Trust principles across identity, devices, data, AI, applications, network, infrastructure and DevOps. They also design governance, risk and compliance, security operations and security posture management solutions.

Candidates have experience with identity and access, platform protection, security operations, data and AI security, application security, and hybrid and multicloud infrastructure. Learn says they have expert skills in at least one area and experience designing with Microsoft security technologies.

## Skill areas and weights

| Skill area | Weight |
| --- | --- |
| 1. Design solutions that align with security best practices and priorities | 20-25% |
| 2. Design security operations, identity and compliance capabilities | 25-30% |
| 3. Design security solutions for infrastructure | 25-30% |
| 4. Design security solutions for applications and data | 20-25% |

## Area 1: security best practices and priorities (20-25%)

- **Resiliency for ransomware and other attacks:** business resiliency strategy, BCDR including secure backup and restore for hybrid and multicloud, ransomware mitigation with privileged access, and security update solutions.
- **MCRA and the Microsoft Cloud Security Benchmark:** controls, defense against insider, external and supply chain attacks, AI solutions aligned to the benchmark, and the Zero Trust adoption framework.
- **Cloud Adoption Framework and Well-Architected Framework:** secure AI adoption, security and governance strategies, Azure landing zones, and a DevSecOps process.

## Area 2: operations, identity and compliance (25-30%)

- **Security operations:** detection and response with XDR and SIEM, centralized logging including Microsoft Purview Audit, hybrid and multicloud monitoring, SOAR with Microsoft Sentinel and Defender XDR, incident response and threat hunting, and MITRE ATT&CK coverage.
- **Identity and access management:** agent identities with Microsoft Entra Agent ID and Conditional Access, access to SaaS, PaaS, IaaS, hybrid and multicloud resources, Entra ID solutions, external identity, modern authentication and authorization, Conditional Access alignment with Zero Trust, AD DS hardening, and secrets, keys and certificates.
- **Privileged access:** the enterprise access model, PIM, entitlement management and access reviews, AD DS resilience, secure administration of cloud tenants, cloud infrastructure entitlement management, and secure privileged workstations.
- **Regulatory compliance:** translating requirements into controls, Microsoft Purview, Azure Policy, and Defender for Cloud regulatory alignment.

## Area 3: infrastructure (25-30%)

- **Posture management:** Defender for Cloud and the benchmark, Secure Score, hybrid and multicloud integration, workload protection, Azure Arc, Defender EASM and Microsoft Security Exposure Management.
- **Server and client endpoints:** server and mobile requirements, IoT and embedded systems, OT and ICS with Defender for IoT, baselines, and Windows LAPS.
- **SaaS, PaaS and IaaS:** baselines, IoT and web workloads, containers and orchestration, and Azure AI services security.
- **Network security and SSE:** network design, Microsoft Entra Internet Access as a secure web gateway, including for Microsoft services and cross-tenant configurations, and Microsoft Entra Private Access.

## Area 4: applications and data (20-25%)

- **Securing Microsoft 365:** posture metrics including Secure Score, Defender for Office 365 and Defender for Cloud Apps, Intune device management, Purview data security, and data security in Microsoft 365 Copilot.
- **Securing applications:** application portfolio posture, threat modeling, lifecycle security, secure development, workload identity, API management and Azure Web Application Firewall.
- **Securing data:** discovery and classification, mitigation priorities, encryption including Key Vault, data in AI workloads, data in Azure SQL, Synapse and Cosmos DB, Azure Storage, and Defender for Storage and Databases.

## What changed on 21 October 2026

The change log lists two minor changes: Design solutions for security operations, and Evaluate solutions for securing Microsoft 365. The audience profile and the other groups are unchanged. The page does not say which wording changed.

## A study plan based on the weights

The plan is advice derived from the weights, not an official plan. Adjust it to your background.

1. Start with the Zero Trust and Cloud Security Benchmark ideas in area 1, because they frame the other areas.
2. Give the most time to areas 2 and 3. Together they make up 50-60% of the outline.
3. Within area 2, practice design decisions. Compare options for detection, identity and privileged access instead of memorizing product screens.
4. Within area 3, learn what each Defender and Entra service covers and where they overlap.
5. In area 4, focus on data protection and application security trade-offs.
6. Use the new Practice Assessment on AI Skills Navigator that the study guide recommends.
7. Revisit the study guide shortly before your exam date, because the skills measured can change.

## Before you book

The study guide has no retirement notice. The exam page and the certification page show current status and exam details. Check them yourself, because this guide does not cover cost, duration or passing score.
