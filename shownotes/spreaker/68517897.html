Copilot Studio agents sound confident but cannot see the customer and order data that lives in on-prem SQL Server. This episode shows Power Platform makers and architects how to connect SQL through the on-premises data gateway as a knowledge source and with write-back actions, without opening the firewall or moving the data.

In this episode

  • 00:00 – A fluent but clueless copilot
  • 00:47 – Why copilots fail without context
  • 03:16 – The data gateway as the spine of hybrid AI
  • 07:28 – Adding SQL as a knowledge source
  • 11:55 – SQL actions and write-backs
  • 16:42 – Hybrid architecture and scaling
  • 20:09 – The real secret: architecture

Key takeaways

  • The on-premises data gateway lets Copilot Studio query and update on-prem SQL Server through outbound-only, encrypted connections without copying the database to the cloud.
  • Expose only well-named, read-optimized views as knowledge sources and clearly labeled parameters for SQL actions, so the agent queries precisely and asks for missing inputs.
  • Use gateway clusters for resilience, separate read and write credentials, and export Power Platform telemetry for auditing.

Worth quoting

“Directly exposing SQL data to the cloud is corporate self-harm. Firewalls, network zones, and authentication boundaries exist precisely because someone once tried just opening a port and spent the next quarter explaining the breach.” – Mirko Peters (02:04)

“The gateway maintains sovereignty by initiating every conversation outward, picture it like an employee who only makes phone calls. They never accept incoming ones.” – Mirko Peters (03:48)
