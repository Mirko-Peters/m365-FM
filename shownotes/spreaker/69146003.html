Microsoft Foundry makes it easy to build agents that run on schedules and events with no human in the loop, which is how shadow IT turns autonomous. This episode is for identity, compliance and platform governance owners who need to control Foundry before the first incident. You get three failure modes, an agent control plane built on identity, Purview labels and observability, and a week-one checklist.

In this episode

  • 00:00 – Foundry as an agent factory
  • 03:54 – How Microsoft platforms created shadow IT
  • 08:10 – Failure mode 1: agent identity collapse
  • 12:54 – Failure mode 2: permission drift
  • 17:56 – Failure mode 3: data boundary collapse
  • 27:12 – Designing an agent control plane
  • 36:50 – Observability and pre-execution gates
  • 45:27 – Week one checklist and outlook

Key takeaways

  • Foundry agents are autonomous workloads under non-human identities, so every agent needs a dedicated workload identity with an owner, a purpose, an expiry and a shutdown trigger.
  • Shared service principals and convenience exceptions cause permission drift, and per-system Purview and DLP rules miss data combinations an agent assembles across systems.
  • Governance must act before execution: no owner, no label and no audit path means no production deployment for an agent.

Worth quoting
