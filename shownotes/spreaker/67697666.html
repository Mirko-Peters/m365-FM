DevOps teams lose hours to setup work, configuration drift and bugs that only show up in production. This episode is for .NET and Azure developers and engineering leads, explaining how agentic AI moves from autocomplete to a teammate that scaffolds, provisions, tests and remembers lessons, while humans keep control through guardrails.

In this episode

  • 00:00 – What makes agentic AI different
  • 04:34 – Reimagining the .NET developer workflow
  • 08:29 – Cloud agents running Azure on autopilot
  • 13:03 – Autonomous testing: bugs humans miss
  • 16:58 – Closing the intelligence loop in DevOps
  • 21:32 – Where to start

Key takeaways

  • Agentic AI differs from autocomplete because agents keep context, memory and goals, coordinate in specialised roles and adapt when conditions change.
  • In .NET and Azure work, agents can scaffold projects, provision infrastructure, detect drift and generate edge-case tests, but only within guardrails that humans define and review.
  • Start small with one measurable pilot, such as Copilot on a prototype or a test agent against staging, and feed lessons from logs and pull requests back into the next project.

Worth quoting

“Automation has long existed in development, think scripts, CICD, pipelines, and templates. These are rigid by design. They follow exact instructions step by step, but they break when conditions shift unexpectedly.” – Mirko Peters (02:32)
