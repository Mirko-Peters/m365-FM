IT admins lose hours every week starting VMs, patching servers and running scripts by hand, and every manual step invites errors. This episode explains Azure Automation in plain English for admins and cloud beginners. You will learn how runbooks, schedules, hybrid workers, state configuration and managed identities work together, with a simple start/stop VM scenario that saves money.

In this episode

  • 00:00 – Why automate repetitive IT work
  • 02:35 – Runbooks: the heart of automation
  • 04:07 – Schedules, alerts and webhooks
  • 05:51 – Hybrid Runbook Workers
  • 07:49 – State configuration
  • 09:39 – Shared resources
  • 11:24 – Managed identities
  • 13:32 – Start/stop VM scenario

Key takeaways

  • Azure Automation centralizes scripts as runbooks in an Automation account and runs them on schedules, from alerts or via webhooks.
  • Hybrid Runbook Workers extend automation to on-premises machines, and State Configuration keeps servers in their desired state.
  • Store secrets as shared resources and authenticate with managed identities instead of hard-coded passwords, then start by automating one repetitive task such as a nightly VM shutdown.

Worth quoting

“A runbook is just a script. Usually PowerShell, sometimes Python, that's it. There's no magic here. You write the steps you want to follow and Azure Automation follows them exactly every time.” – Mirko Peters (02:37)

“But that's not automation. That's just running a script manually from a web page. Real automation needs a trigger, something that tells your runbook when to run without you touching anything.” – Mirko Peters (04:17)
