Phishing, credential stuffing and endless password resets keep draining security teams and help desks. This episode is for developers and IT leaders who want to replace passwords with passkeys and WebAuthn in ASP.NET Core and Microsoft 365 environments. You get a clear implementation checklist, a better user experience and a pilot plan to measure real ROI.

In this episode

  • 00:00 – Why passwords fail by design
  • 00:41 – The real cost of broken passwords
  • 04:41 – Meet passkeys and WebAuthn
  • 08:50 – Building passkeys into ASP.NET Core
  • 13:30 – The user experience shift
  • 17:24 – Business benefits and ROI
  • 20:30 – Running a passkey pilot

Key takeaways

  • Passwords fail because the model itself is outdated, so stricter policies and rotations cannot fix phishing, credential reuse or reset overhead.
  • Passkeys built on WebAuthn keep the private key on the user's device and store only public keys on the server, which removes stolen credentials as an attack surface.
  • ASP.NET Core teams can add passkey registration and login endpoints with existing libraries, then prove the value with a small pilot that measures reset tickets and incidents.

Worth quoting

“The problem lies in the model. Passwords were designed decades ago, an era of local systems and small networks. Today's Internet operates on a scale that relies on global connectivity, distributed apps, and millions of identities.” – Mirko Peters (03:37)

“Passkeys are powered by public key cryptography. The private key stays on the user's device, while the server only holds a public key. That means nothing sensitive ever travels across the network or has to sit in a database waiting to be stolen.” – Mirko Peters (05:11)
