Building a Power App straight from Excel feels fast, but it carries missing keys, mixed types and fake relationships into Dataverse. This episode walks makers and Power Platform teams through five failure patterns and a step-by-step remediation path. You learn how keys, types and relationships turn a fragile spreadsheet into a reliable data model.

In this episode

  • 00:00 – Excel is not a database
  • 00:37 – Failure 1: No primary keys
  • 04:47 – Failure 2: Mixed data types
  • 09:03 – Failure 3: Lookups as joins
  • 12:55 – Failure 4: Multipurpose columns
  • 17:06 – Failure 5: Orphan rows
  • 21:48 – Excel vs Dataverse benchmarks
  • 23:15 – Minimal remediation path

Key takeaways

  • Keep the Dataverse GUID as primary key and define alternate keys on business fields so imports can resolve and upsert rows reliably.
  • Declare explicit data types and clean data in Power Query before import instead of trusting Excel formatting.
  • Replace repeated text with lookups to parent tables, load parents first and make critical relationships required to prevent orphans.

Worth quoting

“Without primary keys, Dataverse can't guarantee row level integrity. It can't tell whether an incoming row should insert or update.” – Mirko Peters (00:58)

“Identity is not a column, it's a contract. The simple version is use surrogate keys for truth, alternate keys for convenience.” – Mirko Peters (01:14)
