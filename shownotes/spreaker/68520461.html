DAX user-defined functions can return numbers that look right but are silently wrong when VAL and EXPR parameter modes are mixed up. This episode is for Power BI and Fabric modelers writing reusable DAX. It explains parameter modes, context transition, materialization with ADDCOLUMNS and type casting, with a checklist for UDFs you can trust.

In this episode

  • 00:00 – Why VAL vs EXPR matters in DAX UDFs
  • 00:34 – The two parameter modes: VAL and EXPR
  • 05:20 – The context transition trap
  • 08:20 – Materialize once with ADDCOLUMNS
  • 12:37 – Parameter types and silent casting
  • 16:01 – Authoring checklist for reliable UDFs
  • 20:01 – Walkthrough from wrong to right

Key takeaways

  • Use VAL for fixed scalars evaluated once in the caller's context and EXPR for formulas that must re-evaluate under the filters and iterators inside the function.
  • An EXPR parameter does not get context transition automatically, so wrap every evaluation of it in CALCULATE inside the UDF instead of relying on callers.
  • When an EXPR is used more than once, materialize it once per entity with ADDCOLUMNS and reuse the column, and choose parameter types that match the math to avoid silent truncation.

Worth quoting

“In DAX UDFs, the parameter passing mode is not decoration. It's semantics. It changes when evaluation happens, which changes what result you get.” – Mirko Peters (00:42)

“Passing an expression does not automatically give you context transition. The measures get an implicit calculate when used inside a row context, row expressions do not.” – Mirko Peters (04:00)
