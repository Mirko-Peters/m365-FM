Most organizations think they have AI agents, but what they really have are chatbots that forget everything when the window closes. This episode is for architects and IT leaders planning enterprise agents on the Microsoft stack. It lays out the agent fabric blueprint, from GitHub Copilot SDK session persistence to Entra Agent IDs, orchestration, cost routing and Agent 365 governance.

Key takeaways

  • Enterprise agents fail not because models are weak but because they are built as stateless, siloed chat interfaces instead of persistent system participants.
  • A working agent fabric needs session persistence, a shared backend with thin clients, a dedicated Entra Agent ID per agent, explicit orchestration and model routing to control cost.
  • Persistent memory and agent-to-agent calls create new risks such as memory poisoning and data leakage, which require Agent 365 governance, DLP by design, sandboxing and causal observability.

Worth quoting

“Chat is stateless by design. Every turn is independent. You ask, it responds done. But agents don't work that way. Agents require state. They need memory across sessions.” – Mirko Peters (01:47)
