SharePoint libraries full of final-final copies make search and Copilot pick the wrong document. This episode gives SharePoint admins and developers an architecture that quarantines clutter in Azure Blob Storage without breaking collaboration. You learn the permission model security will approve and a rollout playbook with reversible, auditable moves.

In this episode

  • 00:00 – Confident search, wrong answers
  • 00:34 – Why hoarding breaks search and governance
  • 04:47 – Architecture: SPFx, Blob, Function, Table
  • 09:43 – The admin-safe OBO permission model
  • 12:49 – Playbook: identify, offload, restore
  • 17:01 – Payoff for search, Copilot and compliance
  • 19:15 – Minimum viable rollout

Key takeaways

  • Duplicate and stale files dilute search ranking signals, so search and Copilot surface the wrong version with confidence.
  • Move clutter to tiered Azure Blob Storage through an SPFx command and an Azure Function, keep a ledger in Table Storage and make restore one click.
  • Use delegated permissions with the on-behalf-of flow and refuse items on hold so security and compliance can approve the solution.

Worth quoting

“Search isn't a librarian, it's a ranking engine. When you scatter duplicates and near duplicates across libraries and sites, you dilute signals, title, body, click history, links.” – Mirko Peters (00:57)

“Users aren't lazy, they're risk averse. Delete feels irreversible, so they create shadow copies, label them, final some date, and swear they'll tidy later.” – Mirko Peters (02:32)
