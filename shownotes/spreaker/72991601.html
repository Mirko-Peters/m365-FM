Every new Azure region in a hub-and-spoke design means more peerings, route tables and firewall rules to maintain by hand. This episode explains Azure Virtual WAN in plain English for cloud and network engineers who need global connectivity. You learn how virtual hubs, VPN, ExpressRoute and routing intent work, and when classic hub-and-spoke is still the better choice.

In this episode

  • 00:00 – Why global Azure networking gets complicated
  • 00:54 – The old way: hub-and-spoke complexity
  • 02:27 – What Azure Virtual WAN actually is
  • 03:58 – The virtual hub as on-ramp
  • 05:30 – Connecting branches, users and cloud resources
  • 07:51 – Routing and security built in
  • 09:41 – Virtual WAN vs. hub-and-spoke
  • 11:38 – Real-world scenarios and getting started

Key takeaways

  • Traditional hub-and-spoke works well in a single region but its peerings and route tables multiply with every new region.
  • Azure Virtual WAN uses Microsoft-managed virtual hubs that route automatically between VNets, branches, remote users and other regions over the Microsoft backbone.
  • Routing intent with a secured virtual hub sends all traffic through the firewall with one setting instead of hundreds of user-defined routes.

Worth quoting
