Front ends can now be built in an afternoon, but the backend behind them still takes weeks of custom API plumbing. This episode explains for architects and platform teams how Microsoft Rayfin turns the backend into governed code inside Microsoft Fabric, why that matters for AI agents, and how to migrate away from custom APIs step by step.

In this episode

  • 00:00 – The middleware crisis
  • 01:14 – Why custom APIs became a liability
  • 07:26 – The agentic AI catalyst
  • 10:33 – What Rayfin actually is
  • 17:24 – Code-first governance
  • 20:51 – Strangler fig and anti-corruption layer
  • 32:53 – HorizonDB, observability and security
  • 39:29 – Organization, cost and migration

Key takeaways

  • Fragmented custom APIs scatter authentication, monitoring and governance across many systems, which makes them a growing liability, especially for AI agents.
  • Rayfin defines the whole backend in code, deploys it into Microsoft Fabric and enforces access policies, masking and audit trails by default.
  • Adopt it gradually with a pilot domain, a facade and an anti-corruption layer, backed by templates, a governance library and a governance board.

Worth quoting

“If your first API uses OAuth and your second uses API keys, you haven't gained flexibility. You have created inconsistency, and that inconsistency is a massive security liability.” – Mirko Peters (02:23)
