Works on my machine tickets, slow onboarding and broken Azure builds usually come from environment drift. This episode shows developers and DevOps teams how dev containers, templates, features and prebuilt images give every laptop and CI pipeline the same reliable toolchain.

In this episode

  • 00:00 – Why consistent dev environments matter
  • 00:50 – Environment drift and local installs
  • 04:00 – Templates as pre-built classes
  • 07:13 – Features as modular upgrades
  • 11:31 – Prebuilding images for fast starts
  • 15:16 – Securing credentials and workspace trust
  • 18:35 – Wrap-up

Key takeaways

  • A shared devcontainer.json makes laptops, VS Code and CI pipelines run identical runtimes and tools, eliminating environment drift.
  • Templates and features turn setup into a declarative, reusable contract, and prebuilt images pushed to a registry remove slow startups.
  • Workspace trust, mounted SSH credentials and dotfiles keep dev containers secure without baking secrets into images.

Worth quoting

“The root cause is local installs. Everyone outfits their laptop with a personal stack of SDKs and CLIs, then crosses their fingers that nothing conflicts.” – Mirko Peters (01:07)

“They burn days installing run times, patching modules, and hunting missing dependencies before they can write a single line of useful code. That wasted time isn't laziness. It's the tax of unmanaged drift.” – Mirko Peters (01:43)
