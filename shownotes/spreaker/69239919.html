Microsoft Fabric did not make SQL optional; it moved T-SQL to where cost overruns, audit findings and performance incidents begin. This episode is for data engineers and platform architects running modern Microsoft data platforms. It shows how to use T-SQL to enforce shape, access and cost so the platform stays deterministic instead of drifting into entropy.

In this episode

  • 00:00 – Beyond SELECT means responsibility
  • 03:53 – Execution order and plans
  • 10:41 – Lakehouse inputs as warehouse liabilities
  • 14:42 – Parameter sniffing and cost spikes
  • 18:52 – Security and least privilege
  • 26:42 – Business logic drift
  • 30:47 – Indexing, partitioning and redesign
  • 45:18 – AI-written SQL and the operating model

Key takeaways

  • Treat the Fabric warehouse as an enforced boundary with explicit schemas, constraints and validation gates instead of fixing bad data downstream in Power BI.
  • Use execution plans as acceptance criteria and manage parameter sniffing, statistics, indexing and partitioning to keep cost and performance predictable.
  • Encode least privilege and business logic in schemas, roles, views and stored procedures, and let AI draft queries only while humans enforce shape, access and cost.
