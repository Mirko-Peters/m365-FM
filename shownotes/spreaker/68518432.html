Slow Power BI refreshes and failing flows are often caused by an on-premises data gateway left on safe-but-slow defaults. This episode is for Power Platform and Power BI admins who want to tune concurrency and buffers, fix network routing, size and cluster the gateway host, and keep it healthy with proactive maintenance.

In this episode

  • 00:00 – Why the gateway is your bottleneck
  • 01:31 – What the gateway actually does
  • 04:14 – Default settings: the hidden performance killers
  • 08:22 – Routing, latency and cold potato routing
  • 13:00 – Building a real gateway host and clusters
  • 16:42 – Proactive maintenance and monitoring
  • 21:00 – Takeaway: tune, monitor, scale

Key takeaways

  • The on-premises data gateway is a processing engine that authenticates, encrypts, buffers and executes queries, so its default concurrency, buffer and streaming settings directly cap Power BI, Power Automate and Power Apps performance.
  • Routing gateway traffic through corporate VPNs or proxies adds latency, while letting it reach the nearest Microsoft edge and ride the Microsoft global network keeps it fast.
  • Run the gateway on dedicated hosts with enough RAM, cores and SSD storage, cluster it, exclude it from antivirus scanning, stage updates and monitor it with the gateway performance report and PowerShell health checks.
