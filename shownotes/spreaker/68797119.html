Your backup jobs show green, yet one over-privileged identity can delete or quietly expire every recovery point. This episode is for Azure administrators and security teams responsible for ransomware recovery. You learn the common attack paths and a three-step hardening plan with soft delete, multi-user authorization, vault lock and identity separation.

In this episode

  • 06:56 – Common attack paths that kill backups
  • 11:20 – Three-step hardening strategy
  • 16:06 – VM, Azure SQL and Azure Files risks
  • 18:51 – Demo: soft delete, MUA and vault lock
  • 19:37 – Enterprise scenarios and tooling

Key takeaways

  • Azure Backup is not immutable by default; soft delete, multi-user authorization and vault lock must be enabled and tested in that order.
  • The real threat to backups is IAM design: contributors, owners, shadow admins and automation that can both deploy and purge.
  • Separate duties with distinct roles, narrowly scoped managed identities, PIM elevation, policy-enforced retention floors and alerts on destructive backup operations.
