Many Azure File Sync environments still authenticate with certificates and SAS tokens that can be copied, leaked and reused. This episode is for Azure and hybrid infrastructure admins who want to understand the risk and move to managed identities with a clear, step-by-step migration path via Azure VMs and Azure Arc.

In this episode

  • 00:00 – Why Azure File Sync authentication is rotting
  • 01:33 – The legacy model: certificates and SAS tokens
  • 04:09 – The "but it still works" syndrome
  • 07:43 – Managed identities explained
  • 12:27 – Migration playbook: Azure VMs and Azure Arc
  • 17:41 – After the switch: security that scales
  • 21:28 – Why migration is the only sensible move

Key takeaways

  • Certificates and SAS tokens in legacy Azure File Sync deployments are transferable secrets that grant access to whoever holds them, regardless of identity.
  • Managed identities replace both authentication legs with short-lived Entra ID tokens and automatic RBAC role assignments, removing manual rotation and extra firewall URLs.
  • Migration means updating the sync agent to version 20 or later, enabling system-assigned identities on Azure VMs or via Azure Arc for other servers, then switching the Storage Sync Service to managed identity.
