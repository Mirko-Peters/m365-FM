A Power BI gateway that works in test can collapse in production because of one missed outbound firewall rule. This episode walks admins and BI teams through the real gateway communication pattern, service account pitfalls and architecture mistakes, plus when a VNet data gateway is the better choice.

In this episode

  • 00:00 – A gateway horror story
  • 00:33 – Simple setup, production collapse
  • 04:06 – The outbound firewall rule
  • 06:57 – Service accounts as saboteurs
  • 11:00 – Architecture mistakes and clustering
  • 14:26 – VNet data gateways as the alternative

Key takeaways

  • A Power BI gateway that passes portal tests can still fail in production when strict outbound filtering blocks its dynamic connections to Azure services.
  • Gateway service accounts need consistent credential mappings and sufficient rights on every data source, otherwise refreshes fail seemingly at random.
  • Run gateways on dedicated hosts, cluster across failure domains, keep them close to the data, and consider a VNet data gateway when data already lives in Azure.

Worth quoting
