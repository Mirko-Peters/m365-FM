Project managers and Microsoft 365 developers who spend hours stitching status updates together from Planner, SharePoint and Teams will learn how to build a custom Copilot plugin that does it for them. The episode covers the API calls, the manifest and the secure authentication needed for one reliable answer.

In this episode

  • 00:00 – Where project data hides in Microsoft 365
  • 04:25 – Mapping the APIs that matter: Graph and SharePoint REST
  • 08:26 – Writing the manifest that teaches Copilot
  • 12:16 – Securing and deploying the plugin
  • 16:13 – One question, one reliable answer

Key takeaways

  • Project data in Microsoft 365 is scattered across Planner, SharePoint lists and Teams, and each source has its own API structure, permissions and query syntax.
  • A custom Copilot plugin needs precisely defined Microsoft Graph and SharePoint REST calls plus a clear manifest that maps natural-language terms to API parameters.
  • An app registration with least-privilege scopes, OAuth 2.0 with tested token refresh, and existing DLP rules make the plugin a governed, dependable reporting path.

Worth quoting
