Without telemetry, Business Central admins only learn about problems when tickets pile up. This episode walks through connecting the Power BI telemetry apps to Azure Application Insights, avoiding the application ID trap and using the four reports to spot performance problems early.

In this episode

  • 00:00 – Running Business Central blind
  • 00:46 – Why telemetry matters
  • 03:48 – Choosing between the two Power BI apps
  • 07:40 – Finding the application ID in the Azure portal
  • 11:18 – Wiring live data into the dashboards
  • 14:15 – The four reports: usage, errors, performance, administration
  • 18:15 – From firefighting to data-driven operations

Key takeaways

  • Business Central telemetry in Application Insights captures behavior signals such as sessions, errors and query durations, not business data, and exposes problems like deadlocks before users report them.
  • Use the environment Usage app for system-wide telemetry and the App Usage app for a single extension, both requiring a Power BI Pro license for live data.
  • Connect with the Application Insights application ID (not the instrumentation key), OAuth 2.0, the right tenant and a sensible lookback and refresh schedule.

Worth quoting

“Telemetry only captures behavior signals like sessions, errors, and performance, not customer invoice data. It's privacy by design, meant for system health, not business secrets.” – Mirko Peters (00:28)

“Users only raise their hand when something hurts, and by then it's already failed. Telemetry keeps the loop tight. It shows performance shifts and error patterns as they build, not just when the roof caves in.” – Mirko Peters (01:05)
