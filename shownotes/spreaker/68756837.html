Attackers no longer need to break MFA when they can talk users into approving prompts, reading out device codes or consenting to malicious apps inside Microsoft 365. This episode walks security and identity admins through five real attack patterns in Teams, OAuth, SharePoint and token replay. You get concrete Conditional Access, consent and detection controls to close each gap.

In this episode

  • 00:00 – Why MFA alone fails
  • 00:51 – Teams pretexting and authority theater
  • 07:02 – Device code flow abuse
  • 13:50 – OAuth app consent persistence
  • 21:12 – SharePoint anonymous link exfiltration
  • 28:20 – Token theft and session replay
  • 34:44 – Corrective doctrine baseline

Key takeaways

  • Disable broad user consent and route all third-party app permissions through administrator consent, verified publishers and app governance.
  • Restrict Teams external access to an allow list and treat any chat-initiated MFA prompt or device code request as a likely attack.
  • Bind sessions with phishing-resistant authentication, token protection and continuous access evaluation so stolen tokens cannot be replayed.

Worth quoting

“Citizens remember Teams is not a chat room. It is an identity elevator. Therefore supervision is compulsory. If external messaging is business critical, confine it with governance. If it is not, disable it categorically.” – Mirko Peters (06:04)
