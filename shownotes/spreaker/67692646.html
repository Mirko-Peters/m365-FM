Cloud platforms look nothing like a 1975 box of switches, yet Azure still runs on the same ideas of shared resources and programmable access. This episode is for IT pros, developers and Power Platform makers who want to reason more clearly about cloud architecture and cost. You learn how mainframe and terminal patterns explain modern design choices and how to apply them to automation today.

In this episode

  • 00:38 – The box with switches

  • 07:54 – The terminal renaissance
  • 11:55 – People and the hidden soft skills
  • 15:46 – From switches to APIs
  • 19:46 – Three takeaways

Key takeaways

  • Constraints create clarity: the Altair 8800 forced precise, efficient design, and the same habit pays off when sizing cloud resources and building flows.
  • Centralization returns for efficiency, so Azure and Microsoft 365 work like a globally scaled mainframe with shared pools, contention and scheduling hidden underneath.
  • Systems thinking still wins: terminals, scripts and APIs reward clear intent, documentation and observability more than any single tool.

Worth quoting

“The cloud hides the machinery, but not the logic. Shared pools, contention and scheduling didn't vanish, They've just become transparent to the end user.” – Mirko Peters (06:46)

“Running computing power as a shared pool has always been cheaper and more adaptable than everyone buying and maintaining their own hardware.” – Mirko Peters (05:53)
