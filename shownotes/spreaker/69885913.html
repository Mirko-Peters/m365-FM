Most Copilot Studio agents look great in the demo and quietly lose trust in production. This episode is for architects and IT leaders building action-capable agents, and explains the contracts, identity, orchestration and governance needed to make agent outcomes repeatable, auditable and safe to scale.

In this episode

  • 00:00 – Chat is not a system
  • 04:50 – Why agents are too conversational
  • 16:19 – The decision model
  • 24:25 – Success and failure cases
  • 36:17 – Intent contracts and decision boundaries
  • 40:12 – Identity, context and tools
  • 56:56 – Governance as portfolio management
  • 61:07 – Metrics, testing and agent ops

Key takeaways

  • Copilot agents fail when conversation carries the workflow; use chat for discovery and parameter collection and push execution into deterministic flows and APIs.
  • Every action-capable agent needs intent contracts, an explicit identity model, bounded knowledge, narrow tool contracts and a system of record for evidence.
  • Run agents as a governed portfolio with environments, DLP, release gates, regression tests and metrics such as intervention rate and determinism instead of session counts.

Worth quoting

“The core line is still the simplest one. Chat is for discovery. Agents are for execution. Confuse the two and you automate ambiguity.” – Mirko Peters (13:51)

“Prompts can shape tone. Prompts can reduce some ambiguity. Prompts can nudge behavior, but prompts cannot manufacture a control plane that doesn't exist.” – Mirko Peters (04:15)
