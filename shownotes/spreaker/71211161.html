Many first Power Platform projects stall because teams build screens before defining the process they want to change. Using a Contoso vacation request example, this episode shows makers and IT leads how to turn Dataverse tables into a working canvas front door, choose between canvas and model-driven apps, and avoid environment and licensing traps.

  • 53:20 – Traps: default environment and premium cost
  • 71:04 – Why the app solves only half the problem

Key takeaways

  • A first Power App should be a narrow business interface that makes one repeated request, such as a vacation request, enter a governed path with a visible status.
  • Choose canvas for a low-friction employee front door and model-driven apps where roles need oversight across many Dataverse records and relationships.
  • Keep release one small: avoid the default environment for operational apps, avoid unnecessary custom or premium connectors, and model future complexity like delegation in Dataverse first.

Worth quoting

“The first app is not a feature demo. It is a business interface. And that difference changes almost every decision that comes after it” – Mirko Peters (03:52)

“If the thinking is clean, low code helps us express it faster. If the thinking is weak, low code helps us spread that weakness faster too.” – Mirko Peters (50:13)
