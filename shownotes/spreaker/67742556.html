.NET teams often assume they are safe because they run the latest framework, while OWASP 2025 points at risks in dependencies, containers and old code patterns. This episode is for developers, architects and security leads who build and run .NET apps. You learn which new categories matter most, which legacy traps to fix and how to build security checks into your pipeline.

In this episode

  • 00:00 – Why the latest framework is not enough
  • 00:34 – The OWASP categories you didn't see coming
  • 04:19 – What's missing and why you're not off the hook
  • 07:52 – Hidden traps in existing .NET code
  • 11:52 – Designing security into the .NET workflow
  • 16:12 – Measuring against the 2025 standards
  • 20:25 – Three moves to take away

Key takeaways

  • The OWASP 2025 update shifts attention to architectural and ecosystem risks such as NuGet supply chain exposure and poor visibility into container images.
  • Risks that dropped in the ranking, like injection flaws and insecure deserialization, still live in existing .NET code and remain attractive to attackers.
  • Security has to be built into the CI/CD pipeline with dependency audits, SBOMs, static analysis, authorization tests and regular threat modeling instead of old checklists.

Worth quoting

“A strong identity library doesn't protect you from an outdated base image in a container.” – Mirko Peters (03:09)

“These improvements drive incident volume down, Yet attackers can still and do take advantage when teams slip back into unsafe habits. Lower ranking doesn't mean gone, it means attackers still exploit the quieter gaps.” – Mirko Peters (05:14)
