Clicking through the Azure portal works for one-off fixes but breaks down when changes must be repeatable across environments. This episode is for Azure admins and developers deciding between Azure CLI and PowerShell. You will learn when to use each tool, how to combine them and how to run scripts reliably in hosted environments.

In this episode

  • 00:00 – The trap of the Azure portal
  • 03:39 – Azure CLI and Azure PowerShell: two personalities
  • 07:35 – When PowerShell meets CLI
  • 11:00 – Where command line tools come alive
  • 15:20 – Automation with a spark of AI
  • 19:20 – Consistency over tool loyalty

Key takeaways

  • Manual clicks in the Azure portal cause configuration drift and outages, so repeated tasks should move to scripts that run the same way every time.
  • Azure CLI fits quick scripts and pipelines with its JSON output, PowerShell fits object-based filtering and reporting, and calling az inside PowerShell combines both.
  • When scripts move to Cloud Shell, Azure Functions, Azure Automation or GitHub Actions, check authentication, the identity's permissions and module versions first.

Worth quoting

“PowerShell isn't better than Cli, and CLI isn't better than PowerShell. The real win is consistency. When you move away from portal clicks and use both tools intentionally.” – Mirko Peters (19:34)

“The simplest way to think about it is this, Cli drops data in, PowerShell shapes data out. Use both, and you stop treating output like a pile to sift through and start treating it like structured input for your next step.” – Mirko Peters (10:42)
