When an AI agent gives a wrong answer, can you prove how it got there? This episode is for developers and compliance teams working with Azure AI Foundry and explains how threads, runs and run steps create an auditable trail of every message and tool call, so agents become traceable, debuggable and ready for enterprise use.

In this episode

  • 00:00 – Foundry agents as a managed runtime
  • 00:28 – Meet the squad leader: model, instructions, tools
  • 03:19 – Threads: the battlefront log
  • 06:31 – Runs and run steps
  • 09:56 – Arsenal and alliances: tools, MCP and connectors
  • 13:14 – Conclusion and next steps

Key takeaways

  • An Azure AI Foundry agent combines a model, instructions and tools, which gives you reproducible and auditable behaviour instead of loose text generation.
  • Threads keep a persistent, time-stamped conversation record, runs execute the agent on that thread, and run steps log every tool call and message for debugging and audits.
  • Built-in tools, OpenAPI and MCP extensions and Logic Apps connectors widen what agents can do, while on-behalf-of authentication keeps user permissions intact.

Worth quoting
