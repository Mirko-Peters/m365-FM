Agents in Microsoft 365 can pass conditional access, stay fully logged in Purview and still delete the wrong SharePoint site or disclose sensitive data to external meeting guests. This episode shows security architects and M365 admins why permissions and forensics are not control, and how action-time policy gates, idempotency and segmented identities contain the blast radius.

  • 50:03 – Conditional access: necessary, not sufficient

Key takeaways

  • Conditional access and Purview operate at token time and after execution, so they cannot stop an entitled agent from doing the wrong thing at action time.
  • Put a deterministic per-tool-call policy gate in front of every side effect, evaluating actor, intent, scope, data class and venue before execution.
  • Use idempotency keys with an authoritative state store and split agent identities into read, write and egress lanes to keep failures small.

Worth quoting

“Organizations keep building governance around artifacts that exist before and after execution, but not at execution. So you get beautiful audit trails and ugly outcomes.” – Mirko Peters (07:03)

“Token time control without tool time control is a polite front door with no locks inside the building.” – Mirko Peters (07:38)
