PowerShell scripts built on MSOnline, AzureAD or heavy Graph modules break on Linux runners, containers and CI/CD. This episode shows admins and automation engineers the module-free token, headers and REST pattern for Microsoft Graph, three auth flows and three enterprise demos for Intune cleanup, onboarding and compliance remediation.

In this episode

  • 00:00 – Why PowerShell modules are legacy
  • 03:32 – The core pattern: token, headers, REST
  • 07:41 – Demo 1: Intune device cleanup
  • 10:35 – Demo 2: Identity onboarding via Graph
  • 13:20 – Demo 3: Compliance drift remediation
  • 16:14 – Architecture and best practices
  • 20:50 – The token audience gotcha

Key takeaways

  • Calling Microsoft Graph directly with Invoke-RestMethod removes module load times, dependency conflicts and the lag between new Graph features and module releases.
  • Use device code for local testing, client credentials with a certificate for unattended automation, and managed identity wherever the workload runs in Azure.
  • Production Graph scripts need paging via nextLink, retry with backoff on throttling, a dry-run flag, logging of request IDs and a token audience that matches Graph.
