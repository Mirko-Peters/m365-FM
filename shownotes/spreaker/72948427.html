API keys and database passwords hard-coded in config files are one push away from being exposed. This episode explains Azure Key Vault in plain English for developers and cloud admins: what to store in it, how access control really works, the contributor-role trap that exposes secrets, and why managed identity is the gold standard.

Key takeaways

  • Azure Key Vault centralizes secrets, keys and certificates so credentials never live in code or config files and can be rotated in one place.
  • Switch from legacy access policies to Azure RBAC and audit the Key Vault Contributor role, because with legacy policies a contributor can grant itself access to every secret.
  • Use managed identities, separate vaults per environment, and enable soft delete and purge protection to build a secure, low-cost secret management foundation.

Worth quoting

“Azure Key Vault is a cloud-based digital safe for your secrets. It's a managed service from Microsoft for storing API keys, database passwords, connection strings, encryption keys, and certificates in one central place.” – Mirko Peters (00:54)
