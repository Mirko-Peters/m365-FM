Slow Power BI refreshes usually come from misunderstanding how Power Query orders and executes your steps. This episode is for Power BI developers and analysts who want to understand logical versus physical execution, keep query folding intact, and structure queries so refresh times become predictable.

In this episode

  • 00:00 – Power BI does not run your steps in order
  • 00:49 – Logical versus physical execution
  • 04:03 – Query folding, the hidden optimizer
  • 09:25 – When folding fails
  • 13:45 – Source, transformation and load stages
  • 17:59 – How to fix the broken order
  • 21:17 – The real order of Power BI

Key takeaways

  • Applied Steps in Power Query describe a logical order, while the engine builds a dependency tree and executes an optimized physical plan that can defer, reorder or skip steps.
  • Query folding pushes transformations back to the source; one non-foldable step such as a custom function or index column makes every downstream step run locally and can turn seconds into minutes.
  • Keep queries foldable by checking View Native Query and query diagnostics, separate source, staging and load queries, avoid uncontrolled query references, and move heavy logic into SQL views or Fabric.
