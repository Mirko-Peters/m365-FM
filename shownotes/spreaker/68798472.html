Single AI agents that try to plan, execute, approve and document everything stall or break things in production. This episode shows Microsoft 365 and Azure admins how to build a governed multi-agent system with Azure AI Foundry and Semantic Kernel that safely automates Intune, Entra and Graph tasks.

In this episode

  • 00:00 – Why multi-agent systems get work done
  • 00:32 – The limits of a single agent
  • 02:32 – Multi-agent roles, tools and safety boundaries
  • 04:47 – Building with Azure AI Foundry and Semantic Kernel
  • 09:50 – Demo 1: Device cleanup in Intune
  • 13:38 – Demo 2: Zero-touch onboarding
  • 17:17 – Demo 3: Automated security hardening
  • 22:58 – Best practices and closing thoughts

Key takeaways

  • Splitting work across planner, operator and reviewer agents reduces role confusion, hallucinations and risky changes compared with one do-everything agent.
  • Azure AI Foundry provides agent definitions, models, knowledge, tools, content safety and tracing, while Semantic Kernel orchestrates the agent loop in code.
  • Every agent needs its own managed identity with least privilege, PIM-gated destructive actions, human approvals and full tracing in Log Analytics.

Worth quoting

“But the real failure is role confusion. One agent trying to plan a change, call Graph, write a remediation script, request approval, verify the result and document it is like running a help desk, a change board, and a post-mortem with one very tired intern.” – Mirko Peters (00:58)

“The planner focuses on intent and constraints. The operator focuses on tools and execution. The reviewer focuses on guardrails, approvals and are we grounded in facts? Each agent keeps a clean short instruction set with the minimum memory it needs.” – Mirko Peters (01:33)
