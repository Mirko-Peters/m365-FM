## FAQ

**What is a Fabric warehouse snapshot?**

A Fabric warehouse snapshot is a read-only, transactionally consistent, point-in-time view of a warehouse. It uses metadata pointers instead of copying data, so it is zero copy. Queries see only transactions committed before the snapshot timestamp, while the live warehouse keeps loading in the background without pausing pipelines or cloning warehouses.

**Do read replicas give consistent reporting during ETL loads?**

No. Read replicas copy changes, including half-loaded batches and schema shifts, so they add read capacity but no point-in-time guarantee. Dashboards on a replica still catch mid-flight data. Snapshots present only committed data as of a timestamp and never change mid-query, so the episode recommends replicas for scale and snapshots for trust.

**How do you keep Power BI reports stable while the warehouse is loading?**

Capture or roll a snapshot with a stable name right before ingestion, run the load and transforms, validate row counts and schema, and only then roll the snapshot timestamp forward. Reports keep the same connection, so analysts never see partial batches, and if validation fails they keep querying the last consistent state.
