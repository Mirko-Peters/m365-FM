- Start with sensitive information types, sensitivity labels, DLP and [conditional access](https://www.m365.fm/entity/conditional-access/?utm_source=podcast&utm_medium=shownotes&utm_campaign=the-truth-about-microsoft-security-and-copilot-readiness-with-asne-holtklimpen-mvpmct), which are available even with E3 licenses, before rolling out Copilot broadly.
- Copilot readiness is really Microsoft 365 data governance readiness and needs management ownership, clear use cases and cleanup of old Teams and sharing links.

## FAQ

**Does Microsoft 365 Copilot create new security risks?**

No, according to Åsne Holtklimpen, Copilot does not create new security problems but exposes existing ones. It only sees what users can access, so folders overshared during pandemic-era moves to Teams, old sharing links and outdated files suddenly become easy to find. Cleaning up permissions and data should come before switching Copilot on broadly.

**How do sensitivity labels keep Copilot away from confidential data?**

Labeling content as highly confidential can stop Copilot from extracting or retrieving it. Åsne recommends first creating your own sensitive info types to classify data, then applying labels and DLP policies. When content from a labeled document is reused, the new file inherits the strictest label, and conditional access can add location-based restrictions.

**Can organizations on E3 licenses prepare for Copilot?**

Yes. Åsne points out that many public sector customers stay on E3 for budget reasons, yet labeling is available with E3 and other licenses. She recommends combining data classification and sensitivity labels with conditional access in Entra ID as simple first steps, and asking someone experienced for help when the team does not know where to start.
