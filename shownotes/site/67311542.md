## FAQ

**Why do Power Apps break when moved from dev to test or production?**

They break because the maker portal is not built for true portability. Moving an app often surfaces missing data sources, lost dependencies and settings that drifted out of sync, which leads to manual rework. Small differences between test and production can then turn into hours of troubleshooting, even when nothing was built wrong.

**How do I set up PAC CLI without risking my production environment?**

Start in an isolated sandbox and create authentication profiles before building anything. Use pac auth list to see connected environments and pac auth create to link to the sandbox, so every command is scoped. Then run a dry check, such as listing solutions, to confirm you are targeting the right environment before making changes.

**Which PAC CLI commands are used to package a Power Platform solution?**

The episode walks through pac solution init, pac solution add-reference and pac solution pack. Init scaffolds the solution structure, add-reference records dependencies such as plug-ins or custom connectors, and pack bundles everything with metadata and version information. If a key dependency is missing, packing reveals it before the release reaches production.
