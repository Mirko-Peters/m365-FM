## FAQ

**What does a production-ready Azure OpenAI architecture in Power Platform look like?**

It has four layers: Power Apps or Dynamics 365 as the trigger, Power Automate for orchestration, the Azure OpenAI endpoint as the brain, and Azure API Management as the guardrail. Power Apps never call the model directly; flows clean and format the payload first, which keeps latency and odd model answers under control.

**Why put Azure API Management in front of Azure OpenAI?**

Because it enforces authentication on every request, limits how many calls reach the endpoint and logs who did what. In the episode's example, a leaked API key and a recursive test loop sent thousands of calls within hours; a rate limit would have stopped the flood early and logging would have flagged it immediately.

**How can I keep Azure OpenAI costs under control in Power Automate flows?**

Match the model and settings to the task and set limits early. Use the smallest model that works for classification or sentiment, cap max tokens for long-form generation, set usage quotas on flows, and monitor request and token usage in the Azure portal. Resource tags, budgets and the CoE Starter Kit help track spending.
