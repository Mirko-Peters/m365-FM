## FAQ

**Why do Power Platform Centers of Excellence fail?**

They fail because they rely on human oversight instead of enforcing rules in the platform itself. The audits revealed five patterns: governance that exists only as documentation, manual review boards with long backlogs, environment sprawl, orphaned flows without owners, and vanity metrics such as maker counts. Policy as code and an automated control plane address them.

**How can a CoE prevent orphaned Power Automate flows?**

Enforce ownership automatically by tying flow and agent identities to active roles in Microsoft Entra ID. The episode suggests checking makers' employment status weekly, sending an ownership request to the department head when someone leaves, and quarantining the flow if no owner is assigned within 48 hours. Ownership metadata should be required at creation.

**What should a Power Platform CoE measure instead of the number of makers?**

Measure business impact, such as manual hours saved and mission-critical processes fixed, instead of makers onboarded or total flows. Counting activity hides that many flows deliver no value while still costing licensing, storage and security attention. Ask how long a process took before automation and how long it takes now, then target high-impact workflows.
