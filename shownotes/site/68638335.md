## FAQ

**What is context engineering for Copilot Studio agents?**

Context engineering means designing the information and boundaries an agent works with across four layers: system, retrieval, tools and policies. The episode argues most Power Platform AI failures come from missing context rather than model limits, so a versioned system message, Dataverse grounding, governed Power Automate actions and DLP stop hallucinated fields and drift.

**Why does my Copilot Studio agent behave differently in dev and prod?**

Environments are the security boundary in Power Platform, so different DLP policies, connectors and bindings change what the agent can see and do. A system message copied without environment tokens adds more drift. Parameterize instructions with environment variables, keep the same tool names and schemas everywhere, and test against realistic DLP settings in UAT.

**How do I stop a Copilot Studio agent from inventing Dataverse fields?**

Ground it in a Dataverse schema index first. Capture entities, fields, data types, option set values, relationships, business rules, masked sample records and a synonyms glossary mapping terms like stage or phase to canonical field names. Set Dataverse as the primary knowledge source, boost schema matches in retrieval and refuse when nothing relevant is found.
