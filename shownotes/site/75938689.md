This episode explains for report builders and Microsoft 365 admins what a gateway does, which of the three gateway types fits, and which limits and mistakes to avoid so refreshes keep running.

## Key takeaways

- A [Power BI](https://www.m365.fm/entity/power-bi/?utm_source=podcast&utm_medium=shownotes&utm_campaign=power-bi-gateways-simply-explained) gateway only connects outward through Azure Relay, so no inbound firewall ports have to be opened.
- Use personal mode only for solo work; as soon as more than one person depends on a refresh, move to a standard gateway or a cluster, or to the VNet data gateway for data inside [Azure](https://www.m365.fm/entity/azure/?utm_source=podcast&utm_medium=shownotes&utm_campaign=power-bi-gateways-simply-explained).
- Most gateway trouble comes from operations: sleeping laptops, undersized machines, outdated versions, mixed cluster members and lost recovery keys.

## FAQ

**Do I need a Power BI gateway for every report?**

No, you only need a gateway when the data sits behind a firewall, a VPN or inside an Azure virtual network. If the data already lives in a cloud service Power BI can reach directly, such as Azure SQL Database, reports usually connect with no gateway at all, and adding one just creates another machine to maintain.

**Does a Power BI gateway require opening inbound firewall ports?**

No, the gateway never needs an inbound connection because it always connects outward. It checks in regularly with Azure Relay, picks up queued queries with encrypted credentials, decrypts them locally, queries the data source and sends results back up. Only TLS 1.2 connections are accepted, so the network can stay closed to inbound traffic.

**When should I use a standard gateway instead of personal mode?**

Switch to a standard gateway the moment more than one person depends on a refresh. Personal mode works for exactly one user and only with Power BI. A standard gateway is shared, managed centrally, supports clusters for reliability and serves other tools too. For data inside an Azure virtual network, the managed VNet data gateway needs no machine.
