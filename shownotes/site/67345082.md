## FAQ

**How should I choose partition keys for a Microsoft Fabric Lakehouse?**

Choose partition keys from the columns your queries actually filter on, not from defaults like date. Check historical query logs and talk to business analysts first. Under-partitioning forces broad, expensive scans, while over-partitioning creates thousands of tiny files and metadata overhead. In one example, switching from region to order type halved the refresh window.

**Why are my Power BI dashboards slow even though caching is enabled in Fabric?**

Default caching treats data evenly, so your hottest tables may not be in memory when reports refresh. Review query history to find the tables critical dashboards use, then pin those so they stay cached during business hours. Leave rarely used data to automatic caching, since over-caching irrelevant data wastes limited, costly memory.

**When should I run compaction on Delta Lake tables in Fabric?**

Run compaction based on table conditions, such as file counts and average file size, rather than on a fixed schedule. Frequent small loads keep adding files, slowing every read. In the episode's example, an hourly-loaded table grew to thousands of files and refreshes crept from two to ten minutes; condition-based compaction brought them back under two.
