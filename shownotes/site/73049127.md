## Key takeaways

- Microsoft Graph Data Connect is built for scheduled bulk extraction of Microsoft 365 data, while the Graph API serves real-time access to small amounts of data.
- Admin consent, property-level scoping, encryption, identity obfuscation and audit trails make the bulk export suitable for regulated industries.
- Data lands as Parquet files in a Fabric lakehouse or Azure storage, but the roughly 45-minute pipeline overhead and per-object pricing make it unsuitable for real-time scenarios.

## FAQ

**What is the difference between Microsoft Graph Data Connect and the Graph API?**

The Graph API serves real-time requests for small amounts of data, while Graph Data Connect is built for scheduled bulk extraction. With the API you page through results and fight HTTP 429 throttling. Data Connect copies entire datasets in one pipeline into your own storage, with no pagination and no throttling to manage.

**How long does a Microsoft Graph Data Connect pipeline take to start?**

Each pipeline run has roughly a 45 minute overhead before data starts moving, while Microsoft prepares the dataset. That makes Graph Data Connect a poor fit for real-time dashboards or alerts. The episode recommends it for nightly or weekly analytics jobs and points to Power Automate or the Graph API for real-time needs.

**How do you set up Microsoft Graph Data Connect?**

You enable Data Connect in the Microsoft 365 admin center and choose datasets, then create an app registration in Microsoft Entra ID. Next you create a Data Connect application in the Azure portal with a destination, have an admin approve it, and build a copy pipeline in Fabric or Azure Data Factory.
