## FAQ

**What is the difference between a thread, a run and a run step in Azure AI Foundry?**

A thread is the persistent conversation record, a run executes the agent on that thread, and run steps log each action inside the run. Threads store time-stamped messages with roles, runs carry statuses such as queued, in progress or completed, and run steps record every tool call and generated message in order.

**How do you debug a wrong answer from an Azure AI Foundry agent?**

You debug it by inspecting the run steps, which show in order which tools were called, which code ran and which messages were produced. That lets you find the exact misfire instead of guessing. You can also rewind the thread to the original request, and inspect run steps in the SDK or in the portal.

**Do Foundry agents respect user permissions when they access SharePoint or Fabric?**

Yes, tools connecting to systems like SharePoint or Microsoft Fabric use on-behalf-of authentication mediated by Microsoft Entra, so an agent cannot read anything the user couldn't. Every tool call is also logged at step level with identity, inputs, outputs and timestamps, which gives compliance teams a traceable record of who invoked what.
