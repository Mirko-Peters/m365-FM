## FAQ

**Why does a medallion architecture in Fabric need CI/CD?**

Without CI/CD, one bad load or untested change spreads through bronze, silver and gold with no way back. Version-controlled pipelines, automated schema and data quality checks, and packaged deployments let you roll back to the last known good build in minutes instead of rebuilding ingestion logic by hand under deadline pressure.

**Should I use GitHub, Azure DevOps or Fabric deployment pipelines?**

Use them together rather than picking one winner. GitHub or another Git host holds notebooks, scripts and pipeline configs; Fabric's deployment features package and move workspace objects between dev, test and prod; Azure DevOps adds approvals, gates and an audit trail. Start from your governance needs, then assign each tool a capability.

**What tests should run before promoting a Fabric Warehouse change?**

At minimum, run schema compatibility checks confirming expected columns and data types still exist. Add null, uniqueness and type checks for silver, a regression comparison on a small sample across environments, and a smoke query that asserts critical KPIs fall within expected ranges. If any check fails, the deployment stops before it reaches production.
