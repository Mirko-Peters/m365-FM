## FAQ

**What are Azure Copilot agents and what do they do?**

They are specialized agents for migration, deployment, optimization, observability, resiliency and troubleshooting. Instead of six separate tools, the episode describes them as a coordinated fabric: an orchestration layer routes work, manages handoffs and keeps state, so each agent builds on what the others learned about the environment rather than starting every investigation from zero.

**How do you keep Azure Copilot agents from making risky changes?**

Use scoped identities and tiered approvals. Each agent gets its own Entra ID service principal with only the permissions it needs, existing Azure Policy and RBAC apply to it, and every action is logged. Low-risk fixes and non-production changes can run directly, while production changes are submitted as proposals that a human approves.

**Which Azure Copilot agent should you pilot first?**

Start with the agent that addresses your most immediate pain, usually optimization or troubleshooting. Mirko Peters recommends one agent, one problem and a non-critical environment such as staging, a baseline measured beforehand, scoped permissions, weekly tracking of accepted and rejected recommendations, and an assessment after roughly 90 days before adding the next agent.
