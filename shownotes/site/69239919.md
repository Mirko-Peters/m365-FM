## FAQ

**Does Microsoft Fabric make T-SQL unnecessary?**

No. The episode argues T-SQL moved upstream into the part of the platform where cost, audit and performance problems start. Schemas, constraints, permissions, stored procedures and plan behavior keep a Fabric warehouse deterministic. Without them, bad lakehouse data loads silently and gets patched downstream in Power BI, DAX and Power Query.

**What is parameter sniffing and why does it cause cost spikes?**

Parameter sniffing happens when the engine compiles a plan for the first parameter values it sees and then reuses it. A plan built for a query returning 50 rows can run against 5 million rows, burning CPU and memory. Options include OPTION (RECOMPILE), local variables or splitting procedures, each with trade-offs.

**How should teams review AI-generated SQL from Copilot?**

Let AI draft the query, but treat the execution plan as the acceptance gate. Reject queries with a large gap between scanned and returned rows, unbounded full scans on large tables, expensive sorts or spills, and joins that change cardinality unexpectedly. Then rewrite approved logic into a view or stored procedure with explicit permissions.
