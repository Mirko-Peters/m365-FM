## FAQ

**Why are service accounts a bad idea for Power Automate email flows?**

Service accounts tie machine tasks to a human-style identity, so MFA prompts, Conditional Access changes and password expiry break flows and can cause duplicate sends. They also attract extra Send As rights and exemptions over time, which creates over-privilege, and shared passwords blur attribution so the audit trail cannot show clearly who sent what.

**What does an Exchange Online application access policy do?**

An application access policy limits which mailboxes an app with the Mail.Send application permission can send from. You put approved mailboxes in a mail-enabled security group and bind the app to it with New-ApplicationAccessPolicy. Without the policy, the episode warns, the app could send as any mailbox in the tenant; calls outside the group return 403.

**How do I avoid duplicate emails when retrying Microsoft Graph sendMail calls?**

Use an idempotency key for each intended message, built from the business object ID, recipient and a timestamp bucket, and check your log before resending. Retry only on 429 and 5xx errors with exponential backoff that respects Retry-After, never retry a 403, and log the client request ID plus Graph's request ID and date.
