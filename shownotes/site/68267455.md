Synchronized Active Directory groups show up in Entra ID as read-only, which blocks automation, self-service and access reviews. This episode is for identity and Microsoft 365 admins running hybrid environments and shows how to clean up groups, flip the source of authority to the cloud and use group writeback so legacy systems keep working.

## Key takeaways

- Source of authority is set per object, and flipping a group to cloud managed lets Entra ID govern it with dynamic membership, self-service and access reviews.

## FAQ

**How do you convert an Active Directory group's source of authority to Entra ID?**

You send a single PATCH request in Microsoft Graph Explorer that sets the group's isCloudManaged property to true. First fetch the group's object ID and consent to the group on-premises sync behavior permission. The episode notes there is no dramatic wizard: one boolean flips and Active Directory stops governing that group.

**Which groups are eligible for source of authority conversion and group writeback?**

Groups must be universal, security-only and not mail-enabled. Global groups should be converted to universal first, distribution lists stay with Exchange, and mail-enabled security groups wait until the mail migration is finished. The episode stresses that only estates with pure cloud messaging should convert, otherwise Entra policies and Exchange schema conflict.

**Do you need a license to flip a group's source of authority to the cloud?**

No premium license is needed for the switch itself, according to the episode. Group writeback is different: it requires an Entra ID P1 license and Entra Cloud Sync rather than the legacy Connect engine. Writeback lets converted cloud groups appear on-premises so older file servers and applications can still check access.
