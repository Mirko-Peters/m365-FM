## FAQ

**Why are tokens safer than passwords for Azure apps?**

Tokens are short-lived and scoped, while passwords are static and grant broad access. Entra ID issues a signed access token tied to a user or service identity, limited to specific resources, and it expires on its own. If one leaks, the damage is small, and the Microsoft identity libraries handle refresh automatically.

**How do managed identities remove secrets from Azure applications?**

A managed identity gives an Azure resource its own identity in Entra ID, so it can request tokens without stored credentials. You enable it on an App Service, function or VM, grant it a role on the target such as a SQL database, and the app gets tokens from the metadata service. Nothing needs rotating or can leak into logs.

**What is the On-Behalf-Of flow in Entra ID?**

The On-Behalf-Of flow lets a service exchange an incoming user token for a new token valid for the next API in a chain. Forwarding the original token fails because it was issued for a different audience. With OBO, each hop gets a token scoped to its role, so the user's identity travels intact without extra consent prompts.
