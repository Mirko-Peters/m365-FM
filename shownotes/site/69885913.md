## FAQ

**Why do Copilot Studio agents fail in production?**

Most fail because conversation carries the workflow instead of a control plane. Intent capture, decisioning and execution collapse into one stream of text, so the same request can take different paths. Adding more prompts does not fix this, because prompts cannot create missing contracts, explicit identity decisions, tool allow lists or an audit trail.

**Should a Copilot agent run as the user or as a service identity?**

Decide per intent contract, because both models have consequences. User-delegated execution preserves the existing access graph and accountability but inherits MFA prompts, Conditional Access and entitlement differences between users. Service execution gives consistent behavior but creates standing privilege and a larger blast radius, so its permissions must be limited to the minimum contract set.

**Which metrics show whether a Copilot agent actually works?**

Intervention rate, determinism score, audit completeness, strictly defined operational KPIs and refusal quality show whether an agent works. Session counts and thumbs-up ratios are comfort metrics. Determinism is measured by rerunning a fixed set of 10 to 50 canonical requests after every change and checking that routing and tool calls stay stable.
