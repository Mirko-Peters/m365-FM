## FAQ

**How can admins control who publishes Copilot agents?**

Admins can separate building from publishing in the Microsoft 365 admin center. Policies define which groups may create automation, while deployment authority stays with designated roles. For example, finance analysts can draft agents for their reporting needs, but only the IT governance team decides whether those drafts ever reach a production environment.

**What can admins restrict in Copilot Studio?**

Admins decide which actions, connectors and publishing permissions are available to builders in Copilot Studio. Marketing might create draft agents while only named people publish them, approved connectors like SharePoint or Dynamics stay available, and sensitive third-party services are blocked. Querying a database can be allowed while directly updating key fields stays locked down.

**Why is enabling permissions not enough for agent governance?**

Permissions act like fences, but without monitoring you cannot see whether agents behave as intended. Audit logs record when an agent changed, which connectors it touched and who triggered it, while usage analytics reveal duplication and unusual activity. The episode describes a company that could not show a regulator who deployed specific automations.
