## Key takeaways

- Business Central telemetry in Application Insights captures behavior signals such as sessions, errors and query durations, not business data, and exposes problems like deadlocks before users report them.
- Use the environment Usage app for system-wide telemetry and the App Usage app for a single extension, both requiring a Power BI Pro license for live data.
- Connect with the Application Insights application ID (not the instrumentation key), OAuth 2.0, the right tenant and a sensible lookback and refresh schedule.

## FAQ

**Which Power BI app should I use for Business Central telemetry?**

Use the Dynamics 365 Business Central Usage app for environment-wide telemetry and the App Usage app for a single extension. Both are free on AppSource, look nearly identical and offer the same four reports. The difference is scope: the whole environment versus one extension, so many teams install both.

**Why do my Business Central telemetry dashboards in Power BI stay empty?**

Most often you pasted the instrumentation key instead of the Application Insights application ID. Also check that OAuth 2.0 is the authentication method, your account has read access to the resource in the same Microsoft Entra tenant, and you triggered a dataset refresh after changing settings. Live data also requires a Power BI Pro license.

**Where do I find the Application Insights application ID in the Azure portal?**

Open the Application Insights resource connected to Business Central and select API access in the left navigation, not overview, properties or keys. The application ID is shown there as a 36-character string with hyphens. Copy it exactly, because one missing character or extra space breaks the Power BI connection without a clear error.
