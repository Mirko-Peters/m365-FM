## Key takeaways

## FAQ

**Why are my Power BI refreshes slow through the on-premises data gateway?**

Often the gateway is still running on default settings built for safety rather than speed. Low concurrency forces queries to run one after another, small buffers spill data to disk, and antivirus scanning throttles I/O. Raising concurrency and buffer limits within the host's capacity and excluding gateway folders from real-time scanning usually helps.

**Should on-premises data gateway traffic go through a corporate VPN or proxy?**

No, routing gateway traffic through a corporate VPN or central proxy adds hops and inspection delays to every query. The episode recommends letting traffic leave locally, reach the nearest Microsoft edge point of presence and ride the Microsoft global network to the Azure region, which keeps latency low and predictable.

**What hardware does an on-premises data gateway host need for production?**

For production, plan on at least 16 GB of RAM, eight or more dedicated cores and SSD or NVMe storage for logs and cache. Microsoft's published minimum is far lower. Virtual machines work only with fixed, reserved resources, and clustering two or more hosts adds load balancing and redundancy.
