## FAQ

**What is mean time to explain in AI and agent operations?**

Mean time to explain is how long your best people need to answer why an agent or Copilot behaved the way it did. Unlike MTTR, which measures restoring a broken component, it measures reconstructing context, tool calls, delegation and prompt versions. The episode argues that once it rises too far, agent architecture stops scaling because explanation becomes the bottleneck.

**Why does Copilot give different answers in Teams, Outlook and SharePoint?**

Because each workload acts as a separate agent runtime with its own context surface. Teams is conversation first, Outlook is thread first and SharePoint is content first, so the same prompt lands on different grounding and relevance ranking. Permission edges in Microsoft Graph add further variance, which the episode describes as runtime variance rather than user error.

**How should an organization run a 90-day agent pilot?**

Pick one cross-functional process that touches a system of record, such as onboarding or access requests, and run the agent as a product with a named owner. Build the deterministic core first, let reasoning only propose actions through registered tool contracts, add two kill switches, measure mean time to explain and prove clean decommissioning at day 90.
