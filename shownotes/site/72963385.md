## FAQ

**What is the difference between a pod, a node and a cluster in Kubernetes?**

A pod is your application, a node is where it runs, and a cluster is the whole environment. A pod wraps one or more containers that share storage and networking. A node is a physical or virtual server running pods, and the cluster is all nodes managed as one system by the control plane.

**What does the Kubernetes control plane do?**

The control plane is the brain of a Kubernetes cluster that decides what runs where. The API server handles every request, the scheduler picks a node for each pod, the controller manager keeps the actual state matching the declared state, and etcd stores the cluster's configuration as its source of truth.

**Why use Azure Kubernetes Service instead of running Kubernetes yourself?**

With Azure Kubernetes Service, Azure runs the control plane for free, so you only pay for worker nodes. Self-managed clusters make you responsible for upgrades, security patches and etcd backups, and many teams spend more time on the cluster than on their apps. AKS also offers an automatic mode with ready-to-use defaults.
