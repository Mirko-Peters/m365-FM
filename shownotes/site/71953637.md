## FAQ

**What is the elastic reservoir model for Microsoft 365 storage?**

It replaces per-tenant static quotas and safety buffers with one pooled storage reservoir that scales with demand. Mirko Peters argues that fragmented silos leave quiet tenants wasting capacity while busy ones hit limits. In the pooled model, resource governance policies keep performance predictable, and Azure Elastic SAN lets performance and capacity scale independently.

**When should automated storage scaling trigger and how do you avoid throttling?**

The episode recommends firing scaling events at 80 percent utilization instead of waiting for Microsoft's 95 percent notification. Orchestration must respect the Azure Resource Manager token bucket limits that return 429 errors, so it uses Azure API Management as a buffer, delta queries, batched requests and load spread across multiple service principals.

**How do you stop Copilot from surfacing another tenant's data in a shared architecture?**

Treat identity and the search index as the boundary. The episode recommends Entra ID governance that checks device and geography context, carrying the tenant ID through every layer of the stack, and isolating the search index so AI only sees data tagged with the user's validated tenant ID. Sensitivity labels can also exclude restricted files from grounding.
