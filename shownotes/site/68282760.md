## Key takeaways

- Generative Pages turn a sentence into a working React page inside Power Apps, but clicking Edit Code turns managed configuration into source code the platform no longer maintains.
- Code-edited pages inherit React version drift, npm dependency vulnerabilities, Dataverse schema drift and permission gaps that low-code governance cannot catch.
- Contain the risk by moving edited pages to developer environments with version control and CI/CD review gates, and treat Edit Code as a one-way door with clear ownership.

## FAQ

**What happens when you click Edit Code on a generative page in Power Apps?**

The page stops being a managed low-code configuration and becomes source code that Microsoft no longer maintains. From then on, React versions, npm dependencies, permission checks and Dataverse field references are your responsibility, and the episode notes that reverting an edited page to pure low code is effectively impossible.

**What is Code Compare for generative pages in Power Apps?**

Code Compare shows the before and after of edits to a generative page's code. The episode reads it as an admission that conflicting code states are now expected, because the AI agent can regenerate React after manual edits and overwrite some changes, leaving diffs that mix human and generated lines.

**How should organizations govern code-edited generative pages?**

Move any page whose code was edited into a developer environment with version control and lifecycle management. Add a review gate with linting, dependency scanning and static analysis before republishing, and treat Edit Code as a one-way door: the page never returns to low code and has a clear owner.
