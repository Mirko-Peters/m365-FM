## FAQ

**Why do unit tests pass when an Azure app still breaks in production?**

Unit tests only prove that isolated logic works with controlled inputs. They do not reach Cosmos DB, Service Bus or the front end, so they miss serialization errors, configuration mismatches, message routing and cross-service timing. In the episode's example, a refactored order function exits early during queue serialization, and payment and notification services never receive the message.

**What do integration tests catch that unit tests miss?**

Integration tests catch environment problems such as mismatched queue names, incorrect connection strings, authentication mismatches and latency issues. They run against real services, often in a staging or disposable environment. A test that actually produces and consumes a message in staging would have revealed a queue name mismatch before users noticed missing emails and triggers.

**How should unit, integration and front-end tests run in an Azure DevOps pipeline?**

Run each layer where it is cheapest: unit tests on every commit right after the build, integration tests in gated builds against a staging environment, and Playwright browser tests nightly or before release. Optional load tests fit major releases against pre-production. Each stage catches different errors before anyone has to debug them.
