## FAQ

**Why does PowerShell hit a ceiling for Azure and Microsoft 365 automation?**

PowerShell hits a ceiling because it is imperative: it executes actions but never declares the infrastructure, identities and permissions its scripts depend on. With dozens of scripts, nobody remembers which automation accounts, key vaults or service principals exist, there is no desired state to enforce, and rebuilding the platform turns into reverse engineering.

**Can Bicep manage Entra ID groups and app registrations?**

Yes. Since Microsoft Graph Bicep support became generally available in July 2025, you can declare Entra ID groups, applications, service principals and Graph permissions in the same Bicep file as function apps and key vaults. Identity changes then go through Git, pull requests and review, just like any other infrastructure change.

**Should I use Bicep or Terraform for Microsoft 365 infrastructure?**

For most Microsoft 365 organizations that run only in Azure, Bicep is the simpler choice: it compiles to ARM templates, supports new Azure resource types on day one and needs no state file. Terraform makes sense if you genuinely operate across AWS, GCP or on-premises, or your team already has strong Terraform expertise.
