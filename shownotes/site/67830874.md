## FAQ

**How do I get Microsoft Graph permissions working in an SPFx web part?**

Declare only the Graph scopes you need in webApiPermissionRequests in package-solution.json, deploy the package to the app catalog and have an admin approve the scopes in the SharePoint admin center. Then test with a normal user account, because an admin sees far more than regular users and can hide access-denied problems.

**How can I make Microsoft Graph calls faster in SPFx?**

Request less data and cache what rarely changes. Use the select parameter so Graph returns only fields like display name, job title and mail, keep profile data in session or local storage with a sensible refresh interval, and handle errors with a fallback message. Leaner calls also help you stay clear of Graph throttling.

**How do I push real-time updates to an SPFx web part instead of polling?**

Subscribe the SharePoint list to a webhook, catch the events in an Azure Node.js web app or Azure Function, and broadcast them with Socket.IO over WebSockets. The SPFx client listens with a socket client, pulls the actual changes from SharePoint and flows them into the UI with an RxJS event stream.
