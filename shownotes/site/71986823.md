## Key takeaways

- Automate repetitive tasks such as user onboarding first, because scripted processes deliver consistent results every time.
- Learn PowerShell with a real business case and understand objects, properties and methods before writing complex scripts.
- Never store credentials in scripts; use a [key vault](https://www.m365.fm/entity/azure-key-vault/?utm_source=podcast&utm_medium=shownotes&utm_campaign=powershell-is-fun) or certificates, version scripts in GitHub and document them so colleagues can run them.

## FAQ

**What should IT admins automate first with PowerShell?**

User onboarding is usually the best first candidate, according to Harm Veenstra. Creating accounts in Entra ID, assigning rights and permissions, adding people to software and setting up Intune laptops involves many repetitive manual steps. Scripting the process means the outcome is the same every time, no matter who runs it or when.

**How should credentials be handled in PowerShell scripts?**

Credentials should never be stored in scripts. Harm recommends Azure Key Vault or certificate-based authentication, where the script contains only the tenant ID and application ID and authenticates with a certificate from the local certificate store. The SecretManagement module helps locally, while role-based access control and Conditional Access add further protection.

**How do you find the right Microsoft Graph calls to automate an admin task?**

Use tools that reveal which Graph endpoints the admin portals call. Harm mentions Graph X-Ray, a browser extension used in developer mode that shows the Graph requests made while you click through a portal, as well as Graph Explorer. Once you know the endpoints, you can reproduce the action in a PowerShell script.
