## FAQ

**What makes ESG reporting auditable on Microsoft Cloud?**

Auditable ESG rests on four system properties: immutability, reproducibility, lineage and separation of duties. In the episode these map to ADLS Gen2 with immutable storage, a governed calculation zone in Fabric or Azure Synapse, Microsoft Purview for lineage, Entra ID for role separation and Power BI as a thin reporting layer.

**Why should ESG emissions calculations not live in Power BI DAX measures?**

Power BI is a presentation tool, not an audit-grade calculation engine. When emissions logic lives in DAX measures, editing a measure silently recomputes historic values, so last year's number can change without a trace. Calculations belong in a governed zone that publishes period-closed KPI tables, which Power BI only reads and displays.

**How should emissions factors be managed for ESG audits?**

Treat emissions factors as versioned reference data, never as a latest table. Each factor library gets a version key, effective dates, provenance and an approval, and is locked once a period closes. Calculations must require that version key and fail without it, so rerunning a prior year produces exactly the same result.
