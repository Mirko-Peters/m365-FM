## FAQ

**How do managed identities make Microsoft Fabric pipelines more secure?**

They remove passwords from pipelines entirely. Each pipeline gets its own identity in Microsoft Entra ID, issued and rotated by Azure, and never appears in a script. You grant that identity access only to the exact storage, databases or APIs it needs, which ends credential sprawl and painful manual password rotation.

**How do I use Azure Key Vault secrets in a Fabric pipeline?**

Store the secret in Azure Key Vault and give the pipeline's managed identity read rights to just that secret. The pipeline then references Key Vault instead of a hardcoded value. Auditors see references and access logs, never the key itself, and rotating the secret requires no code changes in the pipeline.

**Why are default workspace permissions in Microsoft Fabric a security risk?**

Because permissions are inherited from the workspace down to pipelines and datasets unless you restrict them. Adding an analyst for a report can quietly grant edit rights to production pipelines or views of sensitive data. Use granular roles, remove temporary access, and review role assignments regularly, at least quarterly, to stop privilege creep.
