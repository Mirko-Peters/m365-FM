Picking the wrong Azure managed disk can cost you performance, money or both. This episode walks Azure beginners and VM admins through the five disk types, IOPS and throughput, LRS versus ZRS, encryption, backups and cost tips so they can choose the right disk for each workload.

## Key takeaways

- Managed disks remove the need to create and balance storage accounts yourself, because [Azure](https://www.m365.fm/entity/azure/?utm_source=podcast&utm_medium=shownotes&utm_campaign=azure-managed-disks-simply-explained) handles placement, replication and limits behind the scenes.
- Premium SSD v2 and Ultra Disk let you set IOPS and throughput independently of capacity, while Premium SSD and Standard disks scale performance with disk size.
- Azure bills for provisioned disk size, so right-sizing, deleting unattached disks and choosing LRS for non-critical data are the biggest cost levers.

## FAQ

**What is the difference between Premium SSD v2 and Premium SSD?**

Premium SSD v2 lets you set IOPS and throughput independently of disk size, while the original Premium SSD ties performance to capacity. With Premium SSD you may buy a larger disk just to get more IOPS. Premium SSD v2 avoids that over-provisioning and, according to the episode, is generally cheaper for the same performance.

**Should I use LRS or ZRS for Azure managed disks?**

Use LRS for most workloads and ZRS for mission-critical systems that must survive a zone outage. LRS keeps three copies in one data center, ZRS spreads them across availability zones and costs more. Ultra Disk and Premium SSD v2 only support LRS, and managed disks have no automatic geo-redundancy at all.

**When should I use disk snapshots versus Azure Backup?**

Use snapshots for quick rollbacks before a patch or deployment, and Azure Backup for long-term protection and compliance. Snapshots are incremental and cheap but you must create and clean them up yourself. Azure Backup applies policies, handles retention, stores copies in a Recovery Services vault and supports file-level restore.
