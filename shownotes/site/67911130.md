## FAQ

**Why is a single flat table slow in Power BI?**

A flat table repeats descriptive text, like customer names or regions, on every row, so the VertiPaq engine scans duplicated values on every query. DAX has to de-duplicate attributes again and again, and filter propagation can break. Moving those attributes into slim dimension tables makes slicers faster and results more accurate.

**Should I snowflake dimensions in a Power BI model?**

Usually not. The episode recommends flattening dimensions into single tables, so a product dimension holds name, brand, subcategory and category together. Snowflake chains force filters through several tables, increase model size and complicate queries. Treat them as exceptions, for example when shared reference data is governed by another system or a taxonomy changes daily.

**Why do I need a separate date table in Power BI?**

A dedicated date table makes time intelligence reliable, while a raw date column in the fact table leads to inactive relationships and broken calculations. Build a continuous date range, add a surrogate key and attributes like year, quarter and month name, then create role-playing copies for order, ship or due dates with referencing queries.
