## FAQ

**When should a Power App use Dataverse instead of SharePoint lists?**

Use Dataverse once an app has more than about twenty casual users or approval workflows, stores sensitive data such as PII, stacks relationships between entities, or holds data that outlives the project. SharePoint lists remain fine for prototypes, static reference data, short-term surveys and small internal dashboards.

**What are the limits of SharePoint lists as a Power Apps data source?**

The main limits are the 5,000-item view threshold and delegation limits, even though a list can technically hold up to 30 million items. Lists are not relational, so lookups between entities break easily, any editor can delete columns, and ownership is scattered across whoever created each list.

**Is Dataverse really more expensive than SharePoint lists?**

Not in total cost of ownership, the episode argues. Dataverse has an explicit per-user or capacity cost, but it includes auditing, backups, role-based security and integration that list-based apps end up rebuilding by hand. The hidden cost of lists shows up as maintenance hours, broken lookups, lost data and security exposure.
