This episode walks security analysts and Microsoft 365 administrators through two reconstructed SOC investigations, token theft and an OAuth consent grant attack, and shows which Entra, Defender, Sentinel and Purview guardrails decide the outcome.

## Key takeaways

- Modern cloud attackers rarely break in; they log in with stolen session tokens or with OAuth consent a user granted, so identity signals are the first evidence to read.
- Conditional Access with risk-based policies, phishing-resistant authentication strength, blocked legacy authentication and device code flow, and browser-only sessions for unmanaged devices stops a replayed token mid-flight.
- Admin consent workflow, consent policies and Defender for Cloud Apps contain consent attacks, while [sensitivity labels](https://www.m365.fm/entity/sensitivity-labels/?utm_source=podcast&utm_medium=shownotes&utm_campaign=inside-a-microsoft-soc-investigation-of-a-real-world-cloud-breach), eDiscovery, insider risk and records management turn logs into a defensible chain of custody.

## FAQ

**How can attackers take over a Microsoft 365 account even when MFA is enabled?**

They steal the session token instead of the password. In the episode's first case, a phished user enters credentials and completes MFA on a fake page, and the attacker walks away with the session cookie. The token is then replayed from another device and country, so the defense has to come from Conditional Access and token risk signals.

**What is an OAuth consent grant attack in Microsoft 365?**

It is an attack where a user approves a malicious app instead of losing a password. A polite email asks the user to connect a calendar app that requests mail, file and offline access. Once consent is given, the app holds legitimate tokens and quietly harvests data, with no MFA prompt or failed sign-in to raise an alarm.

**Which steps contain a token theft incident once it is detected?**

Revoke all sessions first, then remove the attacker's inbox rule, then reset credentials with phishing-resistant enrollment. The episode uses a temporary access pass to bridge the MFA gap and a FIDO key to close it, while Defender isolates the endpoint and Sentinel correlates the high-risk sign-ins, failed prompts and mailbox rule into one incident.
