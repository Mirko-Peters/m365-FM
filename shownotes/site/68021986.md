## FAQ

**Why do Microsoft Fabric and Power BI costs grow faster than planned?**

Costs usually grow because of self-service sprawl, not one bad purchase. Teams create their own workspaces, clone datasets and build duplicate semantic models, and each copy adds refresh cycles, storage and licensing usage. Without workspace policies and approval paths, organizations end up buying more capacity or PPU licenses just to keep up with demand nobody planned.

**How do Fabric domains help reduce duplicate semantic models?**

Fabric domains assign clear ownership of data, so finance owns revenue, HR owns headcount and sales owns pipeline. Each domain curates and certifies its own data products. Report writers then build on one certified model instead of cloning their own copy every week, which removes duplicate refresh jobs and keeps capacity use predictable while users still self-serve.

**When should you use Power BI Premium Per User instead of premium capacity?**

Use Premium Per User for pilots and contained groups of power users, and premium capacity once BI spreads across departments. PPU is cheap at small scale but multiplies with every seat. Mirko recommends a simple adoption forecast early, so you move to capacity before a popular report forces a rushed switch and overlapping spend.
