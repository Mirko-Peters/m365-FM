## FAQ

**Can a SharePoint agent see files that its identity has permission to open?**

Yes. An agent sees whatever its identity can access through Microsoft Graph permissions; retrieval filters and grounding only steer relevance and are not security boundaries. If inheritance leaves adjacent libraries open, the agent can stitch their content into answers. The episode recommends running agents as least-privilege service identities rather than as whoever invokes them.

**How do you stop a SharePoint agent from processing confidential files?**

Bind sensitivity labels to Purview DLP policies that block agent processing unless the agent is on an allow list. A user can still read a file labeled, for example, Confidential HR, while unapproved agents are blocked with override disabled, a clear message and a high-severity alert. Start in simulation mode and tune confidence thresholds first.

**Should one SharePoint agent cover all company knowledge?**

No. The episode recommends several narrow agents, such as HR policy, benefits and travel, each scoped to its own library with metadata filters and general AI knowledge disabled. If you need one entry point, a router agent hands queries to the right specialist. When source limits are reached, split the scope instead of widening it to the whole site.
