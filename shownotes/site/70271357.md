## FAQ

**What is cloud erosion in Azure?**

Cloud erosion is the gradual drift between the state you intended and the state that actually exists as an organization scales. It grows from velocity, complexity and conflicting incentives: one unencrypted storage account becomes precedent, exceptions pile up, and audit-mode policies keep logging violations nobody acts on until compliance is unknown.

**Should Azure Policy run in audit mode or deny mode?**

Use audit mode only as a starting point, then move to deny mode. Audit mode gives visibility but blocks nothing, while deny mode stops non-compliant deployments. The episode recommends testing policies in code, refining false positives, shifting to deny as confidence grows and using deploy-if-not-exists to remediate automatically.

**How should AI agents be governed in Azure?**

Each AI agent should get its own identity, for example through Microsoft Entra Agent ID, instead of sharing human credentials. Agents need scoped permissions, a human owner, immutable logs, pre-execution gates that validate actions, and cost estimates that block operations over a threshold, because unbounded retry loops can create runaway spend within minutes.
