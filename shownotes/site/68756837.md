## Key takeaways

- Disable broad user consent and route all third-party app permissions through administrator consent, verified publishers and app governance.
- Restrict Teams external access to an allow list and treat any chat-initiated MFA prompt or device code request as a likely attack.
- Bind sessions with phishing-resistant authentication, token protection and continuous access evaluation so stolen tokens cannot be replayed.

## FAQ

**What is device code phishing in Microsoft 365?**

Device code phishing tricks a user into reading out a device code so the attacker can complete the OAuth sign-in on their side. No password is exchanged, and tokens including refresh tokens go to the attacker. The episode recommends banning code sharing, confining device code flow to managed networks and monitoring for device auth bursts.

**How do you stop Teams phishing from external tenants?**

Set Teams external access to deny by default and allow only approved partner domains. Use shared channels with verified tenants instead of open DMs, enable Safe Links in Teams, and require phishing-resistant authentication for any step-up started from chat. Users should verify IT outreach through the published service desk number, never the one in the message.

**Which single misconfiguration undermines MFA according to the episode?**

Broad user consent enabled for Graph scopes. If users can grant apps permissions such as Mail.ReadWrite, Files.Read.All or offline access, a malicious app gains durable access that neither MFA nor password resets remove. The fix is to disable user consent and rely on administrator consent workflows, verified publishers and app governance.
