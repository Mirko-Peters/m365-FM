## FAQ

**What is a runbook in Azure Automation?**

A runbook is a script, usually PowerShell and sometimes Python, that Azure Automation runs exactly the same way every time. Runbooks live in an Automation account together with schedules, credentials and variables. They can start and stop VMs, copy files, query databases, call APIs or send notifications. Graphical runbooks also exist for drag-and-drop workflows.

**How do I run Azure Automation runbooks on on-premises servers?**

Install a Hybrid Runbook Worker on a Windows or Linux machine, ideally connected through Azure Arc, and the runbook runs locally using that machine's network and permissions. This reaches servers the Azure sandbox cannot, and the sandbox's three-hour runtime limit does not apply. In return, you must patch and maintain the worker machine yourself.

**How can I automatically start and stop Azure VMs on a schedule?**

Create an Automation account, import the prebuilt start and stop runbooks from the gallery, and create two weekday schedules, for example 6 a.m. and 7 p.m. Grant the account's managed identity the Contributor role on the VMs' resource group, then link each runbook to its schedule. The first 500 runbook minutes each month are free.
