## Key takeaways

- Enterprise agents fail not because models are weak but because they are built as stateless, siloed chat interfaces instead of persistent system participants.
- A working agent fabric needs session persistence, a shared backend with thin clients, a dedicated [Entra](https://www.m365.fm/entity/microsoft-entra/?utm_source=podcast&utm_medium=shownotes&utm_campaign=architecture-over-chat-building-the-agent-fabric) Agent ID per agent, explicit orchestration and model routing to control cost.
- Persistent memory and agent-to-agent calls create new risks such as memory poisoning and data leakage, which require Agent 365 governance, [DLP](https://www.m365.fm/entity/dlp/?utm_source=podcast&utm_medium=shownotes&utm_campaign=architecture-over-chat-building-the-agent-fabric) by design, sandboxing and causal observability.

## FAQ

**Why do enterprise AI agents fail when they are built as chat interfaces?**

Chat is stateless, so the agent forgets context when the window closes or the user switches devices. Agents doing real work need persistent sessions, their own identity, shared memory and coordination with other agents. The episode argues the architecture, not the model, is what breaks once tasks span systems, days or teams.

**How does the GitHub Copilot SDK handle session persistence across devices?**

It gives each session a stable session ID and keeps persistent event logs that survive process restarts. Resuming means replaying the log, so the agent continues with full context. Because the agent logic lives in one backend and VS Code, the CLI or web apps are thin clients, any device can reconnect to the same session.

**How can organizations keep the cost of always-on AI agents under control?**

Use model routing: send routine tasks such as classification or simple extraction to smaller, cheaper models and reserve frontier models for complex reasoning. The episode says this needs a deliberate routing layer, quality tests and business-driven routing policies, and cites savings of 40 to 85 percent compared with using one model for everything.
