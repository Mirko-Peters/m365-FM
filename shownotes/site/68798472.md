## Key takeaways

- Splitting work across planner, operator and reviewer agents reduces role confusion, hallucinations and risky changes compared with one do-everything agent.
- Azure AI Foundry provides agent definitions, models, knowledge, tools, content safety and tracing, while Semantic Kernel orchestrates the agent loop in code.

## FAQ

**Why does a single AI agent struggle with enterprise IT automation?**

A single agent fails mainly because of role confusion, not model size. When one prompt has to plan, call Graph, write scripts, request approval, verify and document, the context window fills with logs and policies. The agent then truncates important details or hallucinates missing ones, while latency, token costs and retries increase.

**How do Azure AI Foundry and Semantic Kernel work together in a multi-agent system?**

Azure AI Foundry is the home base and Semantic Kernel is the conductor in code. Foundry holds agent definitions, model deployments, knowledge via Azure AI Search, tool wiring, content safety, tracing and evaluations. Semantic Kernel wires the planner, operator and reviewer loop, registers function catalogs for tools, and handles retries with backoff and cancellation tokens.

**How do you stop AI agents from making destructive changes in Intune or Entra ID?**

Give each agent its own managed identity with least privilege and put destructive actions behind PIM. Monitor agents get read scopes, remediators get write scopes, and no identity can delete without elevation that requires a human. Approvals run through Logic Apps, a reviewer agent blocks overly broad scopes, and every tool call is traced in Log Analytics.
