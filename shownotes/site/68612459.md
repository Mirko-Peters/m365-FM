## FAQ

**Why should I not use a product name as the key when importing Excel data into Dataverse?**

Because names drift and are rarely truly unique, so Dataverse cannot tell whether an incoming row should insert or update. Keep the system GUID as the primary key and define alternate keys on business fields such as a product code. The episode describes a team whose bulk rename pointed historical orders at a new product.

**When should I use a choice column versus a lookup column in Dataverse?**

Use a choice when the list is finite, governed and has no metadata, such as a status with a few fixed values. Use a lookup to a separate table when the values carry properties like addresses, ratings or compliance flags, as with suppliers or locations. Text repeated across thousands of rows is a relationship waiting to be modeled.

**How do I prevent orphan records when migrating Excel data to Dataverse?**

Load parent tables first, then children, and make critical lookups required. Import suppliers, locations and categories with alternate keys active, map child rows to those keys, and fail rows that do not resolve instead of auto-creating parents. Set delete behavior to restrict on parents and build views that surface rows with a blank parent.
