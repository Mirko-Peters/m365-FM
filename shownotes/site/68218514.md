## FAQ

**Why is my Power BI refresh so slow?**

A slow refresh usually comes from a bloated model rather than Power BI itself. Unused columns, calculated columns recalculated row by row on every refresh, and tangled many-to-many or bidirectional relationships force the engine to do extra work. Trimming columns, moving logic into Power Query and adopting a star schema shortens refresh times considerably.

**Should I use calculated columns or Power Query in Power BI?**

Push data shaping into Power Query instead of calculated columns wherever possible. A calculated column is persisted in the model and recalculated row by row on every refresh, which bloats the dataset. Power Query transformations run once at load time, leaving DAX free to focus on calculations during analysis rather than preprocessing chores.

**When should I use bidirectional relationships in Power BI?**

Only rarely, as a deliberate exception rather than a default setting. Single-direction filters from dimension to fact should be the rule, because bidirectional relationships create ambiguity, propagate filters unexpectedly and inflate calculations. When you really need it, apply cross-filtering inside CALCULATE for that specific measure, and avoid circular relationships entirely.
