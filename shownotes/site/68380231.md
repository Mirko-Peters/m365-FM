## FAQ

**Why are Microsoft Fabric governance audits so hard to do manually?**

Because Fabric, Purview and Power BI each hold only part of the picture. Fabric knows lineage, Purview knows classifications and Power BI knows security roles, but none of them correlate the others. Auditors end up exporting metadata, matching names that almost align and reconciling spreadsheets, often missing renamed workspaces or misclassified assets.

**How does GPT-5 in Copilot audit Fabric data differently from GPT-4?**

GPT-5 reasons across services instead of answering within one. Given an audit prompt, it traces Fabric lineage, checks Purview labels, cross-checks Power BI row-level security and merges everything into one summary with flagged inconsistencies. It can match differently named fields that mean the same thing, and it explains the reasoning behind each conclusion.

**How do you set up a GPT-5 governance audit in Copilot Studio?**

First, explicitly select the GPT-5 reasoning model as default for your custom copilots. Then connect Fabric, Power BI and Purview through official connectors authenticated with Microsoft Entra ID, build reusable audit prompt templates, and test them with staged anomalies such as a removed Purview label. Keep validating results against Fabric lineage or Purview.
