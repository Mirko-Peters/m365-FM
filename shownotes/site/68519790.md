## FAQ

**Why are 3D objects and digital twins hard to govern?**

A single 3D asset is not one file but a collection of meshes, textures, materials, scans, rigging and simulation data. Each part can have different owners, licenses and sensitivity, and the asset moves across many tools and regions. Folder permissions and file names cannot track versions, rights and lineage at that complexity.

**How do you version a digital twin in Microsoft Fabric?**

Use a twin manifest stored in OneLake that references every component by immutable ID with semantic versions and a compatibility table. Published twins pin exact versions instead of pointing at the latest files, toolchain hashes are recorded in build metadata, and changes branch rather than overwrite, while Fabric lineage records each processing step.

**How can licensing rights for 3D assets be enforced automatically?**

Model rights as machine-readable policies that state who may use an asset, where, for how long and for which derivatives. The platform evaluates them at access time and issues time-bound tokens tied to identity. When a license is revoked, lineage finds every affected manifest, tokens are invalidated and previews purged.
