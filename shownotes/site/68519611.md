## FAQ

**What is the difference between RAG and agentic RAG?**

Classic RAG runs one retrieval against one index, stuffs the results into the prompt and answers. Agentic RAG adds a planner that splits the question, specialist retriever agents for sources like SharePoint and Fabric, and a verifier that checks citations and contradictions. Its loop is adaptive, so it reruns queries when results conflict.

**How does agentic RAG respect user permissions?**

It uses on-behalf-of authentication, so the user's verified token travels with every request instead of a service principal. Retrievers can only fetch what that user may see: Fabric enforces row-level and column-level security, and SharePoint honors site permissions and Microsoft Purview sensitivity labels. Every retrieval call is also logged for audit.

**How do SharePoint and Microsoft Fabric work together in an agentic copilot?**

Fabric supplies the numeric evidence and SharePoint the qualitative context, and a verifier agent reconciles them. In the episode's example, a Fabric data agent finds yield dips linked to humidity while the SharePoint agent finds an email thread about warped packaging. The planner can query Fabric first to narrow the SharePoint search.
