## FAQ

**What is Azure Virtual WAN?**

Azure Virtual WAN is a managed networking service that connects branches, remote users and virtual networks through Microsoft's global backbone. Microsoft-managed virtual hubs, one per region, route traffic automatically between connected VNets, VPN sites, ExpressRoute circuits and other hubs, so you no longer maintain peerings and route tables yourself. For most real-world scenarios the Standard tier is recommended.

**When is hub-and-spoke better than Azure Virtual WAN?**

Hub-and-spoke is usually the better choice for a single region with a handful of virtual networks and a small team that wants full control over every route and firewall rule. In that setup it is simpler and cheaper. Virtual WAN pays off once you span multiple regions, many branches and remote users, and Microsoft supports migrating later.

**What does routing intent do in Azure Virtual WAN?**

Routing intent is a single hub setting that sends traffic through a firewall instead of requiring user-defined routes on every subnet. It covers internet traffic, private traffic between VNets and branches, and traffic between hubs. Combined with a secured virtual hub running Azure Firewall or a supported third-party firewall, one policy then applies across all regions.
