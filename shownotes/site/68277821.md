## FAQ

**Do model-driven Power Apps require Dataverse?**

Yes, model-driven apps cannot exist without Dataverse. That dependency brings tables, relationships, security roles and column-level security to configure, plus licensing for environments, storage and user access. The episode argues this makes sense for ERP-scale systems but is heavy overhead for teams that only need to track tasks or run approvals.

**How do you build a project tracker with SharePoint lists, Power Automate and Teams?**

Create a SharePoint list with project name, owner, due date and status, adding lookup columns for related data. Then build a Power Automate flow that sends an approval when status becomes ready for review. Finally, add the list as a tab in a Teams channel and optionally post adaptive cards.

**When should you move from SharePoint lists to Dataverse?**

Move when real complexity appears, such as multiple integrations, custom APIs or regulated data. The episode recommends starting light, proving value with a fusion team and upgrading after success rather than before it. Indexing columns and archiving old data keeps lists healthy until then, and exporting data later is described as practical.
