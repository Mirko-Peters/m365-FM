## FAQ

**What is the difference between a Copilot Studio agent and a Power Automate flow?**

A Power Automate flow runs fixed steps in a set order when a trigger fires, while a Copilot Studio agent works toward a described goal and decides at runtime which tools to use through generative orchestration. Both rely on the same connectors and Dataverse tables; the difference is who decides when each tool gets used.

**When should I use an agent instead of a workflow?**

Use an agent when the process needs interpretation, conversation or decisions under uncertainty, such as judging whether a purchase fits a policy or gathering data from several systems. Use a workflow when the process is repeatable, measurable and cannot tolerate deviation, such as document approvals, ticket routing, removing access for terminated employees or system synchronization.

**How do you govern Copilot Studio agents?**

By supervising behavior rather than only tracking inventory. The agent feed shows which actions an agent completed on its own, which needed human input and which failed because instructions were ambiguous. Admins define which tools an agent may use under which authentication, and in a hybrid design execution stays in Power Automate, where run histories and DLP policies apply.
