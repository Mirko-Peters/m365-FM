## FAQ

**What is the difference between Dataflows Gen1 and Dataflows Gen2 in Microsoft Fabric?**

Dataflows Gen2 is a rethink rather than a facelift: transformation logic exists once as a core Fabric resource instead of being copied across tools. It separates compute from storage, adds managed staging for temporary data, offers Fabric-native connectors, ties into deployment pipelines and integrates Git, so lakehouse, warehouse and Power BI all reference one definition.

**How does compute separation in Dataflows Gen2 reduce ETL costs?**

Compute separation lets you scale transformation power independently of storage, so you only pay for extra compute while a heavy job runs. A quarter-end load can get a bigger compute tier for that single run, then scale back down. Your data footprint stays the same, and no query rewrites or permanent capacity increases are needed.

**Can I use Git version control with Fabric Dataflows Gen2?**

Yes, Git integration is built directly into the dataflow layer, not added as an export step or plug-in. A dataflow can live in a Git repo as the source of truth, so teams create branches to test changes, review logic through pull requests, track every commit and roll back to a previous working version when something breaks.
