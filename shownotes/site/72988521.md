## Key takeaways

- Event Grid replaces wasteful polling with push-based, event-driven reactions, and you pay per event rather than for idle infrastructure.
- Events are lightweight notifications published to system or custom topics, then routed by filtered subscriptions to handlers such as [Azure](https://www.m365.fm/entity/azure/?utm_source=podcast&utm_medium=shownotes&utm_campaign=event-grid-simply-explained) Functions, Logic Apps, webhooks or queues.
- Retries with exponential back-off and dead-lettering keep events from disappearing, and Event Grid complements rather than replaces Event Hubs and Service Bus.

## FAQ

**What is Azure Event Grid?**

Azure Event Grid is a fully managed event-routing service. Publishers such as blob storage send lightweight events to a topic, and Event Grid routes them to subscribed handlers like Azure Functions, Logic Apps, webhooks or queues. Publishers and subscribers never need to know each other, so services react instantly instead of polling.

**What happens if an Event Grid handler is down?**

Event Grid retries delivery with exponential back-off for up to 24 hours. If every retry fails and dead-lettering is configured, the event moves to a storage queue or blob container instead of disappearing. You can then investigate the failure, fix the handler or subscription, and reprocess the event.

**When should I use Event Grid instead of Event Hubs or Service Bus?**

Use Event Grid when you need to react to discrete events, such as a blob upload or a resource change. Event Hubs is for high-throughput streaming like IoT telemetry, and Service Bus is for guaranteed, ordered, transactional messaging. The episode's rule: Event Grid reacts, Event Hubs streams, Service Bus coordinates.
