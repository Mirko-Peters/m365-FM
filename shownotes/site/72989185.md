## FAQ

**What is the difference between a trigger and a binding in Azure Functions?**

A trigger decides when a function runs, while bindings decide what data flows in and out. Every function has exactly one trigger, such as HTTP, timer, blob or queue. Bindings are optional input or output connections to storage, databases or queues, so you avoid writing SDK code for connections, retries and serialization.

**How much does the Azure Functions Consumption plan cost?**

On the Consumption plan you pay only when your function runs, based on executions and GB-seconds. At the time of recording, the free grant covers 1 million executions and 400,000 GB-seconds per month, and extra executions cost 20 cents per million. The free grant is shared across all function apps in a subscription.

**When should I not use Azure Functions?**

Avoid Azure Functions for long-running, stateful or compute-heavy work. On the Consumption plan, functions time out after five minutes by default and ten at most. Functions keep no state between runs, so sustained CPU jobs belong on virtual machines or containers, and dependent multi-step workflows fit Durable Functions or Logic Apps better.
