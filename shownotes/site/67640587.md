## FAQ

**Is Microsoft 365 compliant with BSI requirements out of the box?**

No, Microsoft 365 is not compliant with BSI requirements out of the box. Microsoft certifies its platform, but under shared responsibility the customer must configure services correctly, align them with local rules, build governance and document everything. Default settings in Microsoft Purview and the audit streams often do not produce the evidence BSI auditors ask for.

**What should be planned before a Microsoft 365 rollout in KRITIS environments?**

Three phases should be planned before assigning any license: strategy, architecture and governance. Strategy maps compliance goals to BSI standards and scope. Architecture decides which services can be used for regulated data and which, such as Planner or Loop, stay restricted. Governance defines usage rules, roles and escalation processes before the first user signs in.

**Why do regulated organizations need third-party tools on top of Microsoft 365?**

Regulated organizations need third-party tools because some audit requirements exceed what Microsoft 365 delivers natively. The episode names log retention beyond default limits, forensic-level activity detail, regulator-ready reporting templates and, in some sectors, data residency verification down to metadata. Even an E5 license only provides potential functionality; certified extensions supply the evidence auditors expect.
