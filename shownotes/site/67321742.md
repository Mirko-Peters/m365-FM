## FAQ

**Why does a Dynamics 365 solution work in dev but break in test or production?**

Usually because of hidden dependencies the package did not carry. A flow, form script or business rule may reference a field, table or entity that exists only in dev. The green check in dev hides this, so map every referenced component and confirm it is included before you export the solution.

**Should I deploy managed or unmanaged solutions to Dynamics 365 production?**

Deploy managed solutions to production and keep unmanaged ones for development. Unmanaged imports merge into the base system, can overwrite earlier work and cannot be cleanly uninstalled. Managed solutions add layer protection and versioning, so you can roll back or remove functionality. Test the managed import in a matching sandbox first.

**Are environment variables and reference data included when I export a Dynamics 365 solution?**

No, the package mainly carries customizations, not their context. Environment variables, connection references and lookup or reference data must be set or moved separately, for example with a configuration migration tool. Document the values per environment and follow a fixed order: import the solution, configure variables, migrate data, then validate.
