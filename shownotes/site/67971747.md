## FAQ

**What problem do dev containers solve for development teams?**

Dev containers remove environment drift caused by everyone installing their own SDKs and CLIs locally. A shared devcontainer.json declares runtimes, extensions and mounts, so laptops, VS Code and CI pipelines all use the same toolchain. That cuts works-on-my-machine tickets and lets new hires start in hours instead of spending days installing and patching tools.

**What is the difference between dev container templates and features?**

Templates provide a complete starting configuration for a project type, while features are modular install units added to an existing configuration. You add a template through the VS Code command palette, then reference features such as the Azure CLI, Git or Terraform under the features property. Features are published as OCI artifacts and can live in private registries.

**How do you speed up dev container startup in CI/CD pipelines?**

Prebuild the image instead of building the container on demand. Use the dev container CLI or a scheduled CI job, such as a GitHub Action, to bake in runtimes and tools, then push the image to a registry like Azure Container Registry. Rebuilding nightly or on dependency changes keeps everyone on a current, consistent image.
