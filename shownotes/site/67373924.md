## FAQ

**What does a Copilot plugin manifest do?**

The manifest tells Copilot which endpoints it can call, what each operation does and which parameters it needs. It is a structured JSON file with plain-language descriptions, parameter names, types and requirements, plus authentication details. It also maps user phrases like a project name to raw IDs such as a Planner bucket ID.

**Which permissions should a custom Copilot plugin request?**

A plugin should request only the least-privilege scopes it actually needs. If it only reads Planner tasks, a read scope for tasks is enough, and for SharePoint lists it should stick to read access unless writing is required. Many scopes need admin consent, and over-permissioning widens the surface area for a potential breach.

**Why does Copilot need explicit API calls to report on Planner and SharePoint data?**

Copilot cannot guess endpoints, so every call has to be defined explicitly. Microsoft Graph returns Planner tasks in nested JSON with opaque IDs, while the SharePoint REST API needs the exact list and explicitly requested custom columns. Filtering at the source, for example to active tasks due in fourteen days, also avoids throttling.
