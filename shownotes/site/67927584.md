## FAQ

**What is the difference between a copilot and an autonomous agent in Microsoft 365?**

A copilot suggests and waits for your approval, while an autonomous agent runs workflows and takes actions, with or without asking. Admins can configure which behavior applies. Agents also keep memory across sessions, storing conversation history and session IDs, so they can follow up on yesterday's tasks without you re-entering details.

**Where do Microsoft 365 AI agents store their memory?**

In Microsoft's own agent samples, Azure Cosmos DB often acts as the unified memory store. It holds conversation history, embeddings and workflow context, so agents can recall IDs and earlier plans days later. The episode advises per-agent, per-session memory scoping and the ability to wipe stored memory when compliance asks questions.

**What should admins configure before turning on autonomous agents?**

Admins should scope agent identities with role-based access, apply sensitivity labels to all data sources, enable full audit trails and require approval flows for any write operations. Agents should be treated as intentional service accounts rather than inheriting admin-like powers, and low-risk tasks such as HR or IT self-service should be piloted first.
