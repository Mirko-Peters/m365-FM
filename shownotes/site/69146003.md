## FAQ

**Why is Microsoft Foundry a shadow IT risk?**

Foundry lets teams build agents that run as autonomous workloads, which removes the user click that earlier platforms still needed. The episode compares it with SharePoint lists, Power Apps and Teams bots, where governance arrived after adoption. Foundry agents wake up on timers or events, have no UI and can keep running after their owners leave.

**How should identities be set up for Microsoft Foundry agents in Entra?**

Each production agent should get its own dedicated workload identity, not user impersonation or a shared service principal. It needs an owner team, a purpose, an environment tag and an expiry date, plus a shutdown trigger. Authentication should be secretless, using managed identities or workload identity federation, and Conditional Access should restrict where the identity can sign in.

**What is data boundary collapse with AI agents?**

Data boundary collapse happens when every individual access is compliant but the combined result breaks policy. An agent might read a support mailbox, internal SharePoint documents and an external API, then write a merged summary elsewhere. Purview DLP rules scoped to one system approve each hop, so nothing fires even though data classes were combined against policy intent.
