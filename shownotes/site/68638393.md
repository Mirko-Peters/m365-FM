## FAQ

**What is a pre-execution contract check for AI agents?**

A pre-execution contract check is a validator that runs before any tool call and proves three things: the requested tool and arguments match a registered capability, the caller has permission right now, and the outcome is feasible and verifiable. If any check fails, nothing executes and the agent returns reasons plus safe alternatives.

**Why do prompt-only AI agents fail at real operations?**

Prompt-only agents fail because a language model works in probabilities while operations need guarantees. The episode names three failure modes: hallucinated tools or fields, missing preconditions such as unchecked SharePoint access, and silent partial failures where a step breaks but the agent still declares success. An executor checks preconditions and post-conditions instead of trusting the text.

**How do Microsoft Graph, Azure OpenAI and Copilot Studio work together in a governed agent?**

Microsoft Graph supplies grounded data through a retrieval agent with narrow scopes, Azure OpenAI reasons and produces cited plans, and Copilot Studio orchestrates tools and human checkpoints. An executor runs actions with idempotency keys, while a validator and policy guard tied to Entra ID scopes enforce schema, permission and boundary rules before anything changes.
