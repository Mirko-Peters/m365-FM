## FAQ

**What are cross-cutting concerns in software development?**

Cross-cutting concerns are features every system needs that do not belong in business logic, such as logging, authentication, validation, audit trails, exception handling and telemetry. When they are written inline, they spread across controllers and services, bury the actual intent of the code and make every future change slower and riskier.

**What is the difference between the decorator pattern and middleware?**

A decorator wraps an existing service to add behavior like logging or validation without changing its core method. Middleware is a pipeline every request passes through before reaching the controller, so concerns such as authentication or request timing are applied once for the whole API. Both keep domain code focused on domain tasks.

**How can I tell when my code needs refactoring?**

Watch for methods that no longer fit on one screen, the same validation rule copied across several endpoints, and log statements that outnumber business lines. Rising cyclomatic complexity and review fatigue are further signals. The episode suggests picking one such method this week and asking how much of it is business logic versus plumbing.
