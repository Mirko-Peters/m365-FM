## FAQ

**How do passkeys protect against phishing?**

Passkeys leave nothing reusable for attackers to steal. The private key stays on the user's device and never travels over the network, so a fake login page captures nothing and sign-in fails outside the genuine site and device combination. Servers hold only public keys, which cannot be reversed into valid credentials.

**How do you add passkeys to an ASP.NET Core application?**

Add a WebAuthn or passkey library, register the service in Program.cs or Startup, and configure the relying party name and origin. Then create a registration endpoint that issues a challenge and stores the public key, plus an authentication endpoint that verifies signatures, using navigator.credentials in the front end over HTTPS.

**What happens if a user loses the device that holds their passkey?**

Recovery must be planned and tested before passkeys roll out at scale. The episode advises every user to register at least one secondary passkey, such as another device or a hardware security key like a YubiKey, and to set up a recovery flow, for example administrator-initiated account recovery or an IT-managed reset.
