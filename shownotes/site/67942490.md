## FAQ

**How do you make a Fabric dataflow resilient to schema drift?**

Land data in Delta tables where schema evolution is controlled, add logic that ingests new columns dynamically, and code joins defensively by validating types and handling nulls. With Delta schema enforcement, unexpected columns make the job fail loudly and visibly instead of silently corrupting weeks of downstream reports, which the episode illustrates with a client case.

**How do you make Power Query dataflows reusable across projects?**

Break transformations into named, single-purpose Power Query M functions and move hardcoded paths, dates and connection values into parameters or a central metadata table. Dataflow Gen2 reuse across workspaces has limits, so the episode suggests pushing heavy shared logic into the lakehouse or a Fabric notebook and keeping workspace dataflows small and modular.

**How should you partition data and use incremental refresh in Microsoft Fabric?**

Partition by keys that match real query patterns, such as month or region, and avoid high-cardinality columns that create thousands of tiny files. Incremental refresh then processes only new or changed rows instead of full reloads. Running optimize and using coalesce keeps Delta tables compact, and more capacity cannot fix poor design.
