## Key takeaways

- Managed connectors add hidden latency, throttling limits and retry storms because data passes through a shared middleware layer you do not control.

## FAQ

**Why do managed connectors fail under heavy load?**

They route every call through a shared middleware cluster with strict quotas, so traffic spikes trigger throttling and HTTP 429 errors. Workflows then retry, and when many clients retry at once they create a retry storm that hammers the system. The episode argues the problem is the transport model, not the developer's workflow logic.

**What makes gRPC faster than REST with JSON?**

gRPC sends compact binary Protocol Buffers instead of verbose JSON text, so payloads are smaller and serialization needs far less CPU. Its schema-first design defines the contract in a .proto file and generates code from it, so mismatched data is caught before sending. That strict contract also prevents the interface drift that silently breaks connectors.

**What is the difference between managed and built-in connectors in Logic Apps?**

Managed connectors run on a shared cluster outside your virtual network, so data leaves your VNet and returns. Built-in connectors in Logic Apps Standard execute on your own single-tenant compute, respect VNet routing and avoid public egress. For SQL or SAP, VNet peering or ExpressRoute can often replace the on-premises data gateway.
