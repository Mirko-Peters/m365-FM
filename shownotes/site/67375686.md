## FAQ

**Why does AI model training on a laptop fail with large datasets?**

Local machines run out of memory, disk throughput and time once datasets reach hundreds of gigabytes or terabytes. The episode describes kernel restarts, hard drive thrashing and a churn prediction run that failed after twenty hours. Workarounds like sampling or splitting files keep the laptop alive but drop subtle patterns and introduce inconsistencies.

**How do Fabric notebooks read Lakehouse data without CSV exports?**

The Lakehouse is the native data layer for Fabric notebooks, so your code runs where the data already sits. Spark executes joins, filters and aggregations inside the Lakehouse and returns only the results the model needs. That removes stale extracts, duplicated storage and mismatched definitions between teams working from their own exports.

**How can I monitor and recover long training runs in Microsoft Fabric?**

Use Fabric's real-time job monitoring alongside the notebook to watch memory, CPU, epoch progress and streaming logs, and stop a run early when something looks wrong. Periodic checkpoints let a failed job restart from the last saved state, and versioned models with their parameters and data splits let you revisit or branch earlier configurations.
