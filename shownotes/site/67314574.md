## FAQ

**Why use Fabric notebooks instead of Power Query for data preparation?**

Notebooks make every transformation visible as Python or R code that can be reviewed, debugged and rerun. Power Query chains can break silently, for example when someone renames a column, and the logic is hard to trace. Notebooks run next to the Lakehouse data, so there is no exporting files between tools.

**How do Lakehouse, notebooks and Spark work together in Microsoft Fabric?**

The Lakehouse stores raw and curated data, the notebook holds your code, and Spark executes it. When you run a notebook, it submits Spark jobs that execute where the data is stored, so large datasets are processed at scale without local copies. Results can be written back as tables for Power BI or ML.

**How do you keep Fabric notebooks governed as more teams use them?**

Set workspace permissions that control who can run, edit or view notebooks and tables, and review audit logs regularly. Add Git integration with a clear branching strategy, group notebooks by project or domain, document why code changed, and build code review and credential checks into everyday work from the first notebook onward.
