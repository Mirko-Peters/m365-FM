## FAQ

**Does PBIP solve collaboration problems in Power BI teams?**

No. PBIP splits reports and semantic models into text files, so Git can show exactly what changed and branches become practical. But it does not fix team workflow: if several people edit the same model, conflicts still appear, just more visibly. Pull request approvals, automated checks and deployment pipelines provide the actual discipline.

**What automated checks can GitHub Actions run on a Power BI PBIP project?**

GitHub Actions can run on every pull request and check naming conventions, obvious DAX anti-patterns, missing relationships and JSON or model files. The episode mentions Tabular Editor command-line validation, PowerShell with the MicrosoftPowerBIMgmt module and the Power BI REST APIs for smoke tests. Failures post comments to the pull request and block the merge.

**What are the limits of using a service principal with Power BI deployment pipelines?**

Service principals cannot configure OAuth credentials for data sources, so some datasets need a human to fix credentials before they refresh. They become owner of the semantic models and paginated reports they deploy, which can block scheduled refreshes. They cannot deploy dataflows, and each deployment call is capped at 300 items.
