## FAQ

**How can I find out which applications still use EWS in Exchange Online?**

Check the EWS usage report in the admin portal, next to the Exchange usage reports. It shows which EWS operations are in use and which application IDs call them. Glen Scales recommends tracing each application ID back to a line-of-business app, an ISV product or a Microsoft endpoint; extra scripts can reveal clients and IP addresses.

**Which EWS workloads are hardest to migrate to Microsoft Graph?**

Email is the easiest; calendaring, tasks, synchronization and streaming notifications are harder. Tasks moved to the To Do API, which cannot reach some old MAPI single-value properties, and custom Outlook forms cause trouble. Streaming notifications have no Graph equivalent, so apps must switch to webhooks with a publicly reachable endpoint, an architectural change.

**What throttling and batching limits should developers plan for in Microsoft Graph?**

Graph allows far fewer concurrent operations than EWS, so plan threads and queues carefully. Glen Scales notes Graph restricts you to four connections per mailbox and batches of 20 items for every workload, while around 50 items per batch worked best for EWS migrations. Queue operations and use the Graph SDKs, which handle retries and throttling.
