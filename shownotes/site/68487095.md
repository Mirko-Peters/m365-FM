## FAQ

**What is the source of authority in Active Directory and Entra ID?**

The source of authority is the system with final say over an object's identity attributes. While Active Directory holds it, Entra ID only receives synced data and rejects cloud edits as read only. Setting isCloudManaged to true moves ownership of the object's attributes, membership and lifecycle to Microsoft Entra ID.

**How do I switch a group or user to cloud management in Entra ID?**

Send a PATCH request through Graph Explorer or PowerShell that sets isCloudManaged to true on the object ID, using an account with the required permissions. Then run a GET to confirm the value flipped, check that the Entra admin center shows the source as Cloud, and test access with a real user.

**Will users lose access to on-premises resources after moving to Entra ID?**

Not if the environment is prepared. After the switch, run dsregcmd /status on the user's device and confirm both the on-premises and cloud TGT entries read yes; otherwise refresh the primary refresh token and sign in again. Mapped drives and file shares should keep working because Kerberos tickets stay tied to the user's SID.
