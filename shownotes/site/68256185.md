## FAQ

**Does stopping an Azure Database for PostgreSQL flexible server stop all charges?**

No. Stopping the server pauses compute billing, but storage keeps billing because the data disks stay allocated and backups keep accumulating. Each instance runs on its own virtual machine, so the episode recommends treating it like an on-premises host: measure CPU use, schedule stop periods and right-size compute.

**Why does high availability double the cost of PostgreSQL flexible server?**

High availability keeps a synchronous standby that duplicates compute and storage, and that standby cannot serve read queries. The episode recommends it only for mission-critical, customer-facing systems such as payments, and suggests asynchronous read replicas for analytics, staging and reporting, since they handle real queries while still offering failover options.

**Are the built-in backups of PostgreSQL flexible server enough?**

Not on their own. Built-in snapshots are tied to the server's lifecycle and are deleted with it after a short grace period, and corruption replicates into them. Add regular logical backups with pg_dump stored in a vault or cool storage, and test restores, because untested backups give no real assurance.
