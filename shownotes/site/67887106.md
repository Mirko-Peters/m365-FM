## Key takeaways

- SELECT is read-only in normal use, so writing your first query to answer a business question is a safe way to learn instead of waiting in a ticket queue.
- T-SQL is Microsoft's dialect of standard SQL: the basics like SELECT, FROM, WHERE and ORDER BY stay the same, while extras such as TOP, TRY/CATCH and GO matter once you automate.
- Choose inner or left joins deliberately and avoid SELECT *, missing WHERE clauses and sorting huge unindexed tables, because those habits are what overload production databases.

## FAQ

**Is running a SELECT query safe on a production database?**

In normal use, yes: SELECT is read-only, so it returns information without updating or deleting data. The episode still advises checking Microsoft's documentation for edge cases, and warns that SELECT *, a missing WHERE clause or sorting huge unindexed tables can overload a production server, so practice on a read-only data set or clone first.

**What is the difference between SQL and T-SQL?**

SQL is the international standard, while T-SQL is Microsoft's dialect used in SQL Server. Core clauses like SELECT, FROM, WHERE and ORDER BY work the same in both. T-SQL adds extras such as TOP instead of LIMIT, IF and WHILE logic, TRY/CATCH error handling and the GO batch separator, which matter mostly once you automate.

**When should I use a left join instead of an inner join?**

Use a left join when the right table may lack matches and you still want every row from the left table, with NULLs where data is missing. An inner join keeps only rows that match on both sides. The episode suggests counting orphaned rows first; for reporting, a left join is often the safer starting point.
