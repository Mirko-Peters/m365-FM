## FAQ

**Is Microsoft Fabric lineage a governance control?**

No, Fabric lineage is observability, not governance. It is telemetry built from events and metadata after an action has happened, so it can trace and explain data flows but never refuse them. Mirko calls it valuable for impact analysis, debugging and audits, but says governance has to deny actions before execution.

**Does connecting Microsoft Purview to Fabric add enforcement?**

No, Purview adds a second observer rather than an enforcer. It catalogs, classifies and maps lineage across systems, but its scans run after data exists. If someone can already run a notebook and write output, Purview improves the narrative afterwards without preventing the write. The real gate still sits in role assignment and egress controls.

**How can I test whether a Fabric control really governs data?**

Ask four questions: can the system say no, can it say no before execution, can it enforce centrally, and can it fail safely. Mirko applies this test to lineage, tags, endorsements and Purview scans, and none of them pass. Anything failing a question is useful observability or process, but not governance.
