## FAQ

**Why is the "Allow Azure services" checkbox in Azure SQL risky?**

It lets any service in the Azure cloud attempt a connection to your SQL gateway, not just your own app services. The episode calls it an illusion of security: you trade protection for convenience and effectively remove the perimeter you configured, which matters in a world of automated scanning and AI-driven brute force.

**Should I use managed identities instead of service principal secrets for Azure SQL?**

Yes, because a managed identity removes the secret entirely instead of relying on rotation. Azure handles the credential, keeps it short-lived and binds it to the resource, so an attacker cannot reuse it from a laptop. It also prevents outages caused by expired secrets and stops keys from ending up in config files or repositories.

**How does just-in-time access for Azure SQL work with Entra PIM?**

You map an empty Microsoft Entra security group to a database role, and engineers activate eligibility for that group only when needed. Activation requires justification, multifactor authentication and optionally a second approver. After a fixed window, such as two hours, Entra ID removes them and access disappears. Deployment pipelines can follow the same pattern.
