IT の仕事をしている方であれば、3つ目の意味でこの用語に出会ったことがあるかもしれません。クラウドアーキテクチャのフレームワークでは、「オペレーショナルエクセレンス」が設計の柱の1つの名称として使われています。AWS Well-Architected Framework では、これは4つのベストプラクティス領域、すなわち Organization、Prepare、Operate、Evolve を対象としています [43]。Azure Well-Architected Framework では、オペレーショナルエクセレンスは信頼性、セキュリティ、コスト最適化、パフォーマンス効率と並ぶ5つの柱の1つであり、「標準、包括的な監視、安全なデプロイ手法によって運用を効率化する」と要約されています [44]。これらの考え方は関連しています（標準、フィードバックループ、継続的改善）が、クラウドの柱はソフトウェアワークロードの運用を対象としています。本ガイドで扱うのは、工場や事業オペレーションのための管理システムです。製造業の IT における Azure 側の内容については、姉妹ガイド [Azure for manufacturing](https://www.m365.fm/en/learn/manufacturing-it-azure/) を参照してください。

### 通常の1日でオペレーショナルエクセレンスを見分ける方法

オペレーショナルエクセレンスは、損益計算書に表れるずっと前に、現場で見て取れます。典型的な兆候は次のとおりです。

- 全従業員が自分の部門の最も重要な2～3つの目標と、自分自身の貢献を理解している。
- 標準からの逸脱が可視化され、月次報告ではなく1シフト以内にエスカレーションされる。
- 管理職は決まった時間を現場の作業場所で過ごし、指示を出すのではなくそこで質問する。
- 問題は共通の手法（A3 や PDCA など）を用いて根本原因まで解決され、その結果が新たな標準になる。
- 指標は少なく、明確に定義され、最新の状態で表示されるため、全員が意味を理解している。
- 改善は、それを始めた人が会社を去った後も定着している。

## 起源と歴史

オペレーショナルエクセレンスは、ある特定の日に発明されたものではありません。この用語は、数十年にわたる複数の発展をまとめたものです。

| 期間 | 発展 | OpEx にとっての意義 |
|---|---|---|
| 1920年代～1950年代 | Walter A. Shewhart が反復的な改善サイクルを開発し、W. Edwards Deming が1950年代に日本の聴衆向けにこれを拡張。1951年には日本科学技術連盟（JUSE）が、おなじみの PDCA サイクルとして体系化 [11] | 科学的で反復的な問題解決を中核に置く |
| 1950年代～1970年代 | トヨタ生産方式（TPS）。大野耐一が7つのムダを分類 [16] | フロー、プル、ムダの排除、人の尊重 |
| 1950年～1971年 | 中嶋誠治郎（Seiichi Nakajima）が日本で全員参加の生産保全（TPM）を開発。1971年、日本電装が PM 賞を受賞した最初の企業となる [14] | 設備の安定化と、オペレーターの参画 |
| 1982年 | 中嶋の著書『TPM 展開』に総合設備効率（OEE）という用語が初めて登場 [13] | 設備効率を捉える最初のエンドツーエンドの指標 |
| 1986年 | Motorola が Six Sigma を導入（Bill Smith） [20] | データに基づくばらつきの削減 |
| 1988年 | John Krafcik が MIT Sloan Management Review で「リーン生産方式」という用語を造語 [19]。ユタ州立大学が新� 茂夫（Shigeo Shingo）を記念して Shingo Prize を創設 [5] | 日本の原則が欧米に伝わる。オペレーショナルエクセレンスの賞の誕生 |
| 1990年／1996年 | *The Machine That Changed the World* と *Lean Thinking* がリーンを広める [19] | リーンが経営理念として定着する |
| 1993年／1995年 | Treacy と Wiersema がオペレーショナルエクセレンスを価値の規律として説明 [2][3] | この用語が戦略の語彙に入る |
| 1995年 | Jack Welch が Six Sigma を GE の戦略の中心に据える [20] | Six Sigma が全社的なプログラムになる |
| 2004年 | Jeffrey Liker が14の経営原則をまとめた *The Toyota Way* を出版 [28] | 焦点が手法から原則へ移る |
| 2008年 | Shingo Model とその評価ガイドラインが初めて公表される [4] | 広く使われた最初の原則ベースの OpEx モデル |
| 2012年 | 生産システムの全体最適に関するドイツのガイドライン VDI 2870 Part 1 が発行される [21] | ドイツの生産システムに関する基準 |
| 2018年以降 | World Economic Forum の Global Lighthouse Network [25] | OpEx をデジタル技術や AI と結びつける |

Krafcik が1988年の論文で示した観察の1つは際立っています。彼が調査した自動車工場において、生産性の最良の予測因子は自動化の水準ではありませんでした。それは、チームワーク、目で見る管理、欠勤、修理エリアから構成される「マネジメント指数」でした [19]。管理手法が技術だけよりも重要であるという洞察は、OpEx の歴史全体を貫いており、後に米国の工場データで大規模に確認されています（「ビジネスケースと ROI」を参照）。
