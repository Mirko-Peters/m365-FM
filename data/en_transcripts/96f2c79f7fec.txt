The cleaning step is called generalizing. On Windows, the tool that does it is sysprep. What it does is remove the machine-specific user information so the image can be used to create many machines. On Linux, the equivalent step is deprovisioning, which the Azure Linux agent handles. This step is where most of the sharp edges live, so it's worth knowing the rules before you touch it. Encryption has to be turned off first because sysprep needs the drives fully decrypted. The DVD drive has to be enabled or the new machine gets stuck at the first run experience. Antivirus can interfere with sysprep, so it's usually disabled before you run it. And the unified write filter, a feature that can be handy elsewhere, isn't supported on these desktops and shouldn't be enabled in the image. The most important rule is that generalizing is a one-way door. Once a machine has been generalized, it can't be started again and the process can't be undone. That single fact explains the recommended workflow. You don't generalize your good machine. You clone it. generalize the clone, capture the image from the clone, and then throw the clone away. The first piece is the image source, which is whatever you build the image from, such as a virtual machine or a managed disk. The second is the gallery itself, which is the shelf where everything lives. The third is the image definition, which is the label on the box. It records what the image is for, such as whether it's Windows or Linux and whether it has been generalized. The fourth is the image version, and that's the actual box you deploy from. The gallery works like a library shelf, the image definition is the label that says what belongs in this spot, and the image version is the specific edition you pull down. You don't deploy from the definition you deploy from a version. Versions use a simple numbering scheme with three parts and you read them from left to right. A version like 2.1.0 and a version like 2.1.3 belong to the same image definition. The second one is newer because the last number is higher. When you ask for the latest version, Azure picks the highest first number, then the highest second number, then the highest third number. That numbering is more useful than it sounds. It means you can keep an older version around as a fallback and publish a new one. You can then switch between them on purpose, instead of hoping you remember which copy was the good one. The core operation is called re-imaging, and in simple terms it replaces the operating system disk of the desktops in the pool with the new image. Drain mode is worth explaining. because the name doesn't give it away. When a desktop is in drain mode, no new users are sent to it. Anyone already signed in keeps working, but the next person who connects goes somewhere else. In practice, that means people are only ever routed to a desktop that has already been updated, so the change happens quietly in the background. That design choice is the difference between an update your users never notice and an update they remember, for the wrong reasons. You can also warn people before it happens.
