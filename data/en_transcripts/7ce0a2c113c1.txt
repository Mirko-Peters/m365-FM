Seeing the list is the easy half and the other half is acting on it. The actions themselves are more familiar than they sound. An admin can install an agent for a group, so it's ready without anyone hunting for it, or uninstall it when it's no longer wanted. They can also delete an agent, though delete is gentler than it sounds. A deleted agent drops into a thirty day recovery window and can be restored before it's gone for good. Approval is where governance gets real when someone wants to roll an agent out more widely, the request lands in a queue. Common mistakes and honest limits. Nobody gets this right on the first try, and the mistakes tend to follow a pattern. The most common one is blocking agents before you have a registry, which is like firing people before you know who works for you. Admins block the loudest agent they've heard about and never find the quiet ones doing damage in the background. The fix is unglamorous and effective. Turn the registry on. Let it fill up and only then start making decisions. The next trap is ignoring ownerless agents until the number is frightening. Every departure adds to that count, and an agent left behind keeps its access to whatever data it was given. That is a risk that grows in the dark. Another common slip is assuming delete means gone. Delete actually opens a thirty day window where the agent stays recoverable and stays recorded in the audit log. There's also the duplicate row where an admin deletes one entry, thinking it's a glitch and is surprised the agent never left. One more is reading early usage numbers as the whole truth data for outside agents only starts counting the day the license switches on, so the first weeks always look thin. Then there are the limits Microsoft states plainly, and they're worth repeating. Without the polish, not every agent appears automatically. Anything built outside Microsoft's channels without a Microsoft agent identity needs extra steps or a registry sink to show up. Admin actions can quietly fail on agents behind a power platform firewall in active enforcement mode because the request arrives from the wrong address. An AI administrator can monitor plenty, but can't change every identity setting, since some of that needs a more privileged role. Draft agents from several platforms still aren't visible, and several of the best views, including the risk column and the map, need the higher tier license. None of that makes the tool weak, and it makes it honest. Honesty is what you want from something whose job is keeping an eye on software that can act without you. The point of listing the limits is so you don't expect a magic switch. What you get is a control room and not a babysitter, and a control room only helps if someone is actually in it.
