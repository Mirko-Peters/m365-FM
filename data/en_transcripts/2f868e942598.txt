Every host pool is one of two types and this is the choice I hinted at earlier because a pool is either personal or pooled. One gives each user their own machine and the other shares machines between users. A personal host pool is a one-to-one arrangement. Each user gets a machine that belongs to them, and the maximum session limit is one because one person uses it. Users either get assigned directly to a specific machine, or they're placed on the first available one and stay there. Every time they sign in, they land on the machine they were assigned to. A pooled host pool is a many-to-one arrangement. Several users share a single machine at the same time, each inside their own isolated session. Nobody is tied to a particular machine, so if a user signs out and signs back in later, They might land somewhere else entirely. That's by design, and it's what keeps costs down. The trade-off is easy to say. Personal costs more per user and gives that user a consistent, dedicated machine. It suits developers, power users, and anyone running something heavy like graphics work or a GPU workload. Pool costs less per user because the machines are shared, and it suits task workers, call centers, and people running standardized web applications. There's more to it than price, though. So the pool is built, and it's a pooled one. A user opens the Windows app client and clicks their desktop. The interesting part is what happens between that click and the desktop appearing. That routing piece is often called the broker and the user never sees it. From their side, they clicked an icon and a desktop opened. If the pool is personal, this part is simple because the user goes to their own machine every time. If the pool is pooled, the service has to choose between two methods. One is called breadth-first and it spreads sessions across the machines to keep things even. The other is called depth first and it fills one machine up to its limit before it moves to the next. The two methods point in different directions. Breadth first favors performance because the load is spread out, while depth first favors cost because it packs people onto fewer machines and lets the rest stay switched off. Breadth first isn't perfectly even and that surprises people. It picks at random from roughly the half of machines with the fewest sessions So the spread ends up close but not exact. Image management has three layers, and it helps to keep them straight. At the top is the golden image, the master copy that holds the operating system, the company-wide applications, and the security settings. Below that is a template machine for one specific pool, which starts from the golden image and adds that pool's size, its department applications, and its policies. At the bottom are the session hosts themselves, the machine's users connect to, all cloned from that pool's template.
